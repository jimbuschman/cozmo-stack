## 3. Existing records contradicted or too weak

1. **M11-024 (RECOVERABLE_GAP) is now answered and should be settled: the selector byte is 1, so
   the non-binomial extractor is live.** Citation `0x008752FC/0x00875304` (`movw r2,#0x101; strh r2,[r0]`)
   and `0x00898B4C/0x00898B50/0x00898BE0`.
2. **M11-025 ("The characteristic-scale select") and the evidence rows A2/A3/A4 are about the
   non-live binomial function.** `BinomialFilter` has exactly one caller, `0x00890736`, inside
   `ExtractComponentsViaCharacteristicScale_binomial` (`0x00890448..0x00890DF4`); the cited
   select loop `0x00890B14` lies in that same range. Since byte 0 = 1 selects the other function,
   M11-025 cannot be EXACT_SOURCE/live_path=true as written. This is the largest correction.
3. **M11-018** claims (per the previous report) the dark-mask uses `BinomialFilter` + `(scale*0xCCCC)>>16`
   and cites `0x00898C18` as "the dark-mask call". `0x00898C18` is the `beq` target for the
   binomial branch that is not taken at the shipped setting; the binomial variant is not live.
   Its other claims (`IsQuadrilateralReasonable`, the `0xCCCC` multiplier value) are separate
   and were not re-checked here.
4. **M11-026's previous-pass values are wrong.** The evidence file row B1 said the solid/sparse
   operands are `+0x74`/`+0x70` (0.03/0.8) and B2 said the hollow fraction is `+0x78` (0.97).
   The call sites read `params+0x1c`/`+0x20` (32000/64) and `params+0x24` (1.0). `+0x74/+0x70/+0x78`
   are the size-filter formula constants used inline in `Detect`; `+0x14/+0x18` are computed, not
   fixed 100/39000.
5. **`MinComponentPixels=100` / `MaxComponentPixels=39000` in `QuadDetector.cs` are not
   source-backed.** 39000 is `params+0x40` (the `ConnectedComponents(int,short,bool,stack)`
   component-count capacity, `0x00898866: ldr r1,[r6,#0x40]`); 100 is `params+0x6c`; the real
   filter uses `+0x14/+0x18`.
6. **M11-031's direction is now settled**: the interior/Bright out-param is the one compared on
   the left of the ratio multiply and the result is `Bright > 1.01*Dark`; the C# "dark >= bright"
   (ratio 1.0) is not the engine's gate (already noted in the evidence file).
