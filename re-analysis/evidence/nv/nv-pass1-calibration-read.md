# NV CameraCalib read path: extraction report (read-only; scratch in `...\scratchpad\extract\NV\`: `nvsc.txt` is the full NVStorageComponent disassembly 0x642848..0x646A94, `cb.txt` is the VisionComponent callback)

**Summary.** The original engine does not send Length 1024 for tag 0x80000001. It sends **Length = 1**. M11-011 misread which table InitSizeTable fills, and so it claimed 0x80000001 is not a factory tag. It is one. The engine also does not concatenate replies. It places each blob at **offset = index × 1024**. If the engine had been given this bundle's replies, it would have delivered 15452 bytes, logged SizeMismatch, and installed no calibration.

### Wire decode of the bundle (frames.jsonl lines 9, 10, 12)
- Out, line 9: `81 01000080 00040000 00 00 0000`. That is tag 0x80000001, word@4 1024, op 0, byte9 0, count 0.
- In: nine NVOpResult with result 3 (NV_MORE), then one with result 0. Each is (index = word@4, n): (5,4) (6,4) (7,4) (0,56) (3,4) (2,24) (1,36) (4,24) (15,92), then (0,0) with result OKAY. All carry tag 0x80000001 and op 0.
- The index-0 blob, read with CameraCalibration's own layout (Unpack at 0x7C64A2), gives:
  - f32 294.716, 294.899, 143.163, 117.454, 0.0;
  - u16@0x14 = 240, u16@0x16 = 320;
  - distCoeffs 0.01389, 0.16597, 0.000778, −0.002705, −0.51256, 3.1e-33, **+inf**, 0.

### What the original would have delivered for THIS bundle's replies
It would not have sent Length 1024 (step 5). Given these replies anyway, every blob would have been accepted (base 0x80000001, factory tag, no header). The data would sit at offsets 5120, 6144, 7168, 0, 3072, 2048, 1024, 4096 and 15360, with zero fill between. The final OKAY carries n = 0, so nothing is copied, and the engine calls cb(ptr, **15452**, NV_OKAY). The callback compares 15452 against 56, logs SizeMismatch, installs **no calibration**, and sets vision enabled (+0x48 = 1). Bytes 0..55 would hold the valid-looking calibration shown above. The stack's result (248 bytes concatenated in arrival order, SizeMismatch) matches the engine's outcome but not its buffer.

### Existing records contradicted by the source
- **M11-011** (EXACT_SOURCE). "0x80000001 falls off the end and IsFactoryEntryTag returns false; the camera calibration asks for 0x400" is wrong. 0x80000001 is a key of `_maxFactoryEntrySizeTable` (0xC8106C, inserted by 0x4D7F9E..0x4D7FAE), and IsFactoryEntryTag's lower_bound (0x6440E6..0x64412A) finds it. Length = 1 (steps 5 and 6). The 0xDE000/0xDE030 emplaces the record cites go into `_maxSizeTable`.
- M11-011: "MORE and the base-tag reassembly are for multi-blob entries" is also wrong. The MORE/index path (0x643538..0x643604) runs for every read, single-blob factory tags included.
- The field name "length" for NVOpResult word@4 (protocol json 0xCD, pycozmo name) is wrong. The engine treats it as a blob index ("offset", ×1024).

### Evidence too weak for the status claimed
- M3-022's provenance says the stack's reader has "no timeout". The engine has a 5 s robot-clock timeout that delivers NV_TIMEOUT to the callback (step 15). No NV-subsystem record covers the timeout, the retry, the acceptance check or the reassembly (steps 2, 8, 10–15). M3-022 hands all of this to "the NV subsystem's" records, and none exist.
- The M2 NVCommand row (layout) stands. Its json name `length` is supported by the engine's log "Length". Its value for factory reads is not settled by M2; M11-011 settled it wrongly.

### Open questions for the manager
1. Steps 5–15 need a home: new NV-subsystem records. They are not M11 or M3.
2. Step 17 is HARDWARE_ONLY. Confirming it means a hardware run that sends Length = 1 and records the reply.
3. Step 4: the gating in Robot::Update before 0x514166 is not yet read (RECOVERABLE_GAP).
4. Index 0's distCoeffs[6] = +inf is installed as-is when robot+0x24 > 6. What robot+0x24 holds is still M3 open question 4.
5. InitSizeTable runs only with a non-null context (0x6428EC). The Robot ctor passes Robot+0 (0x50FD86). That this is non-null in production is inferred, not proven: with a null context, 0xCD would never be subscribed either.
