# REACTIONS-NO-CLIP-E2E-1

The recording's raw wire contradicts the premise that no animation was sent. The actual build gap was the configured/native action lifecycle: cliff, impact and slope used legacy host action handles instead of the robot's ActionList. They now use real native runners, and all five reaction-map entries reuse their configured constructor instances. Unexpected movement also receives the native factory/base inputs and scoped lifecycle. ReturnedToTreads retains its already-built, intentionally quiet implementation.

## Offline input and model boundaries

`replay-physical-reactions.ps1 -Bundle <private-bundle>` uses an in-memory transport; it never connects to a robot. The replay uses recorded inbound F0/F1/F4/D1/C0/C1/D4/DD/DE within each window, 60ms engine ticks, the recorded body hardware revision4, and rebinds only F0 pose origin/frame IDs. Startup is a fresh calibrated fixture with KeepNeedsFull and no Freeplay activity, not a claim to restore the original whole world, needs, RNG or normal-action graph.

The recording's aggregate motion-lock state is folded from original outbound9D/9E before and within each window (MovementComponent::LockTracks0x00640098, UnlockTracks0x0063FE5C). A named context owner supplies those bits alongside the new reaction's real locks. Original owner identities and normal actions are not reconstructed. This context matters: unexpected detector B3 at0x0063E398 rejects nonzero AnimationStateTag unless BODY is locked. Captured F1 tag/tracks/timestamp/drop fields are retained. Its old cumulative byte/frame counts are replaced by an explicit ideal firmware-consumption model of the replay's actual sent bytes/frames (C11/C12 at0x0057BFAE/0x0057C464): one744-sample frame per22320Hz interval, reported at captured F1 arrival boundaries; native0x0057C6F6 still computes finite send budgets. New9B/9A streams receive modeled CA/CB at their modeled playback positions for their actual new tags, not stale captured tags. PCM completion independently consumes real48kHz stereo16 bytes at192000bytes/sec. No native detector threshold, action timeout, trigger-selection draw or audio result is substituted. An initial counter model consumed the whole ahead buffer immediately and was rejected because it shortened authored clips; acknowledgements at host-send time were also replaced with playback-time acknowledgements.

These models exercise the sensor-to-native-reaction-to-authored-stream path and action completion; they are not a hardware pass or a bit-identical rerun of the original scheduler/world.

In particular, the short late-cliff model sends the stop-reaction clip and is then interrupted by captured OnBack input before the main clip; the longer cliff windows reach both clips. The original legacy capture sent both tags earlier. This replay checks the new native compound/action lifecycle, not the old host handle timing. The short early-cliff model also takes the native suspicious-threshold quiet branch before falling/calibration; it does not reproduce the original115ms switch timing. These fresh-prefix/normal-action/firmware context limits remain explicit rather than forcing an interruption or delaying recorded inputs to match the old trace.
