# DESPERATION-SEARCH-1

The random-drive callback ignores its action result and enters SearchForCube only when `useCubes` is true (0x005DA2DE–0x005DA2EC). Search writes state 2, then constructs a helper with ID −1, minimum seen 1 and maximum stage 1 (0x005D96DC–0x005D9720). The factory constructs and registers the helper (0x005B5668–0x005B5698). The helper ctor stores the three parameters at +0xF4/+0xF8/+0xFC and subscribes to RobotObservedObject 0x44 (0x005BACF2–0x005BAD98). At 0x005D9734–0x005D9744 and 0x005D97C8–0x005D97EE, the caller delegates with DriveToCube on success and an empty failure callback.

Init clears the distinct-observation set and starts stage 0 (0x005BAE9E–0x005BAF20). With ID −1 stage 0 skips the specific-target turn and runs one nearby search (0x005BAF9A–0x005BB056; −20 mm, 100 mm/s, head bits 0xBDB2B8C2). Stage 1 omits both target-specific nearby actions and runs two back-up and turn groups (0x005BB1AA–0x005BB3C6). Each back-up is −20 mm at 20 mm/s, animation false. The four relative turns use angle bits 0x3F490FDB, 0x3F490FDB, 0xC016CBE4 and 0xBF490FDB. Completion advances the stage regardless of action result. At stage exhaustion the untargeted path compares the stored count to the minimum (0x005BB5BE–0x005BB5D0).

The expected success from seeing one cube differs from the binary. The 0x44 callback's ID −1 branch compares the count without inserting the received ID (0x005BB7DA–0x005BB7E0, 0x005BB81C–0x005BB82C). The insert at 0x005BB816 is specific-target only. The checked ID −1 path clears its set on Init, leaves the count at zero and returns failure when the two stages end. The code preserves that result.

If the helper reports success, DriveToCube looks up the most recently observed active cube and stores its ID (0x005D98BE–0x005D98DA), or logs and enters Idle when no cube qualifies (0x005D9A66–0x005D9A86 and 0x005D9A46). The world query starts with timestamp zero and keeps the first object at a tied maximum (0x006263A4–0x00626404, predicate 0x0062C14A–0x0062C15C). Existing pre-action pose and drive owners continue the action. Tests verify the normal two-stage failure after a cube observation and exercise the actual success callback with a supplied terminal helper status.

Both behavior-level MISSING markers are removed. The specific-target camera snapshot/occlusion gap (M11-042) remains visible on its own path. Manifest classifications are unchanged. Operator hardware acceptance is pending.
