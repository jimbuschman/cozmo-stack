# DRIVE-TO-FACE-BUILD-1

- Configured factory case 0x0059CB00 allocates 0x128 and calls 0x005DA550. That constructor calls IBehavior(robot,config), zeros state/deadline, constructs SmartFaceID, and installs the derived vtable. There are no derived configuration fields; shipped `voiceCommands/VC_ComeHere.json` supplies only behaviorClass/behaviorID. The binding applies to configured DriveToFace instances, including VC_ComeHere.
- Readiness 0x005DA588..0x005DA626 calls GetLastObservedFace(pose,true), checks the pose's current origin, obtains GetFaceIDsObservedSince(stamp,false), and caches the first ascending ID or resets on an empty result. A foreign cached pose leaves the previous smart reference unchanged. Smart reference remapping/deletion uses the existing native subscriptions. Init 0x005DA668..0x005DA6C0 fails on an invalid smart reference and logs the native warning. Runnable vtable gates (0x01028AD8) are false at 0x005BF04C, 0x0059EC12, 0x005DAD54. Resume is inherited.
- Turn state 0, `TurnTowardsFace`, comes from 0x005DA758..0x005DA89A. Important binary detail: it constructs an unused CompoundActionSequential, TurnTowardsFaceAction(robot,smartID,Pi,false), and VisuallyVerifyFaceAction(robot,rawID), then starts a **separate** TurnTowardsFaceAction with the same arguments at 0x005DA82C..0x005DA86E. The unused group is never queued. The implementation preserves those three constructors' global action-tag reservations (IActionRunner 0x0053FE54..0x0053FEC8); their constructors 0x0054F4C8, 0x0054B754 and 0x00568EB8 otherwise initialize private state. It does not execute an invented sequence. The active NativeLastFaceRunner owns its normal verification/image wait and fine turn. Its completion lambda 0x005DADA8..0x005DADE6 advances only on SUCCESS.
- Distance 0x005DAA20..0x005DAA96 copies the native face pose at entry+0xF4, replaces its local Z with the robot main pose Z, then uses ComputeDistanceBetween 0x00847780 (same-parent shortcut or ComputeVectorBetween 0x008476A8). The existing f32 geometry helper supplies the squared distance. At <=200 mm (0x005DACDC), state 2 `AlreadyCloseEnough` queues TriggerAnimationAction(robot,ComeHere_AlreadyHere=0x64,1,true,tracks0,60f,false), 0x005DAC34..0x005DACA4.
- Otherwise state 1 `DriveToFace`, 0x005DA950..0x005DA9EC, queues DriveStraightAction(robot,distance-200f,220f,true), then SetDecel(bits 0x4326AAAB). SetDecel 0x00547592 sets the explicit-values flag and decel; Init 0x005476AA passes it into the line path. Added a decel field/setter to the existing runner, retaining its prior 500 default for all existing callers. The path starts at the native drive-center/forward pose (0x0054762A..0x005476AA), so the replay accounts for its offset from the main pose when checking the 200 mm standoff. Both drive and already-close animation use the resultless member callback, so either completion result advances to tracking.
- State 3 `TrackFace`, 0x005DAB34..0x005DABE2, sets an f32 now+5 deadline and queues TrackFaceAction(robot,rawID) with an empty callback. Update 0x005DA8FC..0x005DA93C stops the action with (false,false) when now is strictly later than the deadline and returns DONE. Otherwise inherited UpdateInternal ends when the action ends, including early tracking termination. StopInternal 0x005DA93E resets SmartFaceID; shared Stop cancels the action. Owner/generation guards prevent an interrupted or retired instance from issuing follow-up work.
- The personality round waits for native readiness, requests VC_ComeHere through existing Selection/G2E 0x94, records behavior-start/stop, and restores Freeplay afterward. Offline replay supplies face observations and actual motor/path/animation acknowledgments; it checks the emitted path ends 200 mm from the face. Additional cases cover the inclusive close boundary, native geometry, sorted anonymous ID, promotion/deletion, invalid Init, interruption and restart.
- Validation: all 109 affected tests, fidelity.py --check (763 records), and the no-robot `--personality --steps drive-to-face --validate --yes` dry-run pass; all 8,614 full-suite tests passed (24.12 minutes). No fidelity status changed. Robot verification and the manager's binary spot-check remain pending. The existing state-name diagnostic still names the shared VizManager/SDK debug-string gap at 0x00513F6A..0x00513F9C.
