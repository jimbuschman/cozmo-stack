# CHARGER-SET-POSE-ON-CHARGER-1

On contacts (Robot+0x338), BackupOntoChargerAction calls SetPoseOnCharger at 0x0054E7B8 and returns success at 0x0054E7BC regardless of that call's result. The pose function uses the ObjectID at Robot+0x330 (value +0x334, written by Mount Init at 0x0054E120). It looks up that exact ID in the current origin with family −1 (0x0051687C–0x00516886; helper 0x0061F3E0), then casts to Charger at 0x0051689C. A missing or wrong-type object warns and returns 1 (0x0051690A–0x00516948).

GetRobotDockedPose (0x004EA1A0–0x004EA264) constructs a pose parented to the charger's owned pose with rotation pi (0x40490FDB) around Z and translation (30, 0, 0). SetPoseOnCharger flattens it (0x005168B2, body 0x004DF628), then calls SetNewPose at 0x005168BA. SetNewPose flattens again, invokes SetPose (0x005126F6–0x005126FE), then adds a vision-only history sample with the stored timestamp, accepted head angle and lift angle (0x00512708–0x0051271C). SetPose checks the origin, preserves the robot pose name and refreshes the drive-center pose (0x00515034–0x005150AC and 0x00517EC0). The history helper sets the vision-updated byte and increments the pose frame before insertion (0x0051513C–0x0051517A). SetPoseOnCharger propagates the history result and logs success or failure (0x005168CC–0x005168E2 and 0x00516956–0x00516A02).

The existing tick sends the pending vision update and clears the flag at 0x00513CBE–0x00513CCC. SendAbsLocalizationUpdate reads the latest vision-only timestamp, frame and pose (0x00514710–0x0051477C), then sends the absolute update (0x00512734). The path preserves the charger pose, current origin and localized-object ID. Contact-created charger observations are a separate path.

The action now calls the existing robot/world owners from both mount entry paths. Regressions pin the robot pose against a rotated charger, the pose frame and the actual update sent on the next tick. Missing and wrong-type saved IDs preserve the pose and still return backup success. The scoped M13-008 gap is built. Manifest classifications are unchanged and operator hardware acceptance is pending.
