# AI-BODY-PLACEMENT-1

## Native factory and placement path

- The AI lift request uses its original owner's external AtEnd queue, zero retries, external tag and readiness/reaction gates. The SetLiftHeight factory selects PlaceObjectOnGround only when the original f32 request equals 32 mm and Carrying+8 differs from 0xFFFFFFFF (0x0052AC40–0x0052AC76). The external RobotActionUnion entry is 0x1D (0x0052796C–0x005279A8, 0x00526080–0x00526092). Nearby and negative requests still take ordinary lift construction (0x0052AC78–0x0052AC9E). The placement branch does not consume lift speed, acceleration or duration. The original owner's carrying, docking, manipulation/vision and behavior owners are required for this entry.
- The action uses type 0x18, head/lift/body mask 7, no interrupt and 30 s timeout (0x00554638–0x0055469C, vtable 0x010222B8, 0x0052B0B3 and 0x0052B0C3). Init rechecks carry on promotion. It returns 0x03000011 if carry has been lost. Otherwise it saves the carried ID, clears Docking+5 and sends 0x44 with three zero pose fields, 100/200/500 speed/acceleration/deceleration and flag false. The send uses the existing reliable robot owner and its actual return value (0x00632A88–0x00632AC4, 0x00632B88–0x00632BFA).
- A nonzero send result becomes 0x03000016. Both valid-carry send branches construct the verify child with the saved ID, the current carried marker, max turn zero, verify true, track false and suppressed track locking. Init calls the existing StopAllMotors tail even for no carry or failed send. Successful Init disables ObjectPositionUpdated (trigger 8) under the original manager's placeOnGroundAction lock and stops an active reaction of that type (0x00554794–0x005548D4, table 0x00C55A21).
- The action reads the original Docking+4 active mirror, written from robot status bit 2 (0x00512A96–0x00512AA0). It requires an observed busy tick, then busy clear and body stopped before ticking the retained turn/vision child. Docking+5 and PickAndPlaceResult do not substitute for this busy gate. A non-success, non-running child result clears the saved object in the current origin and returns the child result (0x005549B0–0x00554A3A).
- Exact-runner cancellation keeps the original owner and queue identity. A pending deletion can complete NOT_STARTED without a placement send, while an active action completes CANCELLED through normal teardown (0x0053E83C–0x0053E96E). Teardown removes the original manager's name lock for a started action, retires the retained child, then runs generic stop/unlock/watcher cleanup (0x005546D0–0x00554742). It has no placement-specific AbortDocking call.
- Native completion variant 0 writes the saved ID, count 1 and false flag at 0x00554AE0–0x00554AFA. Four other ID words are uninitialized. M12-052/M1-034 continue to withhold that full raw/app payload while retaining the defined local data and scalar result. The AI task observes its scalar result only after the original action has unlinked.

## Files and verification

- Motion.cs shares the existing AI admission and completion wait across lift and placement. NativePlaceGroundRunner.cs binds the original carrying, docking, manager and verification owners. Docking.cs and CozmoEngine.cs route the checked 0x44 send and its real result. NativeObjectRunners.cs, NativeVisionRunners.cs, ChargerActions.cs, VisionSystem.cs and CompoundActions.cs guard the nested verification and teardown after a callback retires the original owner.
- AiLiftControlTests.cs reaches the real AtEnd queue and fake transport. The rendered Ground scene drives actual turn and vision verification, checks the 0x44 fields and StopAll order, verifies trigger-8 lock acquisition/release, and receives the defined scalar and local completion without an undefined public payload. Other cases cover pending and active token cancellation, carry loss between admission and Init, failed native send, ordinary nearby and negative lift paths, and replacing the robot at a verification motor send. The replacement case verifies the old reaction lock is released and no old verification motor command goes to the successor. StackFirmwareScene.cs stops test input at the known old-owner boundary.
