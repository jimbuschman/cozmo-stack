# FACE-ALBUM-FILE-BOUNDARY-1

## Claims and evidence

- VisionComponent startup reads the optional FaceAlbum string and takes the existing NV path for empty or exact lowercase robot at 0x00650FD6–0x00651010. The separate file tail forwards the configured directory at 0x00651022–0x00651028. The original recognizer appends /data.bin and /enrollData.json at 0x00869432 and 0x00869692. The host uses a valid explicit directory from that same setting. No resource rebasing or new selector is introduced.
- Startup calls EraseAllFaces at 0x00651014. The recognizer erases enrolled users, resets the maps and clears the album at 0x008678D8–0x00867974. The component invokes ordinary save at 0x00651524 before the first empty 0x58 at 0x00651538. The empty save queues 0x184000 then 0x183000 erases at 0x00657474 and 0x00657600. Its result reporting follows the existing NV failure owner. FaceWorld observations are separate.
- FaceTracker gates file load on its initialized byte and common handle at 0x0086E218–0x0086E2EE. The file loader at 0x008693FC restores raw album bytes through 0x00867384 and reads JSON separately. It still tries to install an empty candidate when the JSON cannot be read. Its consistency check at 0x00863064–0x00863120 precedes the capacity check at 0x00868942–0x0086899C. Equal capacities exchange ownership at 0x00868A3E–0x00868A44. A smaller candidate clears and copies through 0x00868B2A and 0x00868BC0–0x00868BE4, retaining the destination handle. Startup does not save imported contents back to NV.
- The legacy entry constructor at 0x0085FEE4–0x008602E4 reads time, name and album entries. Its first element sets the current slot even when the slot is -1. Duplicate guest keys take the last timestamp, and a missing required element field clears the entry map while retaining its current slot. Leading future times clamp before the guest map is filled. FindLastSeenTime at 0x0086165C returns the maximum map timestamp with a zero floor. The file constructor leaves +0x04 zero.
- The loader enumerates lexical JSON keys, accepts the signed decimal prefix at 0x0086980A and stages each full report before unique signed-ID insertion at 0x00869920–0x008699E4. One captured report clock supplies the three signed age divisions at 0x00869860, 0x00869882 and 0x00869898. At 0x00651032 startup calls replay before testing the load result. Replay sends another 0x58 at 0x0065159C then the staged 0x1C entries at 0x00651612, including an empty name or a parsed entry whose candidate was rejected. The source Pack at 0x0079B7CC writes the ages and signed ID, then String8 uses a modulo-256 count at 0x006C22F8–0x006C2316.
- A defined unready face guest yields a defined album clear failure at 0x00867924–0x0086793C. GetSerializedData at 0x00867D10 returns one and the save exits at 0x00657198 before NV. The first erase report still follows, then file load fails at 0x0086E244, replay sends the second erase report, and the component continues through its warning to +0x10 at 0x006510E2. Both this case and other defined file failures reach constructor backup reads at 0x005103CE–0x005103D4.
- The implementation binds enqueue, reports and readiness to the original startup owner and epoch. Guest candidate ownership follows the installed handle, while the asynchronous NV result stays pinned to the original robot and storage owner. Malformed JSON or stoi exceptions in the terminating original path use M1-034 at 0x0085FEE4 or 0x0086980A and skip the affected candidate.

## Files and tests

- CozmoEngine.cs and CozmoRobot.cs dispatch the optional constructor tail. Vision/FaceAlbumFile.cs and FaceRecognizer.cs own file ingestion, guest candidate and startup replay. AppDelivery.cs and UiSubscriptionHub.cs carry captured app and local subscribers.
- FaceAlbumFileStartupTests exercises the configured fake-robot startup and checks the NV prefix, two erases, raw and typed lexical reports, component/backup completion and absence of an imported save. It covers missing binary, staged results on rejected consistency, a real smaller guest album, the unready case and a failed NV response.
- The manager ran the original ARM JsonCpp and enrollment constructor with a controlled realtime clock, verifying BOM/truncation rejection, comments and trailing bytes, sentinel first slot, duplicate timestamp replacement, missing-key map clear and leading future clamp. Original ARM file load verified exact paths, missing binary, empty album with missing metadata, successful lexical ages, and staged report survival on failed install. A real small 3 by 2 album with one image-extracted guest sample copied into the existing destination. Original ARM Pack verified lengths 255, 256, 257 and 514. Stdio and realtime were fixture inputs. No original assets or binaries were added.

- EngineAppLayerTests keeps the separate host face-session generation across removal and checks its positive, unchanged value. Actual face state remains in the fresh-instance comparison. The first broader pass was 254/255 because the fixture expected that generation to reset. The builder passed 255/255 affected after correction, then 13/13 after the final all-negative timestamp regression. The manager independently passed 81/81, then 14/14 after the timestamp correction.
