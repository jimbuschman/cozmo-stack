# LLM-BRIDGE-MCP-1

- Built `cozmo-mcp`, a stdio JSON-RPC console around `Cozmo.Bridge`. It lists the bridge's 21 unchanged schemas plus `get_state`, `read_events(since)` and `list_animations`; tools return the existing bridge's native code/name and admission/retirement details. No robot behavior or fidelity status changed. `ListAnimations` reads the existing library's trigger map and clip-name snapshot without choosing an animation.
- The row-authorized SDK probe against the offline NuGet cache failed with NU1101 (`ModelContextProtocol` absent), so the direct protocol fallback implements initialize/initialized, supported-version negotiation, ping, tools/list, tools/call, cancellation and EOF shutdown. Requests dispatch concurrently so a pending native action does not block polling/cancellation; stdout contains only newline JSON-RPC and all engine diagnostics are redirected to stderr. Primary protocol evidence: [stdio transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), [tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools). No new engine reconstruction was required.
- Startup reuses `HardwareEngineOptions.Create`, `CozmoRobot.Create`, `HarnessStartup.ConnectAfterReadiness` and `HighResolutionTimer`, as `M15CubeHw` does. Resource loading runs alongside MCP initialization; state and action admission retain real native readiness. No setup input competes with stdin. Engine logs are attached in BeforeStart, frame capture precedes ConnectToRobot, and shutdown disposes the bridge/engine/transport. The existing startup gate retains M2-021's Unity StartupManager.cs:322–341 / ConnectionFlowController.cs:670–673 ordering; no replacement connection flow was added.
- Session evidence streams engine/app/MCP events, raw frames and stack logs under `<stamp>-LLM-SESSION`. On close, the same `M5HwAnalysis.ReadWire` exporter decodes messages with retransmission/connection epochs. `result.json` identifies the compiled assembly's commit/hash, arguments, timestamps, host status and final bridge state. A closed process is not a hardware pass; incomplete startup is marked incomplete. Hard kills can leave raw streams without the final export.
- `cozmo-stack/src/Cozmo.Mcp/README.md` has the Windows build/validate commands and exact Desktop/Code config JSON with `--resources`, optional speech banks, tool/result semantics and evidence locations. The client launches the built `.exe` so its CETCompat=false setting satisfies the existing UnicornLongjmp host requirement. It cites the official client configuration documentation. Machine-local configuration and all session bundles remain uncommitted.
