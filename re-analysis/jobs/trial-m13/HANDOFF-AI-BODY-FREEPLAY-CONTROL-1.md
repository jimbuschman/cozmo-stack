# AI-BODY-FREEPLAY-CONTROL-1

Unity `Robot.cs:1767–1784` sends `ActivateHighLevelActivity(Freeplay)` on enable. On disable it sends `ActivateHighLevelActivity(Selection)` and then `ExecuteBehaviorByExecutableType(Wait, -1)`. The native 0x92 subscription is at 0x005A147E–0x005A149C. Its callback at 0x005A4FA2 calls `SetCurrentActivity(activity, false)` at 0x005A4FB6, stamps the first Freeplay start at 0x005A4FD6, and clears the spark fields on other inputs at 0x005A4FDC–0x005A4FDE. `SetCurrentActivity` at 0x005A106C keeps an active reaction and clears the parked resume state at 0x005A119E–0x005A122A. Selection's executable-type subscription is 0x0060A91C–0x0060A938, with callback 0x0060AAAE–0x0060AAC8. Wait is executable type 0x0B. The public toggle uses the existing activity and executable dispatch on the same engine owner.

`RobotResumeFromIdle` delegates to the activity toggle. The 0x96 `BehaviorManagerMessageUnion` subscription at 0x005A15B0–0x005A15CE and switch at 0x005A3C6C–0x005A3DDA handle ActivateSpark, SparkUnlocked, DoATrickRequest and PlayAGameRequest. The generated 0xEF `ContinueFreeplayFromIdle` has a native getter at 0x00751476. No Unity sender or direct native branch to that getter was found. A runtime recipient for 0xEF remains unestablished. The shipped app's toggle path uses 0x92 and 0x93.

`QueueSingleAction` at 0x00527950 constructs the requested action, sets its tag at 0x00527A78 and queues it using the message's position at 0x00527A8C. `ActionList::QueueAction` reads the external-action block at Robot+0x2C7 and rejects blocked external tags (0x0053D94C–0x0053D982). `BehaviorManager::UpdateRobotPropertiesForReaction` sets that field at 0x005A2F60. The outside AI's existing authored-animation API uses AtEnd, whose native path checks duplicates/clearing and enqueues to the main queue at 0x0053DEA4–0x0053DEE2. The manager updates the activity at 0x005A2F84, checks reactions at 0x005A3062 and updates the running behavior at 0x005A30BC. This flow keeps the selected Freeplay activity through queue admission and completion. Existing action order, track contention and reaction restrictions still apply.

Behavior-owned work can go ahead of the pending request or replace a running request through the native StartActing queue call (Now, 0x005BDB60–0x005BDB6C) and QueueNow (0x0053E24C–0x0053E36E).

The regression tests exercise the real Selection Wait, animation queue order and delivery of a supplied terminal result while the real Freeplay activity stays selected. `AiAuthoredAnimationTests` independently exercises firmware playback callbacks. The offline `m15-cube-hw --freeplay-control --validate` validated six record references and showed the two 60-second observation windows. The live round records the terminal action result and the engine reports in the bundle for operator review. Manifest classifications remain unchanged. Operator hardware acceptance is pending.
