# FACE-NV-ALBUM-RESTORE-1

## Claims and evidence

- The shipped NV path still queues 0x184000 then 0x183000. The enrollment completion at 0x0065A860 only installs on result zero, uses both byte vectors at 0x0065A876–0x0065A896, and clears the source buffers at 0x0065A9DE. The managed stock callback carries the original owner and startup epoch into the restore. Component readiness and the backup order remain in the constructor. The file selector and compatibility read-result event retain their separate paths.
- FaceRecognizer::SetSerializedData at 0x00867F54 first restores the raw candidate via 0x00867384. The native handle is the success gate, with guest registered-user and total-data reads at 0x008673AA and 0x00867450. The temporary handle remains owned until transfer or cleanup. Consistency at 0x00863064 checks registered count and reverse-map correspondence. Capacity at 0x00868948–0x0086899C rejects any larger dimension. Equal capacities exchange the handle at 0x00868A40–0x00868A44. Smaller candidates clear the existing recipient and copy registered slots through 0x00868B2A and 0x00868BC0–0x00868BE4, keeping the destination handle. Successful installation commits the maps and clears transient tracking. Only then does 0x008680FC set the next face ID.
- The native enrollment parser at 0x008684D4 accepts the eight-byte header with prefix 0x0002FACE and signed next ID. Parsing at 0x00868566–0x00868618 starts while offset is less than size minus three, so one to three trailing bytes after a complete record are tolerated. Duplicate signed IDs use the last decoded record at 0x008685BA–0x00868608. The storage constructor at 0x00860728 uses the first slot even when it is -1 and replaces duplicate slot timestamps. With matching array lengths, the constructor clamps future leading timestamps at 0x00860852 and 0x00860420–0x00860630. It preserves slot timestamps. FindLastSeenTime at 0x0086165C takes a signed maximum with zero floor.
- A successful restore builds one installed report snapshot in signed face-ID order, including unnamed entries. The report clock is captured at 0x00868100 and the three signed age divisions are at 0x008681DE, 0x008681F4 and 0x0086822E. After unlocking vision, successful NV completion calls replay at 0x0065A9D4. Replay sends one empty 0x58 then one 0x1C per installed entry at 0x0065159C and 0x00651612. Native Pack 0x0079B7CC provides the three ages, signed ID and raw String8 bytes. App enqueue precedes the local signal at 0x00511DE8. The original owner and attempt fence each report. Managed compatibility name/ID notifications follow their existing public API shapes. A nonzero NV or restore result produces neither replay nor a save.

## Files and tests

- CozmoEngine.cs, CozmoRobot.cs and VisionSystem.cs connect original-owner NV completion to stock vision. FaceAlbumFile.cs shares the guest candidate install and native report publisher between file and NV with separate replay rules. FaceRecognizer.cs decodes the NV enrollment container. NativeOkaoFaceRecognizer.cs reads the guest registered-data count.
- The manager executed original ARM SetSerializedData at 0x00867F54 with a real 3 by 2 guest album, an extracted image feature and a fixed realtime clock. The native destination handle survives the smaller copy, has the registered sample, and receives next ID 321. It reports (94,93,100,17,Smaller). A wrong guest key leaves the prior sample and next ID with no report. Empty guest with metadata sizes 8 through 11 succeeds, while 7 and 12 through 13 with malformed suffixes fail. An unsorted metadata list reports signed numeric order with the unnamed entry. A duplicate ID uses its last record, clips future leading fields to now, and leaves future guest-slot age negative. Both defined unready prefixes return one with no output. The ARM oracle used fixture realtime and synthetic data only.

It tests the eight-byte parser boundary, raw non-ASCII name, signed ordering, duplicate replacement, negative and future ages, independently sampled clock phases, compatibility callbacks after replay, and replacement of the owner from the first 0x58. A real smaller guest loads through the NV path and identifies the face on subsequent camera frames. FaceRecognizerTests verifies the generic metadata helper and FaceAlbumFileStartupTests keeps its original file cases.
