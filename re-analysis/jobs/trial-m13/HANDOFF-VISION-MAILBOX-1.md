# VISION-MAILBOX-1

## Claims and evidence

- The input slot and completed-result FIFO are independent. SetNextImage replaces pending input at 0x006530CC–0x00653140. Processor takes it at 0x0065201E–0x00652212 and discards intervening pending input after UpdateVisionSystem returns (0x0065222E, 0x00652240–0x0065224C). A successful result enqueues at 0x006B5676–0x006B568C under the result mutex at +0x35C. CheckMailbox selects one front element, transfers its header and eleven lists, and pops and unlocks at 0x006B2AD4–0x006B2CC4. The managed FIFO already serves the supported live producers. The change makes original-owner admission, consumption and selective retirement explicit. It keeps the queue lock across owner validation and a single pop, releasing it before handlers or pose disposal.
- SetNextImage checks initialization and enable at 0x00652B1C–0x00652B24. A nonzero +0xE4 previous receipt is compared unsigned at 0x00652B26–0x00652B38. Accepted timestamps, including equal values, replace the receipt clock at 0x00652BFA before calibration and pose work. Older input warns at 0x00652B4E, clears received and processed clocks at 0x00652B76, and returns before input handover or result FIFO mutation. The warning format is at 0x006532C4/0x006532F8. The clock belongs to the original component lifetime (constructor 0x0065013A–0x0065013E). The shared processed clock starts at zero on a different-owner bind and is preserved on same-owner rebind.
- Robot::Update gates the drain on first full state and outer calibration at 0x00513C5C–0x00513C76. UpdateAllResults pops repeatedly until empty (0x00654A6E–0x00654A7A), runs the supported consumers in the original relative order, and aggregates a failure for that drain only (0x00654AC4–0x00654ACE). It writes the original component's processed clock at 0x006549A2–0x006549AA and broadcasts 0x43 through that component's original Robot at 0x00654A14–0x00654A1C. The stack's host callback runs before its clock and report tail. If the callback retires the source owner, neither the clock nor report crosses into the replacement. Valid failed results still reach their timestamp/report tail and affect that owner's tick.

## Files and tests

- Vision/NativeVisionInitialization.cs and Vision/VisionSystem.cs implement owner-local input admission and guard the consume path and processed clock. Vision/VisionResultQueue.cs carries FIFO ownership and fences the raw, typed and local report. CozmoEngine.cs guards the tick after the vision callback. DriveOffPilotVisionTests uses real F2 chunks, the worker and the normal tick for receipt/reset and result ownership. It exercises equal, older, zero and recovery input, preservation of pending and completed work, disabled and unavailable initialization, old-owner replacement and successor delivery, disposal during a callback, and FIFO/sticky failure with two real marker detections and injected world status. The first backward F2 frame is rejected by reassembly, the second reaches vision. NativeVisionInitializationTests checks the earlier source warning and reentrant successor binding. Affected 316/316 passed, and the independent final subset including unchanged NativeOkaoOracleTests passed 79/79. The initial sticky fixture needed real IMU inputs for the historical marker gate. An intermediate 72/73 run still expected the prior inner-worker warning, so the test now checks the earlier native SetNextImage warning.
