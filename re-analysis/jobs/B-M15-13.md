1. **The action** subclasses the stack's existing TriggerAnimationAction / PlayAnimationAction.
   - **Construct with** trigger Count (0x23F), loops 1, interrupt true, mask 0, timeout 60 s, strictCooldown false;
     own flag C9 = false; debug name `PlayNeedsGetOut`; action type PLAY_ANIMATION.
   - **Init** reads the shared SevereNeeds `Selected` *at Init*:
     - Repair → 0x141 `NeedsSevereLowRepairForceGetOut`;
     - Energy → 0x135 `NeedsSevereLowEnergyForceGetOut`;
     - Play → 0x13A `NeedsSevereLowPlayForceGetOut`;
     - 3 → log NoTransitionNeeded and return SUCCESS, keeping Count.

     For a real trigger, SetAnimGroupFromTrigger, then the inherited Init.
   - **CheckIfDone** (0x005451C8), in this order:
     1. trigger == Count → SUCCESS;
     2. else, if C9 is false and started (+0x88): Clear the SevereNeeds selection, then C9 = true;
     3. then ended → SUCCESS; else failed → ANIM_ABORTED 0x03000001; else RUNNING.
   - **Destructor or cleanup** (0x0054504C): if the current Selected != 3 and C9 is false, Clear. This applies to
     never-started, cancelled and failed actions too. Then the inherited cleanup.
   - **Completion** is the inherited PLAY_ANIMATION completion union. No bespoke message.
2. **The API:** `CozmoRobot` gets a method that queues this action the way the app's QueueSingleAction does:
   - union 20, NOW, 0 retries, main queue 0;
   - the caller's id tag, from the stack's existing API action-tag counter;
   - it returns the tag; completion arrives through the existing RobotCompletedAction delivery.

   Use the stack's existing API action path, as other union actions use it (see `DriveActions.cs:405` for a
   factory-backed example). If that path doesn't exist for animation actions, write MISSING and say what is absent.
   - The stack does not send it by itself. The app's hub, feed and SDK flows aren't reproduced (app boundary).
