## Why

The graders `M5HwAnalysis.FiniteLayers`, `Blinks` and `Audio` accept optional evidence (`FaceActivity`, `BlinkCall`,
`BudgetAdmission`) that only unit fixtures supply, so on hardware LAYERS, PARAMETERS and AUDIO are INCONCLUSIVE by
construction and the run can never exit 0. Read-only observation of engine state touches none of AGENTS.md "What we
reproduce" 1-4, so it is instrumentation, not invented behaviour.

## Work

### 1. Stack hooks (read-only)

Add one diagnostic channel to the animation code in `Cozmo.Robot` (for example an event on `AnimationScheduler` carrying
small immutable records). It reports, at the native point each grader cites:

- **Blink timer (M5-028; `0x58D382..38C`, `0x58D54C..550`):** for every `FaceLayerManager.KeepFaceAlive` call: a
  monotonically increasing call number, the blink timer before the 60 decrement, the timer after the call, and whether a
  blink layer was generated.
- **Layer face flag (M5-029; `0x64F204..22C`, `0x57C63C..C646`):** for every `StreamLayers` frame: whether the face flag
  was set (a face buffered) and, so the harness can join it to the wire, the frame's position in the stream's outbound
  order (for example the count of audio frames buffered so far). Join by stream order, never by timestamp alone.
- **Send admission (M3-012; `0x57C6F6..7AC`, `0x57BF96..BFCC`, direct End `0x57C464..496`):** for each buffered message
  offered at the gate: message id, size, the remaining byte and audio-frame allowances at that moment, and whether it was
  sent; for a direct End, a marker that it bypassed admission.

Rules:

- **No behaviour change.** No RNG draws, no allocation or ordering change on the engine path, no extra lock, no change
  to what is sent or when. With no subscriber, the hook costs one null check.
- **Subscriber safety.** Raised under the scheduler's existing lock; document that a handler must not call back into
  the scheduler or the robot and should only enqueue. A throwing handler is caught and logged (M1-034 style) and never
  alters the engine path.
- Tag each hook with the existing record (`// fidelity: M5-028` etc.) and cite the native address it mirrors.

### 2. Harness wiring

In `M5Hw.cs`, subscribe to the channel for the run (enqueue only), and pass the captured evidence into
`FiniteLayers`, `Blinks` and `Audio` (`activity`, `calls`, `admissions`), joined to the wire within each check's window.
`BudgetAdmission.Coherent` is true only for these gate observations. Update the graders' `missing` and verdict text
where it now says the evidence is unavailable. If a join cannot be made unambiguously, leave that row unjoined and the
verdict INCONCLUSIVE with a stated reason. Never guess.

### 3. DRIVING split

In `M5HwAnalysis.DrivingPhases`, the check's verdict covers M5-063: OBSERVED when the phase verdict is
`OBSERVED_SUCCESSFUL_START_LOOP_END_REQUESTS` or `OBSERVED_FAILED_START_END_CLEANUP`, whatever the drive result.
Keep `successfulTraversalCoverage` false, the traversal judgement NOT_JUDGED, and state in the rule that successful

failed-path run leaves Loop coverage open for a later run. Contradictions (for example Loop after a nonzero Start, or
a failed End action) stay non-OBSERVED as now.

## Regression requirements

- **Hook tests:** drive the real scheduler through a seeded sequence and assert the reported blink-timer values against
  the source rule (60 per call; a new deadline inside the configured min..max), the face flag against what was buffered,
  and admission rows against the native allowance formula (bytes `max(0, min(30000, played - streamed + 8192))`,
  frames `max(0, played - streamed + 14)`).
- **No-change test:** the outbound message sequence with a subscriber attached is byte-identical to the run without one,
  over a clip, a layer pulse and live idle.
- **Grader tests:** the join, with hook-supplied evidence, produces the positive verdicts. A missing or ambiguous join
  stays INCONCLUSIVE.
- **DRIVING tests:** the run-1 failed path gives OBSERVED with Loop not covered; a successful path gives OBSERVED with
  Loop covered; the existing contradiction cases stay non-OBSERVED.
- Expected values come from the cited native rules, never from running the code under test.
