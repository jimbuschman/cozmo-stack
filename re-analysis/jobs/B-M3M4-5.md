1. **M4-009, the Stopped loop dirties located matches** (`Cubes.cs:724`). The binary's Stopped loop runs the same body as
   the Moved loop (0x00534116..0x0053413C): at 0x00534924..0x0053494A it calls `ObjectPoseConfirmer::MarkObjectDirty(obj,
   false)` when `!IsCarryingObject(obj+0x14)` and `obj+0x24 == 1` (manager-checked). Build it on the Stopped path, passing
   the matched object itself, not a re-lookup by id. Test it.
2. **M4-009 / M4-018, no invented ObjectIDs** (`Cubes.cs:495` `WorldId`, `Lights.cs:739-740`). In the original the object
   always comes from BlockWorld's connected-object lookup, so its ObjectID is real (rows §3, §13.1). When the stack has no
   world or the lookup returns null, don't fall back to the active id (`Cube.ObjectId`). Emit a visible `MISSING:` line
   naming M4-009/M11-004 and skip what needs the id, as the power-level path does (`Cubes.cs:599-600`).
3. **M3-048, only engine log calls become engine entries** (`EngineLog.cs:53-70`).
   - The stack's own lines are not engine DAS entries: the M1-034 isolation lines (`CozmoEngine.cs:883`, M3-049;
     `Lights.cs:115`, M4-036), `MISSING:` lines, and other stack diagnostics. Route them to a separate stack-log stream,
     always shown and never filtered by the DAS display. Match the transport's isolation form (`ReliableTransport.cs:496`,
     its `Warning` event).
   - Only call sites that port an engine sEventF/sWarningF/sErrorF/sChanneledInfoF/DebugF produce entries.
   - Fix the parser bug: a line without ": " currently loses its first character (`rest = line[1..]`, e.g.
     `NvStorage.cs:609`). Better still, have the engine sites call the entry API directly instead of parsing text.
4. **M4-035, no callouts under `_gate`** (`CubeConnections.cs:516-525`). SendBlockPoolData runs inside `lock (_gate)`
   and calls `FlushLogs`, `_log` and the public `BlockPoolData` event. Queue the log line and the event as the class
   already does for logs (`Queue`/`FlushLogs`, :281-293), and deliver them after the lock is released, in the engine's
   order: the info, then the message. The `+0x74 := now` store stays where it is. Also move these out of their locks:
   - `Sensors.cs:503-507`, the event and `SendCliffDetectThresholdToRobot` under the sensors lock;
   - `AnimationScheduler.cs:140-149`, the logs under the stream lock;
   - NvStorage `LogCall`, engine log subscribers under the NV lock;
   - `Lights.cs:765`, the PlayLightAnim timer clear, which re-takes the lock and lets Update run in between. Make the
     push and the clear one locked step.
5. **Hardware evidence must not be filtered** (`M3M4Hw.cs:339`, `ControlCheck.cs:694`). The scripts build bundle evidence
   from `Engine.LogLine`, which now drops info and debug. Have them record the **structured entries** (`LogEntry`, every
   level) plus the stack-log stream into the bundle. The display stays as built. Check that the M3-022
   `ReadCameraCalibration.Recvd`/`IgnoringDistCoeffs` lines, the M1-040 firmware line and the `SetCameraSettings` info
   reach the bundle. Test it.
6. **M3-053, the circular test** (`EngineDisplayTests.cs:69`). How `_DAS_GetLevel` (libDAS 0x11758..0x11866) treats an
   intermediate override node depends on DASConfigure's tree insert, which is unread. It is unreachable with the shipped
   DASConfig.json (no overrides; M3-052 fixes the input). Remove that assertion. In the code, replace the
   intermediate-node behaviour with a comment naming it unreachable with the shipped input, and keep the root-level and
   exact-match paths. Test only what the rows give.
