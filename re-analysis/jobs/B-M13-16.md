Existing code is a candidate: keep what the rows support, repair what they don't.

1. **M1.** Caller order: world callback, map(old), then the state-change tail; a changed nonzero state calls the map
   again with the old state (0x00506F98..0x00506FB8, 0x00506296..0x005062B4). Invalid -> Known therefore adds twice.
2. **M2.** Family 6 returns (0x0067EA9C). Invalid -> valid adds the current pose; valid -> Invalid removes with the
   old pose's root; both invalid logs and sets the error flag (0x0067EB2C).
3. **M3/M4.** Both valid: per-ID outer cache, current-root inner entry. Missing entry adds. A false added-flag
   retries; true compares with 5 mm per axis and angle 0x3E32B8C2 and skips when within. The retry removes first only
   when slot+0x5C returns exactly 1 (the charger's returns 1, 0x004E3882), then adds. Keep "false entry" and "absent
   entry" distinct; no timestamp dedup.
4. **M5/M6.** Family 4 -> content 4 adding, 5 removing (0x0067F4C0). Add needs an existing map for the pose's root,
   else returns before height and cache. Query relative to Robot::GetPose; IsPoseTooHigh(relative,1,15,0) == 1 records
   the supplied pose with added=false. Use the existing height helper (M12-012/M11-088 boundary); fix the height defect
   from the 20261021 check.
5. **M7/M8.** Accepted: root-relative pose, quad padding 0; type-4 base data with both stamps from the last image,
   MemoryMap::Insert; then write the cache entry (added=true) whatever Insert returned; then FillBorder(9, mask
   0x00C87675 = {3,4,5,6,7,10}, 10, time).
6. **M9.** Remove's callback matches only content 3 plus ObjectID, so a type-4 charger footprint is never removed by
   it. No blanket charger removal.
7. **Tests** (label reach; old value and fail): Invalid -> Known adds twice; within-threshold valid/valid skips;
   false entry retries with remove-then-add; root without a map adds nothing and caches nothing; too-high records
   added=false; charger removal leaves the type-4 content; CanDriveIdealDistanceForward (0x005C2420, W1) sees the
   charger content if the stack has that query, otherwise MISSING.
