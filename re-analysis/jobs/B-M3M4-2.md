corrects Part A** and gives the WebP probe. M3-045's `unresolved` and Part C.5 hold the manager's rulings.

**Build:**
- Port `imdecode_`'s signature dispatch exactly:
  - the window is **always 32 bytes**: the payload's first min(32, size) bytes, then 0x20 (space) padding up to 32
    (Part C.1; Part A3's "min(32, size)" is wrong);
  - every A.2 check runs on that 32-byte window as the code does, so length tests such as PxM's "size > 2" always pass
    and the padding can decide a match (for example, the payload "P5" matches PxM);
  - decoders are tried in registration order: BMP, HDR, JPEG, WebP, SunRaster, PxM, TIFF, PNG, JPEG2000, EXR;
  - the first `checkSignature` match wins;
  - no match gives the empty Mat, with no log.
- **WebP's check** (decoder 4) is the probe in Part C.2/C.3, rows P1..P13, ported exactly (P1's version test
  included). WebP is now identified by its RTTI name, not inferred.
- JPEG keeps the existing port.
- A match on any of the nine other decoders is a visible `MISSING:` (the decoder body isn't ported) and returns the
  empty Mat.
- Code: `cozmo-stack/src/Cozmo.Robot/Vision/Jpeg/OpenCvImdecode.cs`.

**Tests:**
- one payload per signature, routed to the right decoder (JPEG decodes; the others give MISSING and an empty Mat);
- short payloads where the padding decides the result ("P5" to PxM; a short payload starting 0x2F to WebP);
- the WebP probe: each acceptance shape in C.3 (RIFF+VP8X, VP8L 0x2F by each route, VP8 key frame) and a rejection on
