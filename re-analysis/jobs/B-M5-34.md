# B-M5-34: Make the M5 operator observations understandable

Operator request, 2026-10-20: the test is confusing; the operator cannot tell what
to look for. Manager-dispatched to a separate implementer in this workspace,
followed by manager affected-diff review.

## Scope

`cozmo-stack/src/Cozmo.Conformance/M5Hw.cs` and operator-facing wording in
`re-analysis/acceptance/hardware/scripts/m5-hw-1.md`. The manager owns this job,
its status, review and handoff. No engine, graders, manifest, inventory or
hardware-run changes.

## Required result

- Plain-language previews before each human observation: where to look, what
  happens, what to remember and the questions that follow.
- Pause for Enter before starting the marked observation, so reading does not
  consume the interval. Preserve --yes and cancellation behavior.
- Clear START/END markers without asking the operator to interpret host timestamps.
  Keep all actual timestamps in the saved evidence.
- Numbered answer choices with plain definitions. Distinguish not-seen (watched
  and saw none), unclear (watched but cannot decide), and not-observed (missed it).
- Explain blinking, eyes shifting on screen, head movement and wheel/body movement
  separately. For cancellation, distinguish the original animation from subsequent
  blinks/darts. Do not invent an exact appearance for an arbitrary selected clip.
- Preserve the actual loaded resting-eye reference and its comparison requirement;
  explain opening the SVG and comparing eye outlines rather than color/scan lines.
- Label automatic checks as automatic with no answer required. Explain that the
  operator records observations, not a pass/fail judgement.

Do not change canonical answer tokens, evidence fields, grading gates, robot
commands, sample durations or the DRIVING split. The only added wait is the
pre-observation readiness prompt, outside the marked window. Preserve unknown and
unobserved outcomes; never coach the operator toward a passing answer.

## Verification

Review every changed call site for timing/window placement and unchanged grading.
Run existing M5Hw tests and offline --validate. Do not add tests that merely
