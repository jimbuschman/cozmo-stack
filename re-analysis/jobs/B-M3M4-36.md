## Items

1. **Build the VisionSystem with the robot.** Native constructs the VisionComponent and BlockWorld with the Robot, so every
   production CozmoRobot has them. Make CozmoRobot construct its VisionSystem (and so its BlockWorld, the cube ObjectID lookup
   and the light recipient) as part of its own construction, and expose it to hosts (for example `robot.Vision`). Keep the
   calibration path the code uses today (M11-049's NV read). Do not change what VisionSystem does once built, its threads'
   start conditions, or the existing public `Enabled` behaviour. The constructor's optional calibration, detector and
   OKAO recognizer arguments become robot options with the same defaults (null calibration as today). Late-construction
   handling in the VisionSystem ctor (events that fire once, e.g. M11-037's firmware event) must still work when the
   VisionSystem is now built before connection; say in the status file what each such path does in the new order.
2. **Callers.** Conformance tools and tests that call `new VisionSystem(robot, …)` use the robot's own instance. Tests that
   need the world-less composition construct it explicitly through an internal test seam and say so (`reach: unit`).
3. **World-less MISSINGs.** With the world always present, `Cubes.cs`:526 and :820, `Lights.cs`:1091, and
   `CozmoRobot.cs`:859-865 (charger-platform step) are unreachable in production. Keep them as visible guards for the test
   composition, or remove them; either way no production path may reach them. Check the Lights ObjectID-unavailable logs
   (`Lights.cs`:1275, 1300, 1323, 1346, 1556): if a production path can still reach them (a cube type with no connected
   world object), report the case in the status file; do not invent an ObjectID.
4. **Lifetime.** The VisionSystem is disposed with the robot, in the order the code already uses when a host disposes it
   first (M4-027 / M11-055 teardown). No new teardown step.
5. **Cleanup (queued, non-behavioural):** the four items in `research/20261019-m3m4-settle.md` "Cleanup folded into
   B-M3M4-36".
6. **Tests.** A production test: a real `CozmoRobot` connected over the framed test peer, with no host-built VisionSystem,
   receives ObjectMoved for a connected cube and reaches M4-009's located loop (no MISSING), and a public PlayLightAnim for
   that cube sends CubeLights. Expected values from the shipped light JSON and the checked rows, not from the code.
