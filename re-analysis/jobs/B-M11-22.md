The map add, update and remove stamp calls Robot::GetLastImageTimeStamp at 0x0067EFCE, 0x0067F0A6 and 0x0067F32C.
That getter (0x00516EC0) returns robot+0x258 → VisionComponent+0xE8. Since B-M11-21, the stack holds that value as
`CameraSettings.LastProcessedImageTimestamp`, written after the result handlers and used by the overhead writer's
border.

1. **Bind** `Maps.ImageTimestamp` (BlockWorld) to that same value, and remove the "unsourced stand-in" MISSING at
   `BlockWorld.cs:832`.
   - The stand-in is `VisionSystem.cs:100`: max of `Camera.LastFrame.Timestamp` and `_frameTimestamp`.
   - Keep a visible MISSING only when no vision component exists (`MissingMapImageTimestamp`).
2. **Other readers of `World.LastImageTimestamp`:** list each one and say which clock it should read. Change a reader
   only if its native getter is this same 0x00516EC0. Otherwise write MISSING for it and continue.
   - `Behaviors.cs:739` binds `vision.LastRawFrameTimestamp` for a behaviour context. Name its native getter, or write
     UNKNOWN.
3. **Tests** (label reach, give the old value, show each fails on the old code, dispose everything):
   - during a frame's handlers, the map stamp of an object added equals the previous result's processed timestamp,
     not the current raw frame's (old: the current frame);
   - 0 before the first processed result.
