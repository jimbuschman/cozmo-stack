# Job I-M15: turn the M15-freeplay extraction into an approved inventory

**Agent:** opencode, as cozmo-manager. **Type:** integration. **Needs:** job X4 DONE. If it isn't, set this job's status to `WAITING X4` and end.

## How to do it

0. Read `re-analysis/jobs/README.md`, `AGENTS.md` and `.opencode/agent/cozmo-manager.md`. Exact, always; no guesses.
1. **Claim the job:** write `re-analysis/jobs/status/I-M15.md` with `CLAIMED <date time>`, then commit and push that file alone.
2. **Read the extraction reports:** `re-analysis/research/*-X4-M15-freeplay*extraction*.md`.
3. **Check the citations.** Give `@cozmo-verifier` every row that changes a record's status or contradicts one, plus a sample of at least 20 others. Ask it to open each citation in the `.so` and confirm it says what the row says.
   - A row that fails goes back to `@cozmo-extractor` to be fixed.
   - Never keep a row that failed the check.
4. **Close the gaps.** Rows marked UNKNOWN or RECOVERABLE_GAP go to `@cozmo-extractor` for a gap pass, with the report written to `re-analysis/research/<yyyymmdd>-I-M15-gapN-extraction.md`.
   - Repeat until every row is settled, or is HARDWARE_ONLY or BLOCKED_EXTERNAL with a reason. At most 3 gap passes.
   - Whatever is left stays RECOVERABLE_GAP, with exactly what to read.
5. **The inventory:** write `re-analysis/inventory/M15-freeplay.md` in the same form as `re-analysis/inventory/M10-derived.md`:
   - a header saying where it comes from (the sources and the passes);
   - a Records table naming every record id of the subsystem, new ones included, each with its rows;
   - Decisions: which standing decisions (SD1..SD4) were applied, and where;
   - the existing record evidence found contradicted or too weak;
   - appendices with the full report texts.
6. **The records** in `re-analysis/fidelity_manifest.json`, for every record of the subsystem:
   - set title, location, evidence (the citations), effect, authority, hardware_required and live_path;
   - **status:** IMPLEMENTATION_GAP for everything to be compared or built. That includes records marked EXACT_SOURCE before this process: those claims were never checked. Use HARDWARE_ONLY, BLOCKED_EXTERNAL or RECOVERABLE_GAP only where the rows say so, with the reason;
   - new records continue the numbering;
   - set the subsystem's `review.inventory` to `re-analysis/inventory/M15-freeplay.md`, `implementation_fidelity_complete` to false, and `source_investigation_exhausted` to false if any live-path RECOVERABLE_GAP is left, otherwise true.
7. **Approve it:** `python re-analysis/tools/fidelity.py --approve M15-freeplay`, then `--write`, then `--check`. The check must pass.
8. **Commit and push:** commit only the inventory, its `.approved.json`, the manifest, `re-analysis/FIDELITY_GAPS.md`, your gap reports and your status file. Then `git pull --rebase` and push. If the rebase conflicts in the manifest, keep both sides' records, run `--check` again, then push.
9. **Finish:** set the status to `DONE <date time>`, with the record count for each status. If you can't go on, set it to `BLOCKED <reason>`.

**Write scope:** `re-analysis/inventory/M15-freeplay.md`, its `.approved.json`, this subsystem's records in the manifest, `re-analysis/FIDELITY_GAPS.md`, `re-analysis/research/*-I-M15-*`, and `re-analysis/jobs/status/I-M15.md`. No code. No other subsystem's records.
