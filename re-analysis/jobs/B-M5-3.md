## 1. Blocking

1. **M5-011 G4: the draw always happens** (`AnimationLibrary.cs:118-120`).
   - In GetAnimationName, both the end of the loop (0x0058AA70) and the empty-entries branch (0x0058A9FC
     `beq 0x58aa72`) reach `RandDbl` at 0x0058AA72..0x0058AA7E.
   - The empty-candidates test comes after it (0x0058AA86 `beq 0x58ab30`).
   - So every pass consumes one RandDbl (two MT outputs). That includes passes that go on to NoMoodMatch (which recurses
     and draws again), to the backup, or to NoAnimation.
   - **Fix:** draw before the empty test.
   - **Test:** the shared ContextRandom stream position after an empty pass.
2. **M5-038: no null action on the production path** (`CozmoAnimations.cs:169`, `CozmoEngine.cs:2118`).
   - `SleepTriggerFactory` is never assigned, so `QueueGoToSleep` queues null and emits the engine warning
     `ActionList.QueueAction.NullAction`, which the engine never emits here: CreateGoToSleepAnimSequence
     (0x0052CEA2..0x0052CFBE) always returns the compound.
   - **Fix:** while the M8 recipient is missing, don't queue anything. Emit the visible `MISSING:` line on the stack
     stream and keep the earlier visible fallback (the `GoToSleepRequested` host event).
   - **Test** the CC6 path: no NullAction warning, MISSING present.
3. **M5-001 L6.4: a read failure logs `BinaryDataEmpty`** (`AnimationLibrary.cs:418`).
   - ReadFileAsBinary (0x00803584) returns an empty vector when open fails (0x0080361C..0x00803622).
   - LoadAnimationFile tests begin==end first (0x005213B4) and logs `RobotDataLoader.LoadAnimationFile.BinaryDataEmpty`
     (sErrorF 0x005213DA).
   - Every read failure, of any exception type, becomes the empty-vector path. None may escape the worker or abort
     Open.
4. **M5-047: the stop must not produce engine errors** (`AnimationLibrary.cs:145`, `AnimationScheduler.cs:1156`,
   `CozmoEngine.cs:1206-1211`).
   - When the backup reaches an entry whose window is unknown (M5-047), the result is "unknown", not "none". The engine
     always picks something there.
   - **Fix:** carry a distinct unknown result, and on it take no engine-logged path:
     - no `EmptyIdleAnimationFromGroup`;
     - no `NoAnimationForTrigger`;
     - no `_errG`;
     - no nonzero Update result;
     - no `Robot.Update.AnimationStreamer` warning.

     On the idle path, start no idle that tick. On the trigger path, return a failure to the host API.
   - Emit `MISSING: M5-047 <group>` on the stack stream once each time a group enters this state, not every tick.
   - **Test** both paths.
5. **G1's mood is a silent default** (`AnimationLibrary.cs:475`).
   - G1 reads `MoodManager::GetSimpleMood()` (0x0058A954). If the stack has the M7 mood manager's simple mood, wire
     `CurrentMood` to it.
   - Otherwise emit a visible `MISSING: M5-011 SimpleMood (M7)` line once, and keep Default.
   - Don't restore the caller-supplied mood. The engine doesn't take one.
6. **No invented engine result** (`CozmoAnimations.cs:260`). A caught host exception is M1-034 isolation: log it on the
   stack stream, and return 0, not 1, so no `Robot.Update.AnimationStreamer` warning is emitted for it.
7. **L10b LoadTime** (`AnimationLibrary.cs:303`). Use a monotonic clock in nanoseconds × 1e-6 as a double
   (`clock_gettime(CLOCK_MONOTONIC)`, 0x00833D40..0x00833D6A), not integer wall-clock milliseconds.
