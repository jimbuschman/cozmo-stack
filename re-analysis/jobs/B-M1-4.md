## What this delivers (the supported function)

A running stack goes through the engine's own states: started, loading (with progress), ready (animation list
delivered, then the ready state) or failed. Robot connection and robot updates run only once ready, as in the engine.

## Items

   native handler path 0x004ECBDA..0x004ECC4A: seed, SetLocale, then SetEngineState(1) unless already 3 (state 3 logs the
   error). Use the stack's existing seed and locale settings; don't invent new defaults.
2. **SetEngineState** 0x004ECCBC: same state does nothing; store first (0x004ECCD2); then deliver UpdateEngineState
   {old, new} (tag 0x7B, 0x007276F8) to the C# API; telemetry `app.engine.state` best effort. Expose the transitions on
   the C# API as the loading/ready states the operator asked for (M1-056).
3. **State 1 → 2 (M1-058 (2)).** The C# API host is the one connected UI device from engine start. Keep the native
   gate as written (0x006632F4..0x0066330E: some slot, count ≠ 0, count ≥ desired 0). SendSupportInfo is **not

   exit the tick (0x004ED5EE). Not supported: UiDeviceAvailable,
   UiDeviceConnected, Ping (M1-059); build none of them.
4. **State 2: loading.** The poll per OV124 rows 8/12 and OV125: copy progress out, done short-circuit, start the
   worker once (0x005235E2), join only at ≥ 1.0f with the native comparison (0x005235A2/0x005235AA), then return 1.

   Use the stack's existing loaders for the work; the progress arithmetic follows the rows. Expose progress on the API.
   On completion (exactly 1): the post-loading broadcast (already built) then SetEngineState(3) (0x004ED60E).
5. **Failed (M1-058 (3)).** A missing resources root, or a loader failure the stack can detect, reports **failed** on
