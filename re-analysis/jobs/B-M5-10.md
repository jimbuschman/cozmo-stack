## 1. Blocking

1. **G11 on any rejected entry** (AnimationLibrary.cs:961, :396-400).
   - `AnimationGroup::DefineFromJson` sets sb=1 on any entry failure (0x0058A6CA) and returns `sb & 1` (0x0058A798).
   - So the container logs `AnimationGroupContainer.DefineAnimationGroupFromJson` "Failed to define animation group
     '%s' from Json." plus errG/break for **any** rejected entry (0x0058B8B6..0x0058B916). Today it does so only for
     NoAnimations.
   - The rejected entries are NoName, InvalidName, NoWeight, NoMood, BadType and NoHeadAngle. Valid entries are still
     defined, and the group is still added (the result is ignored by G9).
   - Test: a group with one bad entry gives AddEntryFailure, then G11.
2. **The mood string** (AnimationLibrary.cs:925).
   - `SimpleMoodTypeFromString` (0x00791F0C) maps {Happy:0, Sad:1, Default:2, Count:3} (0x00791F3C..0x00791FA2).
   - A miss writes "error: string '…' is not a valid SimpleMoodType value" (0x007920F0) to an ostream and returns
     **0, which is Happy** (0x00792050). Read where that ostream goes. If it's stderr, the stack writes nothing to the
     engine log; if it's unclear, emit a visible MISSING on the stack stream.
   - BadType only when the result is 3, i.e. the string "Count" (`cmp r0,#3`, 0x0058C5D4).
   - So "invalid" and "0" are Happy entries.
   - Fix the code and the test InlineData at M5X9BuilderTests.cs:84.
3. **A face-name miss logs a pair, twice** (AnimationScheduler.cs:1521, :1531-1537).
   - GetNumFrames first calls GetAnimationByName (0x005816DE). On a miss, that function warns
     `FaceAnimationManager.GetAnimationByName.UnknownName` "Unknown animation requested: %s" (0x0058140C, 0x00BEF6A9,
     sWarningF 0x005813B4). Then GetNumFrames warns (0x00581714).
   - FaceAnimationKeyFrame::GetStreamMessage calls IsDone through vtable+8 (0x004F97D4; vtable 0x0101F0B8, reloc
     0x0101F0C0), and IsDone calls GetNumFrames (0x004F97A0).
   - Emit the UnknownName and GetNumFrames pair at each native call, in native order. Fix M5X9BuilderTests.cs:257.
4. **`asString` does not throw for scalars** (JsonClipLoader.cs:96-99, AnimationLibrary.cs:554-556).
   - FaceAnimationKeyFrame::SetMembersFromJson (0x004F9434) calls `GetValueOptional<string>` (0x004F9528), then
     `GetValue<string>` (0x008400D8), then `Json::Value::asString` (0x008E48B0).
   - That converts int, uint, real and bool (0x008E4906, 0x008E48E2, 0x008E48F2, 0x008E4916). Read the exact text each
     one produces: real formatting especially, and "true"/"false".
   - Only array and object throw, which falls under M1-034 (skip the file).
   - So a numeric or bool `animName` defines the keyframe with that text. Do the same for `DefineDeviceAudio`'s
     `audioName` (:446-448): read its native site first.
   - Restore per-keyframe handling, so that only a real JsonCpp throw skips the file.
