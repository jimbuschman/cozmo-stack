# R-BEH2 extraction gap pass 1 for M8-framework: BehaviorHelperComponent (M8-011), the pose base in AIWhiteboard (M8-014), the C# callers

- Job: R-BEH2, extraction gap pass 1. Date: 2026-10-03 (file name carries the manager's date 20261002).
- Kind: read-only extraction. Every address below was disassembled from `resources/lib/armeabi-v7a/libcozmoEngine.so` (ELF ARMv7/Thumb) with capstone and lief (scratch scripts only). `re-analysis/decomp` was not used as evidence. The earlier report `research/20260929-R-BEH-M8-framework-gap1-extraction.md` was used as a lead list and every row of it that is repeated here was re-read.
- Conventions: symbols carry no Thumb bit. `PLT 0x004acXXX` is the import stub; its target is named by the relocation, not by an address. `this` is r0. A std::function in libc++ is 24 bytes: storage 0x00..0x0f, manager pointer at +0x10 (a manager equal to the storage address means small-buffer); "empty" means manager == 0. A shared_ptr<IHelper> is 8 bytes: pointer, control block. For a control block, `[ctl+4]` is `__shared_owners_`, which is -1 when no owner is left.
- BehaviorStatus values as the engine uses them: 0 = Failure, 1 = Running, 2 = Complete. Evidence: `IHelper::LogStopEvent` 0x005b6850 maps `[this+0x1c]` 0 -> "robot.behavior_helper.failure" (adr 0x005b694c), 2 -> "robot.behavior_helper.success" (adr 0x005b696c), 1 -> "robot.behavior_helper.cancel" when its bool is 1, else "robot.behavior_helper.inactive_stop" (0x005b68a0..0x005b68c2); `UpdateActiveHelper` 0x0056de74 sends 0 to `OnDelegateFailure` (0x0056dee8) and 2 to `OnDelegateSuccess` (0x0056dedc), and tests `cmp r0,#1` for Running (0x0056df20). This agrees with M8-012's "IBehavior::Update return 0/2 finish, 1 keeps".
