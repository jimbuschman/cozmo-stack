# Verifier report: R-VIS M11 build batch A

Verifier: cozmo-verifier (read-only), 2026-09-29. The full report came back as text; this file is the manager's transcription of its verdict. **VERDICT: FAIL.** Judged: `Vision/BlockWorld.cs`, `VisionSystem.cs`, `RobotStateHistory.cs`, `ChargerGeometry.cs`, `CameraCalibration.cs`, `CozmoEngine.cs`, `Behavior/CubeReactions.cs`, `Conformance/VisionTool.cs` and the tests. Addresses are in `libcozmoEngine.so`.

## Objections (most severe first)

1. **MarkObjectUnknown (BlockWorld.cs) collects one object on top and one underneath; the engine loops upward only and never looks underneath.** 0x00507128: with propagate (`cmp r4,#1` at 0x00507162) the set starts as {obj ID} (0x0050715E); the loop head 0x005071D2 builds a fresh filter ignoring the current object's ID (0x00507220) and families 6 and 7 (0x00507224..0x00507240); it calls FindObjectOnTopOrUnderneathHelper(r7, 15.0f (`movt r2,#0x4170` at 0x00507252), filter, onTop = 1 (`movs r1,#1; str r1,[sp]` at 0x0050724C/0x0050724E)) at 0x00507258, the only call of PLT 0x4A7144 in 0x507128..0x5075A4; a result that is not carried is inserted into the set (0x005072C6) and becomes the next r7 (`bne 0x5071D2` at 0x0050731E); a carried result logs a warning (0x00507288) and the walk continues without adding it; then RobotMarkedObjectPoseUnknown is broadcast per set entry (0x005073B8) with the ORIGINAL object's ID every time (0x005073AA..0x005073B2); then DeleteLocatedObjects (0x005073F4) and `*objRef = null` (0x005073FC); no confirmer erase anywhere in the function. Effect: an upper cube deleted by two misses also deletes the cube under it in the C# (the engine does not). The test `M11_007_TwoConsecutiveMissesDeleteTheObjectAndItsStack` never asserts the lower object survives.
2. **CheckForUnobservedObjects candidate test adds a compensation.** GetLastVisuallyMatchedTime is fully readable (0x00507824..0x0050783A: finds the entry by ID and returns `[entry+0x30]`, or 0 if absent); the engine's test is only `GetLastVisuallyMatchedTime(ID) < ts` (`bl` at 0x00621D64, `cmp r0,r5; bhs skip` at 0x00621D68). The C# adds `o.LastObservedTimestamp < timestamp` (a union) to compensate for the unbuilt M11-044: +0x30 is written by AddVisualObservation (0x00506A9C..0x00506AA4) and a confirmed object reaches it every frame through PotentialObjectsForLocalizingTo::Insert -> UseDiscardedObservation (call at 0x0050CDF6); in this build a confirmed object skips it (0x00620C5C gate), so +0x30 goes stale. The manifest and code present this as an unresolved reading of an unread getter, not as a stand-in for M11-044.
3. **CanBeUsedForLocalization stub (throws NotSupportedException) on a reachable live path.** ActiveCube vtable slot 0x101CE04 relocates to ActiveObject::CanBeUsedForLocalization; thunk 0x004E4ACC leads to body 0x004E49AC: it needs PoseState == Known (`[+0x24] == 1`), activeID `[+0x40] >= 0` and fromDistance `[+0x10] >= 0` (0x004E4A06..0x004E4A28), then calls vtable +0x1C (0x004E4A30). The C# throws when UpdatePoseInInstance's second skip clause decides (instance == existing && !closeAndSteady && Known). Reachable: a Known cube gets one miss, then is re-sighted at more than 250 mm; the Processor's catch swallows the exception and the frame's tail is lost. Visible (test `M11_007_TheLocalizableTestIsAVisibleStub` asserts the throw).
4. **WarnIfNotConnected's 'now'.** 0x00620E42 calls BaseStationTimer::getInstance and 0x00620E46 GetCurrentTimeInSeconds; the result goes to r5, then s22 (0x00620E5E). The C# uses frame timestamp / 1000; the test `M11_013_AnUnconnectedCubeIsKeptAndWarnsOncePerTenSeconds` advances rig.T by 11 s, entrenching the wrong clock (log timing only).
5. **AddAndUpdateObjects dist.** The engine calls `bl 0x4EA398` at 0x00620BE2 (Robot::GetPose, Robot+0x298, the current pose); the C# uses pd.RobotPose (image-time pose). dist feeds the 250 mm Known/Dirty gate.
6. **FindObjectMatchForObservation non-unique branch** (not reachable for cubes or charger, which are unique): predicate 0x006281DA writes abs(delta) back to both the translation tolerance (`[r4+0xC]`, 0x00628248) and the angle tolerance (`[r4+0x10]`, 0x00628250); the C# narrows only the translation. FindLocatedClosestMatchingObjectHelper 0x0061FA68 also adds the observed object's own ID to ignoreIDs (0x0061FAA6).
7. **FindLocatedForObserved non-unique branch** (not reachable for cubes or charger): the engine calls GetLocatedObjectByIdHelper(id,-1) at 0x00620FE0 with no not-carried predicate; the C# adds `!Carrying`.
8. **CheckForUnobservedObjects xPad/yPad = 0.** The formula is readable at 0x0062206E..0x006220DA (camera-to-object translation length, GetMaxLocalizationDistance_mm 0x00621F36, `(2.0 - d/max)`, fields at calib+4/+8 and node+0x18/+0x1C). The decision (MarkObjectUnobserved iff visible, or (not visible, hasNothingBehind and Dirty)) is verified at 0x00622106..0x0062218E.
9. **AddAndUpdateObjects omits the BlockWorld+0x58 store.** 0x00621214: `BlockWorld+0x58 = (u32)fmax((double)ts, MemoryMap.vt+0x38())` after this+0x54 = 1 (0x006211E6).
10. **UpdateObservedMarkers** uses the frame timestamp where the engine uses Robot::GetLastImageTimeStamp() (empty-list branch 0x00625028; UpdateMarkerlessObjects 0x0062521A).
11. **Wiring and live behaviour.** World.DockingObjectId, UnSetCarryObject and BlockConfigurationManagerForceUpdate have no production wiring (disclosed in M11-007). VisionSystem.cs:64 subscribes to PhysicalRobotSet with no catch-up; the tools build VisionSystem after `await ConnectAsync` (ManipTool.cs:28-29) and CozmoEngine.cs:790-792 raises the event once: if FirmwareVersion has already arrived the LiftOccluderPoints stay empty and the lift occluder is never filed (ordering untested). The regression is real: a Known cube marked Dirty (ObjectMoved, MarkObjectDirty) and re-seen inside 35.2 mm never returns to Known, because IsObjectConfirmedAtObservedPose is true so AddVisualObservation is skipped (0x00620C5C); the engine returns it to Known through Insert -> UseDiscardedObservation (M11-044, unbuilt). The gap is visible (named test `M11_044_AConfirmedObjectsPoseIsNotRefinedUntilInsertIsBuilt`, the counters, the M11-044 record) but the Dirty-stays-Dirty consequence is stated nowhere. VisionTests `AMovedReportMakesTheCubeDirtyAndTwoSightingsAfterItStopsMakeItKnownAgain`: `Assert.Equal(before, o.Pose)` encodes the missing path as the expectation (circular against the unbuilt M11-044).
12. **Citation defect (harmless):** the 'extra predicate 0x00620D20..0x00620DE6 unread and not applied' is a plain function pointer 0x006215C4 (`ldr r1,[r0]; ldr r1,[r1,#0x5c]; bx r1`) = IsUnique(), always true there.
13. **Tests.** ManipRig.Frame() processes two images while any in-view object is 'unconfirmed', decided with BlockWorld.ObjectMatchToleranceMm (an implementation constant); Rig.State and WorldRig.State force Status |= HeadInPos: together they silently alter the semantics of about 130 tests (none exercises a first sighting through Rig.Frame; the camera-moving path is covered only by two named tests). `M11_013_AnObservedUnconnectedCubeGetsTheCountersIdOncePerType` has a vacuous `if (one is not null)` assertion. The class comment claims 'every expected value comes from the citation', but items 2 to 4 and 11 are exceptions.
14. **Static-state races:** none found. ObjectIdSpace and s_unconnectedWarnUntil are locked; M11RVisBuildTests is in a DisableParallelization collection; other classes seed the same values (7, 8, 9, 100), so concurrent writes are idempotent. Residual: seeds overwrite the process map while other classes run; `_markerTimestamp` and `_didObjectsChange` are written outside `_gate` (benign on the vision thread).
15. **Manifest:** `fidelity.py --check` clean (409 records); no status raised; the new records' `unresolved` text has inaccuracies (items 2, 3, 4, 8, 12).
