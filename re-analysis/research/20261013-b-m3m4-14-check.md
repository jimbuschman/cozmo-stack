## Blocking

1. **ApplyAnimModifier adds per LED, not LED 0's values to every LED** (Lights.cs:910).
   - 0x00638AD0 `add.w r3, sb, r2` runs with r2 = 4i, and r2 is incremented only after it (0x00638AD4).
   - The loads come from r3: [r3,#0x20] (0x00638AE0), #0x30, #0x40, #0x50 and #0x60 (0x00638AFC).
   - So onPeriod[i] += mod.onPeriod[i] (mod+0x20+4i), and the same for offPeriod, transitionOn, transitionOff and
     offset.

   `research/20261012-m4-046-anim-modifier.md` dropped the +4i. That file is now corrected.
2. **Circular test:** M3M4X14BuilderTests.cs:104-111 expects LED 0's additions on every LED.
3. **canBeOverridden comes from the last pattern** (Lights.cs:1034; M4-018 LC2/LC3).
   - 0x006386EC loads the container list (GetAnimation's result, 0x006383D6);
   - 0x006386EE `ldr r0,[r0]` reads libc++ `__prev_`, which is the back node;
   - 0x006386F0 `ldrb r0,[r0,#0x98]` reads that node's canBeOverridden, stored to +0x24 at 0x006386F4.
   - The same function reads [list+4] for begin (0x006385E4, the first pattern's duration), which confirms the layout.
   - Nothing rewrites +0x24 per pattern.

   **Shipped data:** wakeUp.json, sleep.json and pyramidFlourish.json end with a false. So WakeUp and Sleep are pushed
   non-overridable, and a layer-2 play during them gets CantBeOverridden. The approved LC2 ("the first pattern's") and
   LC3 ("fadeOut's false is never applied") were wrong; both are corrected on M4-018.
4. **The blended slot is shared, not copied** (Lights.cs:1024/1028/1032; M4-045 B3).
   - 0x006385B6 `list::assign` writes into the per-object slot node+0x44+12·layer, reusing its nodes.
   - info+0x10 := [slot+4] (an iterator into the slot) and info+0x14 := the slot (0x00638698..0x006386A8).
   - Update walks that iterator (0x006379A6..0x006379AE).

   So a later blended play on the same layer overwrites what an earlier blended entry, buried under a non-blended one,
   resumes with. The stack copies the reference at push time.
5. **The +0x44 timer offset is never read in Update** (Lights.cs:784/1033, 1106/1114). When advancing, the original
   does timer := 0, then if (dur | [+0x44]) != 0, timer = now + dur + [+0x44] (0x00637B3A..0x00637B4E). It holds while
   timer == 0 (0x0063798A..0x00637994). The stack uses now + DurationMs with no offset and no zero guard, and holds on
   DurationMs == 0.
6. **Unsupported change to the cube trigger-map loading** (Lights.cs:595-597).
   - `TryGetProperty` became `GetProperty`, so a pair missing CladEvent or AnimName now throws out of the CozmoRobot
     constructor;
   - the "trigger map not found" and "cube light animations not found" warnings were removed.

   No row covers this. Restore the previous behaviour.
7. **The mtime warning can appear twice** (Lights.cs:641/646). The cube loader re-walks the directory and emits
   "could not get mtime", which CollectAnimFiles' type-2 walk already emits (AnimationLibrary.cs:308, :466-467). The
   original walks once (callback 0x005241DE). Follow the backpack loader's precedent (`deferLoaderLogs`,
   Lights.cs:163-166): consume the type-2 list from the one walk.
