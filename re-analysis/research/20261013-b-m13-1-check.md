## Blocking

- **B1 (a regression): the final turn to the goal heading** (NativeLatticePlannerRuntime.cs:160-165).
  - **Natively,** lattice GetCompletePath, after AppendToPath, removes the trailing point turns and then **always
    appends one point turn to the exact goal heading** when the path is not empty (0x004FFC9A..0x004FFDC4: ±2 by sign,
    accel 10, tolerance 0x3DB2xxxx).
  - **The stack** removes the turns but adds nothing. So a plan ending in a turn in place leaves the robot ≥ 22.5° off,
    and DriveToPose's IsSameAs (10°) gives FailedTraversingPath.
- **B2: SelectPlanner uses the closest goal** (NativePlannerSet.cs:36). It is SelectPlannerHelper(goals[
  ComputeClosestGoalPose(robotPose, goals)]) (0x0064AA18..0x0064AA48), not Goals[0].
- **B3: an empty kept prefix starts from the robot state** (NativeLatticePlannerRuntime.cs:92). If the kept prefix's
  action vector is empty, the start is the robot State_c (0x004FEEBC..0x004FEECA), not the closest-index endpoint.
- **B4: no cached path in Read** (NativePlannerSet.cs:15, 62-63). HandlePlanComplete builds a fresh local Path every
  call (0x00649F66), ignores GetCompletePath's return (0x00649F82), and tests the count byte. If GetCompletePath fails,
  the path is empty: EmptyPlan, then status 4. The stack reuses the previous drive's path.
- **B5: missing engine logs and events on the live lattice path:**
  - a. sEventF `robot.lattice_planner_success` / `robot.lattice_planner_failure`: $data is the elapsed ms, the text is
    "%d:%d" (expansions:considerations) (0x00500112/0x0050011C, call 0x005001CC);
  - b. DoPlanning's Debug "old plan" (0x00500504) and "new plan" (0x0050055A), plus PrintPlan;
  - c. StartPlanning's Info "Unnamed" "LatticePlanner" "currentRobotState: <State_c>" (0x004FED4C..0x004FEE3C);
  - d. Info Planner `LatticePlanner.GetPlan.OldPlanUnsafe` "old plan unsafe! Will replan, starting from %zu, keeping
    %zu actions from oldPlan." (0x004FED00..0x004FED26);
  - e. the Warnings `LatticePlanner.ComputePath.AlreadyRunning` "Tried to compute a new path, but the planner is already
    running! (timeToPlan %d, running %d)" (0x004FE720) and `…PreviousPlanRequested` (0x004FE6CA);
  - f. Info Planner `LatticePlanner.GetCompletePath.Offset` "Robot is %f from the plan, at index %d" (0x004FFBF2), and
    the Debug at 0x004FFC42;
  - g. RestartPlannerIfNeeded's logs: Info `PathComponent.RestartIfNeeded.Error.Fallback` (0x00649C64), Debug
    `PathComponent.Replan.Running` (0x00649C9E), Info `…Error.NoFallback` (0x00649CE0). (The new branch bypassed the old
    MISSING.)
