## Consequences and limits

`UpdateAllResults` loops over FIFO mailbox results. For each, `UpdateOverheadEdges` walks that result's edge-frame list: 00655400 loads list head, 0065540A passes node+8, 0065540E gets Robot+25C, and 00655412 calls ProcessVisionOverheadEdges. Only after selected handlers does 006549AA publish that result's timestamp. All edge frames in that result therefore see the pre-tail E8; after the tail, the next dequeued result sees this result's timestamp. An empty mailbox does not advance it. P9 checked producer failure branches skip the result push, so receipt/attempted processing alone does not imply advancement. A handler error is different: the consumer records the failure but continues to its timestamp/broadcast tail.

The type-1 clear polygons and type-9 segments retain their own **OverheadEdgeFrame timestamp** under row 60; only the type-10 border call uses the getter.
