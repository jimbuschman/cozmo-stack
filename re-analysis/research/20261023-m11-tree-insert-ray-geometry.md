## Reused exact numeric contract

These are the contracts of the cited **existing checked rows**, provided together so their precision/strictness is unambiguous. They are not newly inferred C# behavior. Let F be one separately rounded f32 result, D one f64 result; no reassociation or fused multiply-add is implied. Epsilon e is f32 bits `0x3727C5AC`, negative e `0xB727C5AC`. Branch conditions below refer to finite ordered operands unless otherwise stated; retain Q's explicit unordered behavior too.

**FastPolygon, Q row 1b / §1:** Copy the supplied vertices, preserving order. For four corners there are four cyclic segments; FastPolygon does not repair winding or sort them. Any upstream quad import/sort is a separate step (QC omitted fact 5), not a constructor operation. For each edge, dx=F(next.x−x), dy=F(next.y−y); len=sqrt32(F(F(dx*dx)+F(dy*dy))), inv=F(1/len); normal=(-F(inv*dy), F(inv*dx)), with VNMUL for the negative product. VSQRT's NaN result takes imported sqrtf. No duplicate-edge/zero-length normalisation guard; fewer than two vertices produces no edges/normals.

Centre uses inv=F(1/F(uint32(n))), then each component accumulates F(old+F(inv*vertex.component)) in vertex order from +0. It is **not** sum then divide. Empty centroid is zero. Bounds use four separate scans: minima start at largest finite f32, maxima at negative largest finite; MI updates min, GT updates max, so NaNs do not update them. Node bounds are cached separately; QC omitted fact 2 describes ResetBoundingBox.

For n≥3, vertex-centre differences are f32; outer squared distance is F(D(dx)*D(dx)+D(dy)*D(dy)), with the two squares and sum in f64 and one final narrowing. Outer maximum updates on MI. Inner dot=F(F(nx*F(cx−vx))+F(ny*F(cy−vy))); inner squared distance F(dot*dot), minimum updates on GT. The final error diagnostic branches only for ordered inner>outer, despite its “>=” text. For n=1/2, inner=0; outer is the same mixed-precision squared distance from vertex0 to vertex0/vertex1: for two points it is the **full segment length squared**. n=0 reaches an undefined vertex read in ComputeCircles, not a valid empty FastPolygon contract (Q §1, 0x00841A8A..0x00841A9C; M1-034). Empty-vector behavior of node Contains/overlap does not make construction safe.

**Node Contains, V row 1.5 + N Q1–Q6; overlap Q row 1a:** Visit stored points in order, compare x to F(xmin−e), F(xmax+e), then y to F(ymin−e), F(ymax+e). Finite equality is inside. HI/LT rejection (node Contains) and the overlap routine's corresponding HI/LT/LS/GE decisions reject NaN coordinates. Every bound expansion is f32; there is no f64 geometry here. Node Contains returns false at first outside vertex, true on exhaustion, including empty input.

Overlap tracks allInside and anyInside. Both inside and outside seen →1 immediately; all inside →3 (empty vector also 3); none inside with n<2 →0. Otherwise node diagonal0 then diagonal1, and for each all polygon edges in stored order; any IntersectsWith →1. Neither diagonal intersects → Contains(minimum corner) ? 2 : 0. The diagonals are (xmin,ymin)→(xmax,ymax), (xmax,ymin)→(xmin,ymax), not the four rectangle sides. Segments come from the cached node bounds (Q §1, 0x006868CC..0x00686912).

**FastPolygon.Contains, Q row 1b / §1:** Reject for xmin>x (GT), xmax<x (MI), ymin>y (GT), ymax<y (MI), no epsilon; equality passes. dx/dy subtract in f32; r²=F(F(dy*dy)+F(dx*dx)), all f32. Strict r²>outer rejects (GT), strict r²<inner accepts (MI). Otherwise visit stored normals: dot=F(F(nx*F(x−vx))+F(ny*F(y−vy))); continue on LE against zero, else false. Thus finite equality passes; unordered dots also continue on ARM LE. Bounds/circle GT/MI do not reject unordered values. Clockwise convex interior has nonpositive dot, but circle shortcuts happen first. Exhausted normals returns true. Do not replace this with a winding-number test or claim it universally rejects every non-clockwise/degenerate input.

**Segment construction/intersection, Q row 1c / §1:** Endpoints copied; constructor obtains xmin/xmax/ymin/ymax through fminf/fmaxf, stores dx=F(bx−ax), dy=F(by−ay). Orientation t=F(F(segment.dy*F(px−ax))−F(segment.dx*F(py−ay))), all f32. Code negates negative t on MI to form abs, retaining original comparison with −e. abs(t)<e is strictly MI →class0; otherwise original t≥−e GE →class1; otherwise class2. NaN →class2. Exactly ±e is **not** collinear. For orientation0, unexpanded inclusive endpoint bounds must also pass (unordered rejected via HI/LT/GE).

Order: B.a against A, on-segment success →true; B.b against A, same; equal first two classes →false; A.a against B, on-segment success →true; A.b against B, same; finally whether latter classes differ. This is the actual early-return algorithm. At the overlap call A is the **polygon edge**, B the node diagonal (`0x00688344: mov r0,r7`; `0x00688346: mov r1,r6`; `0x00688348: blx #0x4bd080`). Swapping receiver/argument is not justified by mathematical symmetry when retaining exact floating arithmetic and early returns.

**Ray, Q row 6a / §6:** Eleven pairs, nonzero bool includes 1<<enum, OR all included bits. The endpoints are copied as two points, no equality rejection or endpoint extension. Construct their FastPolygon with the same arithmetic above (including two opposing edges). Recursive node type is tested before geometry: unselected childless node false immediately; otherwise overlap computed; selected node returns overlap!=0, including selected internal Unknown/type0; unselected overlapping node recurses children in stored index order, returns at first true. No check against an original object footprint is inserted at the leaf. The result is cell overlap. Equal endpoints still take degenerate FastPolygon/segment arithmetic; do not invent a zero-length ray early return.
