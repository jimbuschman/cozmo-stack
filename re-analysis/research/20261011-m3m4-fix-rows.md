libDAS.so rows are authority 2. The manager re-read the M3-021 strings (0x6B9E2C, 0x6B9E50, 0x657EA8) and Camera.cs.
The manager's rulings are in section 12. The job is `jobs/B-M3M4-3.md`.

## Logger signatures

- `sChanneledInfoF(channel, key, kv, fmt, ...)` and `sChanneledDebugF(...)` take a channel. `sWarningF(key, kv, fmt,
  ...)`, `sErrorF(...)` and `sEventF(name, kv, fmt, ...)` do not.
- "kv empty" means the key/value pair vector built on the stack is empty.
- "errG/break" means this tail: `strb #1` to `_errG`, then `sDebugBreakOnError()` if `_errBreakOnError` is set.
- How these reach the log is in section 7.

## 10. M3-028: UnhandledReadForWriteErase is unreachable

**The row:**
1. After the header passes, +0x79 := 1.
2. If +0x48 != 0: sWarningF, key "NVStorageComponent.HandleNVOpResult.UnhandledReadForWriteErase", fmt "", no errG. The
   re-request is skipped (0x006437F4..0x0064383E).

**Why it can't be reached:**
1. The header gate needs +0x78 != 0 (0x006430C8..0x006430CE).
2. +0x78 is set only by the READ dispatch (strh #1 at 0x00645422), which is followed by SetState(2) (0x00645474).
3. ProcessRequest's only caller is Update, and only when state == 0 (0x006456BC..0x006456CC).
4. SetState(0) clears +0x48, +0x1C and +0x78 (0x00642B52..0x00642B5C).
5. +0x48 is written to 1 only at 0x0064596E, in Update's state-1 branch. State 1 is entered only from state 0
   (0x00645320).
6. Every other writer stores 0: 0x0064288C, 0x00643074, 0x006432E2, 0x00642B56, and 0x0064529E (r6 = 0 from
   0x00645262).

So +0x48 is 0 whenever a read is pending.

## 11. M3-043: the vector overload Write(tag, vector const*, ...) at 0x006443F4 is dead code

- **A null vector pointer:** sChanneledInfoF, channel "NVStorage", key "NVStorageComponent.Write.NullData", fmt "%s",
  arg EnumToString(tag), then return 0 (0x00644400..0x00644486).
