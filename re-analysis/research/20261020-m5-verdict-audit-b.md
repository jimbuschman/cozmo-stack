2. PARAMETERS preview/question suggests a 44–45 **second** blink interval (`M5Hw.cs:82,538`). This is not the source's timing rule. Native 0x0058D382..0x0058D38C subtracts 0x3C from both timers once per KeepFaceAlive call; 0x0058D48C..0x0058D4BE generates a blink when its counter is <=0; 0x0058D4D0..0x0058D550 draws/stores the new parameter range. Wall clock and firmware display are not measured by those instructions. The human answer already does NOT gate `Blinks` and must remain observation only. The current prompt needs to say there is no source-established wall-clock target. M5-028 is EXACT_SOURCE and explicitly cites 0x0058D374..0x0058D558; M5-062 is EXACT_SOURCE and cites 0x0057E860..0x0057E90E.
3. SLEEP's positive result means the **stack fallback** and its diagnostic were captured, not that the native factory/compound runtime was reproduced. Native 0x0052CE54..0x0052CE6A calls the factory then queues position0/retries0; factory 0x0052CEA2..0x0052CFC0 constructs actual compound children. The `GoToSleepRequested` event and `MISSING: M5-038 -> M8` text are local gap instrumentation (M1-045 unresolved explicitly says no native app-message producer invented). Keep the observation visible; it cannot be an engine-behavior PASS. No exact sleeping appearance is sourced.
4. AUDIO's current Records list lacks M2-008/M2-009, which actually own 745-byte AudioSample / 1-byte AudioSilence union framing. Both are EXACT_SOURCE; M2-008 title `Outbound union: tag byte first, then the member; size = 1 + member; typed constructors write the tag`; M2-009 title `Outbound layouts and sizes of the 42 engine-to-robot messages this stack sends`.
