## What “before Init” actually means

Manager ctor stores initialized byte0 and initializes an empty ordered trigger tree at+40 (root+44/size+48 zero, begin points to sentinel). InitConfiguration sets the initialized byte1 at its tail but **does not populate that trigger tree**. It selects activity, conditionally subscribes event handlers and calls the retained audio Init. Trigger strategies are loaded by the following, separately named InitReactionTriggerMap.

The full DisableReactionsWithLock routine has no test of manager+0. It iterates the trigger map from begin+40 to sentinel+44; immediately empty returns at005A2824→005A2964. Consequently, a lock taken just after construction, or after InitConfiguration but before reaction mappings, is **not saved for later**. There is no pending per-manager table of lock names to replay. Conversely the function can operate on any existing trigger entry while initialized byte is0; initialized status is not its gate.

For mask-enabled existing entries, its ordinary per-trigger disable/add/optional stop actions run. Existing lock set emptiness controls strategy disable calls (005A2896..005A28B8); absent name gets AddDisableLockToTrigger(005A28C8). stop=true and matching active trigger leads to SwitchToBehaviorBase(005A292E). The supported SevereNeeds caller's stop=true and table/literal stay exactly as previously checked.
