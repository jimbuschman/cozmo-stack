## Adopted correction boundary

- M5/M3M4/Control wait for delivered engine readiness before connecting. The
  existing 60-second M1M2 wait limit is a host coverage budget, not native timing.
  Known cancellation/startup failure prevents connect, even if ready is also set.
- Capture engine logs through BeforeStart and finalize the startup report before
  disposal, including early exits. Window labels do not claim host-constructor
  coverage before the callback. List actual startup error text separately from
  harness exceptions; arbitrary error severity is not a new behavioral oracle.
- Invalid setup stops before check actions and observation prompts and still
  saves the bundle. M5 requires its cached neutral clip's first face for this
  test's setup. No new visual expectation is imposed on firmware.
- Preserve any captured contradictions; do not overwrite a negative verdict
  merely to mark setup incomplete. Hash the shared helper and validate startup
  fidelity IDs in all three bundle paths.
- ControlCheck's optional synchronous animation load remains before connect,
  after the readiness wait. This preserves its explicit resource selection and
  removes overlap with the engine loader. It was not demonstrated to suffer the
  same neutral miss as M5; its correction is to the host policy/order.
