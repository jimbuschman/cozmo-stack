## Open questions

1. Oracle or transcription: Detect runs under the emulator with the structures above. Whether the build uses it as the oracle (a corpus over images, H and rect positions) is for the manager.
2. Status input (row 5): the engine reads RobotState.status of the frame (LIFT_IN_POS, IS_CARRYING_BLOCK). The stack Detect has no such input; the manager decides where it comes from.
3. Return 1 (row 9, pose-tree failure) drops the whole vision result of the frame (row 2). It needs lift and camera poses without a common root; the manager decides whether our system can produce it.
4. FilterEngine border fill (row 16) and the fillConvexPoly rasteriser (row 18) are unread in the binary; the emulator executes them. Without an oracle both need reading.
5. Project3dPoint polynomial (row 9) is outside this scope (lift-gate owner).
