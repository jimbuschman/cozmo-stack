Two instruction-derived consequences matter. First, initial minima zero suppress an otherwise all-positive initial window until a reset installs infinity. Second, maxima start at zero and every reset restores zero; extrema update only raises them. A continuously negative filtered gyro therefore cannot meet the matching-negative-sign/max-magnitude test. There is no minimum count check in the drift detector. Bias counts wrap in u32 storage but the evaluation branch interprets the count as signed. ## Yaw dependency and numeric order

Both drift yaw reads use the outlined Robot::GetPose accessor (`0x004EA398..0x004EA46E`) then const GetTransform (`0x0084499A..0x0084499C`, load pose `+4`). GetPose returns Robot's pose at `+0x298`; it does not silently replace it with a packet yaw or a newly transformed pose. Its two invariant checks can call `sVerifyFailedReturnFalse` and then still return that pose: root-ID mismatch at `0x004EA3E8`, key `Robot.GetPose.BadPoseRootOrWorldOriginID`, format `VERIFY(%s): WorldOriginID:%d(%s), RootID:%d`, condition text `_pose.GetRootID() == GetWorldOriginID()`; root mismatch at `0x004EA44A`, key `Robot.GetPose.PoseOriginNotWorldOrigin`, format `VERIFY(%s): WorldOrigin: %s, Pose: %s`, condition text `_pose.HasSameRootAs(GetWorldOrigin())`. These common pose diagnostics retain the pose-layer owner and logging contract; they are not new gyro report messages.

`Rotation3d::GetAngleAroundZaxis` is `0x0084AA1C..0x0084AAB8`. For the four successive f64 components `q0,q1,q2,q3` read at offsets 0,8,16,24, its exact dependency order is:

1. f64 products: `b=q1*q1`, `d=q3*q3`, `c=q2*q2`, `u=q3*q0`, `v=q1*q2`.
2. f64 sums `p=b+d`, `r=c+d`, difference `s=v-u`, sum `t=v+u`; double `r`, double `p`, double `s`; subtract doubled p from f64 1; double t; subtract doubled r from f64 1.
3. Convert the four values separately to f32: `a=2*s`, `b'=1-2*p`, `c'=2*t`, `d'=1-2*r`. Products/sums above occur before those conversions, with separate instruction rounding.
4. Compute f32 `n1=a*a+b'*b'` and `n2=c'*c'+d'*d'`. If ordered `n2>n1`, call `atan2f(c',d')`; otherwise (including equality or unordered) flip the sign bit of a and call `atan2f(-a,b')`.
5. Construct a Radians from that f32 result, enabling native rescale.

This is not interchangeable with a single textbook yaw expression. Radians assignment copies both value and flag (`0x0084C856..0x0084C85E`). Subtraction (`0x0084CA18..0x0084CA32`) subtracts the two stored f32 values, sets flag 1 and invokes rescale. For finite yaw/difference here, the rescale body (`0x0084C87C..0x0084C936`) preserves `(-pi,pi]`, with f32 pi `0x40490FDB`, negative pi `0xC0490FDB`, and ±2pi `0x40C90FDB/0xC0C90FDB`. For magnitude <10 it repeatedly adds 2pi at/below -pi or subtracts 2pi above pi. The >=10 or unordered path uses f32 divide by 2pi, add -0.5, `ceilf`, ARM f32→s32 conversion, s32→f32 conversion, multiply by 2pi, subtract from original. Preserve these instructions and existing shared Radians semantics for exceptional values; do not substitute `%`.

The detector's comparisons use the ARM unordered flags directly. In particular, drift's two `bgt` rejections and bias's high-pass `bgt` permit unordered values to continue; drift's final `ble` and bias's threshold `ble` reject unordered. Bias min/max updates use `mi`/inverse `pl` selection, also preserving old extrema on unordered comparisons. No fast-math reassociation or fused operations are supported by this evidence. ADP-1 does not apply to this non-audio arithmetic.
