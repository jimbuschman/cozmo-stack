## Analysis: teardown flow

**At engine/robot teardown:**

1. Each signal hash table (keyed by message type ID, value `Signal<...>`) is destroyed via `~__hash_table` → `__deallocate` (0x0066349A) → bucket destructor `FUN_006634B8` (0x006634B8).

2. `FUN_006634B8` walks each bucket's circular subscriber list. For each node it calls `FUN_006634F4` (unlink):
   - If the node is "self-owned" (`param_1+8 == param_1[6]`): calls `release` (vtable+0x10) on the callable.
   - Otherwise, if callable != null: calls `unlink` (vtable+0x14) on the callable.
   - Nulls the callable (`param_1[6] = 0`).
   - Unlinks from the doubly-linked list.
   - Calls `FUN_0066352E` to decrement refcount at +0x20 and free at zero.

3. `FUN_0066352E` decrements the refcount at +0x20. If it reaches zero, it calls `release`/`unlink` on the callable (same self-owned test) and then `operator_delete` on the node.

**Signal dispatch (runtime, not teardown):**

`FUN_00663C74` (0x00663C74) iterates the circular list, incrementing each node's refcount before invoking its `std::function::operator()` (at +0x08) with the event, then decrementing. This prevents use-after-free during invocation. Caller: `FUN_00662590` (0x00662590), not individually disassembled.

**Destroy bodies:** The individual `release` (vtable+0x10) and `unlink` (vtable+0x14) methods for each ProtoHandle kind were NOT located. The vtables themselves were not found in the binary scan. Whether they are "mostly bx lr" as the unresolved field suggests is UNKNOWN.

**EngineToGame release (0x00664708):** Has 0 call sites. It is dead code (or called only via function pointer not visible to static scan). It does NOT detach a global missing sink before destruction in any reachable path.
