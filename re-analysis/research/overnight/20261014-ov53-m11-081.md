## Parameters and shipped inputs

SetExposureParameters receives target byte, percentile, max-change, subsample. It validates **max-change first**, against f32 bit patterns lower `0xB727C5AC` and upper `0x3F800054` (0x0085F378..0x0085F396), then percentile against the same bounds (0x0085F398..0x0085F3AE), then subsample>0 (0x0085F3B0..0x0085F3B4). Bounds include tolerance beyond [0,1], despite the log wording. No clamping is performed. Target is already uint8 and has no additional validation.

## Histogram fill, integer order

Reset calls __aeabi_memclr4(this,0x404), clearing bins and total at once (0x008731F0..0x008731FA). Fill methods **accumulate**, never implicitly reset. Bins/total use four-byte additions, no saturation or wider accumulator. Image rows/cols are +0xC/+0x10, data +0x14, row step `*[image+0x30]`, continuous bit `(byte[image+5]&0x40)!=0`. The byte image is traversed directly; no gamma application or color conversion is inserted.

Unweighted FillFromImage first checks signed subsample s>0. If invalid, log error `ImageBrightnessHistogram.FillFromImage.InvalidSubSample`, format `%d not > 0. Will use 1 instead.`, set errG/optional break, then continue using s=1 (0x00873208..0x0087325E); this is not an error return. For s==1 and continuous image, flatten dimensions to rows=1, cols=originalRows*originalCols. Otherwise keep original dimensions. The zero-row/column case performs no pixel loads. Sample y=0,s,2s,... <rows and x=0,s,2s,... <cols, row address data+y*rowStep. Optional transform callable, when present, maps pixel byte to bin byte; otherwise use raw byte. Increment bin by 1 (0x008732B0..0x00873306). At end compute signed integer `(s-1+rows)/s` and `(s-1+cols)/s`, using __aeabi_idiv, multiply the two and add to total (0x00873308..0x00873326). It does not increment total at each pixel. Return 0. For valid nonnegative dimensions this is ceil(rows/s)*ceil(cols/s). Preserve integer instruction order and normal image-dimension preconditions; negative/overflowed synthetic dimensions are not a license to invent a new defined native contract.

Weighted FillFromImage first compares original rows and cols of image/mask. Mismatch logs `ImageBrightnessHistogram.FillFromImage.InvalidWeightMaskSize`, format `Weight mask [%dx%d] not same size as image [%dx%d]`, sets errG/optional break and returns 1 **without modifying histogram** (0x008733F4..0x00873462). Only after that does it validate subsample, using event `ImageBrightnessHistogram.FillFromImage.InvalidSubSampleWithWeights` and the same corrective message/action, then s=1 (0x00873464..0x008734BA).

Flatten only when **both image and mask** are continuous and s==1 (0x008734BC..0x008734F4). Otherwise use original rows/cols and each image's own row step. Grid order is y outer, x inner. Read weight byte first; when zero skip image byte load, transform and both counts. For nonzero weight w, obtain raw/transformed image byte b, then `hist[b]+=w`, then `total+=w`, in that order (0x00873520..0x0087354A). A mask is not a Boolean inclusion test: weight 255 contributes 255. Sampling skips mask positions too. Return 0. No percentile/division occurs in either fill loop.

ComputeExposureAdjustment's callers supply an **empty transform function**, set by zero callable pointer before fill. Thus exposure uses raw sampled image bytes even though the generic histogram helper supports transformation. A pipeline gamma table does not silently change this path. Callback execution/ABI is a named std::function interface when another caller supplies it; the exposure path never enters it.

## Percentile, including boundaries

Read signed total T. If its bits are zero, sWarningF `ImageBrightnessHistogram.ComputePercentile.ZeroTotalCount`, `Returning 0 for p=%f because histogram is empty`, with p promoted f32->f64, and return 0 (0x0087362E..0x00873632, 0x00873694..0x008736DA). No error flag.

Otherwise initialize lo=+0f, replace with p only for ordered p>0 (`vmovgt` 0x00873646). Initialize bounded=1f and replace with lo only for ordered lo<1 (`vmovmi` 0x0087365C). Thus p<=0, -Inf and NaN yield +0; p>=1 and +Inf yield 1. Then convert **signed int32** T to f32, multiply bounded*T in f32, call system roundf, then `vcvt.s32.f32` truncates to signed int32 (0x0087364A..0x00873674). The usual roundf contract is nearest integer with halfway away from zero; the phone system library's body is not shipped here and is not claimed extracted. Do not replace it with ties-to-even MathF.Round's default. ARM conversion truncation occurs **after** roundf; it does not replace that rounding stage. For normal counts and p, all inputs to roundf are finite/nonnegative. Counts interpreted negative after overflow lead to nonpositive targets and return 0; signed cumulative comparisons and 32-bit add are retained below.

For target K<1 return 0. Otherwise start sum=0 and result=0. At loop head, truncate result to byte j; if j==255 return 255 **before reading bin 255**. Read hist[j], increment result, add bin to sum, then continue while signed sum<K (0x0087367C..0x00873692). Return incremented result, truncated to byte. Thus the first qualifying bin j<255 returns j+1, not j. If qualification would require bin255, return255 without adding it. No interpolation between bins. Small p with roundf(p*T)==0 returns0 even for nonempty histogram.

Derived examples (not executed tests): all samples bin0, K>=1 ->1; all bin100 ->101; all bin254 ->255; all bin255 ->255; T=1,p=.5 ->roundf(.5)=1, then one-past-bin result; p=0 or NaN ->0. These follow the cited instruction order and are intended to catch a conventional quantile implementation.

## All three exposure overloads

Image+mask overload (0x0085F748): initialize output factor to exactly 1f, construct empty transform, reset histogram. Check mask emptiness via data pointer, then total element count (rows*cols for dims<3, product of sizes for higher dims). Empty mask takes unweighted fill; nonempty takes weighted fill. Copy/release the empty callable around fill as required by its value ABI. On nonzero fill result, emit error `ImagingPipeline.ComputeNewExposure.FillHistogramFailed` with empty format, errG/optional break, return the fill result retained in r7; factor remains1. On successful fill but total==0, warning `ImagingPipeline.ComputeNewExposure.EmptyHistogram`, empty format, return1 with factor1. Otherwise call ComputePercentile(midPercentile).

For returned byte b==0, set factor=maxChange+1f and return0 (0x0085F8DA..0x0085F8E8). For b!=0, convert b and target mid-value **unsigned** to f32 (both bytes exactly representable), divide `ratio=target/b` in f32, and store ratio to output first. Load maxChange c, calculate lower=`1f-c`, upper=`c+1f` separately in f32. Replace lower with ratio only if ordered ratio>lower (`vmovgt`), then replace upper with that lower only if ordered lower<upper (`vmovmi`). Store resulting upper and return0 (0x0085F856..0x0085F89C). Normal finite c gives the usual bounded factor with inclusive boundaries. If c is NaN accepted by setter, both bounds are NaN and final output is NaN; no finite fallback. The byte ratio is finite here. The b==0 branch is intentional and does not divide by zero. No f64 calculation, fused operations, floor, integer exposure-time conversion or gain change occurs in these overloads.

Image-only overload (0x0085FA02) constructs an empty Image mask, invokes image+mask, preserves status, releases the temporary Mat's reference/storage, and returns status (0x0085FA10..0x0085FA7C). Cleanup has matching unwind paths (0x0085FA82..0x0085FAE0). It does not independently reset, compute or clamp.

Vector overload (0x0085FAE4) initializes factor1, then checks begin==end **before histogram reset**. Empty vector logs error `ImagingPipeline.ComputeNewExposure.EmptyImageVector`, `No image ROIs provided`, errG/optional break, returns1 and leaves the existing histogram intact (0x0085FAFE..0x0085FB14, 0x0085FC1A..0x0085FC6C). For nonempty vector reset once; iterate Image records in order with 0x40-byte stride. Empty image (null data or zero element count) warns `ImagingPipeline.ComputeNewExposure.EmptyImage`, `Skipping`, and continues (0x0085FB2A..0x0085FBBA). Each retained image calls **unweighted** FillFromImage with empty transform and configured s, accumulating all histograms without averaging per ROI or deduplicating overlapping pixels. On first failed fill, error `ImagingPipeline.ComputeNewExposure.ComputeHistogramFailed`, empty format, errG/optional break, exit with fill status (0x0085FBB0..0x0085FBB2, 0x0085FCEE..0x0085FD3E). Earlier histogram contributions remain; factor remains1.

After all images, total0 warns EmptyHistogram and returns1. Nonzero total computes the identical percentile/ratio/bounds as above (0x0085FBBC..0x0085FC18; b==0 at 0x0085FCAA..0x0085FCBA), returning0. Destruction and stack guard preserve selected status (0x0085FCBE..0x0085FCE6). No wire message is emitted by these methods; applying the factor to camera gain/time belongs to the separately checked M11-057 path.
