  A new record covers the ForceSetNeedsLevels handler.

## Manager rulings

1. **The FP mode** (FPSCR: FZ, DN, rounding) is **BLOCKED_EXTERNAL**.
   - **Why:** no shipped library writes FPSCR. The scan of every executable section of all 28 .so files found only
     libtbb restoring a captured value, and nothing imports fesetenv or its relatives. So the mode is the phone's
     kernel/runtime initial state, which the APK doesn't ship.
   - **The rows record the result for each mode:** under the shipped instructions, FZ changes flags and paths but none of
     the 19 measured result bits.
   - **No departure is taken here.** If a build must choose a mode, that's an operator decision then.
2. **The never-written inventory words 2..63:**
   - **The situation:** a robot with no stored inventory answers −1, a normal path, and the original still **sends**
     InventoryStatus, carrying 62 words its ctor never wrote. Word 1 (Sparks = 0) is defined, and it's the only word the
     app reads.
   - **The original loses no report,** so "skip the smallest unit the original would have lost" doesn't apply.
   - **The ruling:** apply the same treatment as the approved M2-017 (failed field reads hold 0). The stack sends the report
     with those words as **0**, logging that once visibly on the stack channel and naming this ruling.
   - **For the operator:** this is recorded as a manager ruling by analogy with M2-017. The operator can overrule it.
3. **ForceSetNeedsLevels and SetNeedsPauseStates** are app inputs. Their engine handlers are built exactly, and the stack
   API decides whether to expose them (the app-boundary rule).

## M15-030: needs exceptional values

- **Confirmed:**
  - **F1:** the Info `NeedsState.ApplyDecay` "Decaying need index %d with elapsed time of %f seconds".
  - **F2:** the match scan. A missing NeedId **inserts 0.0f** (emplace).
  - **F3:** remaining = elapsed/60.0f (BLE, also taken on unordered).
  - **F4:** rate·mult (BLS).
  - **F5/F6:** dist and time. If a later segment's eff ≤ 0, the candidate is the previously crossed threshold.
  - **F7:** the clamp; **the store at 0x0069C522** (0x0069C544 is a vmul); dirty; PossiblyDamageParts(Decay).
  - **The condition-code table** for unordered results.
  - **The sources:**
    - S1 copies raw words;
    - S2: modifiers at stride 16, pairs at stride 8. GetNeedLevel's missing key logs sErrorF "Need level does not exist in
      cur levels!", sets `_errG`, and returns 0.0f;
    - S3: the timer (/1e9, f64 then f32);
    - S4: the Update deadline (BLS) is advanced by the period with no reset, then LocalNotifications::Update(now), then a
      tail call to PossiblyWriteToDevice;
    - S5/S6: /100000.0f;
    - S7: the ForceSet clamp keeps NaN;
    - S10: a NaN bracket gives count−1;
    - S11: the InvalidNeedLevel warning;
    - S12: NaN counts every threshold.
- **The pause window** (ApplyDecayAllNeeds 0x00695D34..0x00695D86; Codex said there was no gate):
  - the +0x1DC byte skips the need;
  - if pauseEnd ≠ 0 (a NaN counts as ≠ 0) and now ≤ pauseEnd, or unordered, the need is skipped, and `last` isn't
    updated;
  - otherwise last += f32(pauseEnd − pauseStart), and both are zeroed.

  So **a NaN pauseEnd suppresses that need's decay permanently.**
- **The elapsed producer** (ApplyDecayForTimeSinceLastDeviceWrite 0x00695304..0x00695374):
  - elapsed = l2f((now_us − last_us)/1,000,000), truncated;
  - last[i] = f32(now − elapsed);
  - the pause times are shifted by −elapsed;
  - then ApplyDecayAllNeeds.

  A negative elapsed keeps the level and sets dirty.
- **Downstream:**
  - **SendNeedsStateToGame** copies the levels as raw bits (0x0069389E..0x006938AC), so a NaN payload goes out unchanged.
  - **Persistence** quantises with vcvt.s32(f32(level·100000)): it rounds toward zero, NaN becomes 0, and ±inf
    saturates (WriteToDevice 0x00693D86..0x00693D92, StartWriteToRobot 0x00695578..0x00695586). So a NaN level is saved
    as 0 and reads back as 0.0f.
- **Build rows (M15-030):**
  - the ApplyDecay exceptional branches 0x0069C41A..0x0069C54C, including the insert-on-missing at 0x0069C43E;
  - the bracket NaN 0x0069C1A6..0x0069C1FE;
  - the damage-count NaN 0x0069C62C..0x0069C640 and 0x0069CCC4..0x0069CCDC;
  - GetDecayMultipliers 0x0069C26C..0x0069C2A8;
  - the Update deadline 0x00695CBE..0x00695CC6;
  - the pause-window NaN branch 0x00695D34..0x00695D86 (M15-001 owns the window);
  - the persistence NaN → 0 and saturation (M15-014's ranges; this record owns the exceptional values);
  - the raw-bit game copy.
- **New BLOCKED_EXTERNAL:** the FPSCR mode (ruling 1).
- **Optional RECOVERABLE_GAP:** the config parsers' numeric acceptance (NeedsConfig::Init 0x0068E7C0..0x0068EE04,
  InitDecayRates 0x0068EE88..0x0068F10C, InitDecayModifiers 0x0068F10C..0x0068F5F4). The shipped values are all finite.

## The ForceSetNeedsLevels handler (new record)

At 0x00697DA4..0x00698002.

1. **The log first:** keys 0x006980EC/0x00698110, with three f64 arguments. The old map is copied for formatting.
2. **The clamp** (0x00697E6C..0x00697EBA): BLS keeps min; GE substitutes max; NaN is stored.
3. **dirty** mgr+0x90 = 1.
4. **SendNeedsStateToGame(NoAction).**
5. **The sEvent** `needs.force_set_needs_levels`, with the old/new string.

It reads 3 elements unconditionally. A count of 0 dereferences null (0x00697E78), and 1–2 read past the block. That's
M1-034. The app always sends 3.

## M15-034: ProgressionUnlockComponent's NV read callback

- **The slot is +0x18**, not +0x14 (0x0102F6D0 = 0x0064CE35).
- **The dispatch:** signed. −1 → defaults; any other negative → error.
- **The size:** 0x800. Padding happens only when aligned > len. Any length ≠ 2048 is an error.
- **A short input is a use-after-free:**
  - the Info `ProgressionUnlockComponent.ReadFewerUnlocks` "Padding unlock data due to size mismatch";
  - pad with zeros;
  - **delete at 0x0064CEEA, then Unpack reads it at 0x0064CF04.** That's M1-034.
- **The decode:** 512 ReadBytes(4), stopping at the first failure.
- **Replace:** reset the set, then copy in the global defaults set (M15-043 is the producer). Then accept the saved IDs
  where (id−1) ≤ 0x53 unsigned, then one SendUnlockStatus.
- **−1:**
  - the Info "UnlockComponent" `ReadGameUnlocks` "No unlock data found on robot unlocking defaults";
  - then the defaults;
  - then SendUnlockStatus;
  - then NotifyGameDefaultUnlocksSet. That has no guard: a null interface dereferences at 0x0064C114 (M1-034).
- **Errors:** "Read failed with %s" with NVStorage::EnumToString, and "Size mismatch expected %zu, got %zu". Both set
  `_errG`, keep the state, and send no report.
- **SendUnlockStatus** (gated by the external interface):
  - the Info "Sending current unlock status (%zu unlocked)";
  - UnlockStatus, tag 0x6D, with fromBackup = 0;
  - Pack writes a u8 count.
- **The shipped defaults** (22 IDs) are confirmed.

## M15-035: InventoryComponent's NV read callback

- **The slot is +0x18.**
- **The ctor:** new(0x130) with no memset. It writes +4 and +8 only; **words 2..63 are never written** (ruling 2).
- **Init order:** Progression Init, then Inventory Init. Read, then subscribe only with an interface, then caps for types
  0..1.
- **The Read:** the Info `InventoryComponent.ReadCurrentInventoryFromRobot` with an empty format, then Read(0x195000). On
  failure, the Info "…ReadFailed".
- **The callback:**
  - ready = 1 is set first;
  - **result ≥ 0:** Unpack with no length check (min(64, ⌊L/4⌋) words), then SendInventoryAllToGame;
  - **−1:** SendInventoryAllToGame, then (with an interface) RequestDefaultSparks (tag 0x70, empty, via
    Robot::Broadcast);
  - **any other negative:** the sErrorF `…ReadError`, `_errG`, break-on-error, and **still** SendInventoryAllToGame.
- **The sink:** gated by ready and the interface. InventoryStatus is tag 0x6F, 64 LE words with no prefix.
- **The starting Sparks** come from the app (COMPATIBILITY_POLICY input, Unity GiveStartingInventory).
