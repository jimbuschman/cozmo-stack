## The three key answers

1. **Does note-off envelope 381606890 stop a held sung voice?** It depends on the case.
   - **Case A, the usual case:** the vibrato LFO already owns the voice when the note-off holder is due on its first
     pump. The envelope then attaches with an infinite deadline, never completes, and holds at sustain 0.095 on the
     volume binding. The voice ends by the loop break, or by some other cause.
   - **Case B:** there's no owner, or the holder is pumped before it's due. The envelope then gets a finite deadline,
     completes (release is 0), and stop policy 1 stops the voice.
   - **Which case applies is still open,** pending four reads (recorded in a new record):
     - the state insertion that writes V+0x34 (0x009DD120..0x009DE688);
     - the caller of 9D9908;
     - whether an LFO completes on a deadline;
     - the parser's offset bound (M9-005).
   - **The manager accepts the conditional answer for now.** M9-024 keeps its effect as a disjunction.
2. **The vibrato's depth at note-on:**
   - if the game parameter was **never posted**, the depth is **+0** (A17280's no-entry branch skips the curve, and the
     entry default is 0, Init.bnk 0x459);
   - if it was **posted with g**, the depth is curve(g)/100, linear (0, 0) → (1, 100), clamped at the ends.
3. **Does the depth update live?** Yes.
   - **The chain:** an immediate write (0x00A12CCC..0x00A12CE4), then the subscriber snapshot, then type 3
     (0x00A11348..0x00A11360), then 9DBF78, then the visitor (0x009D5058..0x009D506C), then the LFO setter's index 0
     (0x009E2084..0x009E2090), then the per-tick capture of S+0x74 (0x009E2ED0/0x009E2EF0).
   - **The Perform order:** command drain (0x009AFA08), then phase-8 dispatch (0x009AFA48), then the modulator tick
     (0x009AFA8C).
   - **Still open:** whether a running vibrato state is in the tree, which again depends on the insertion. Ramped posts go
     through A0E5E4, which is unread.
