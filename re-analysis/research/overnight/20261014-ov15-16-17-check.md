## M11-058: an exception from the image decode

- **R1, failure vs throw:** a returned decode failure and a throw are different paths. Only the returned failure runs
  ImageCache::Reset, Toc, the Result return, and the caller's warnings (`DecodeFailed` 0x00652E90 or `UpdateFailed`
  0x00653D46).
  - Every imdecode call site in both helpers (Gray 0x004F287C, RGB 0x004F2184) is cleanup-only (action 0). There is no
    catch: a cv::Exception reaches `__cxa_begin_catch` then `std::terminate` (0x004E39F8).
- **R2, three entry routes:**
  - direct (calibration or dot test) 0x00652E6C;
  - synchronous 0x0065304C;
  - asynchronous (the Processor) 0x0065222E.
- **R3:** the effects that happen before the decode stay: the raw forward to the game, the +0xE4/+0xF0 timestamps, and
  VisionPoseData::Set (0x00652D52). No lock is held across any decode.
- **R4:** nothing is rolled back, and there is no Processor completion (0x00652238..0x0065224C).
- **R5, the M1-034 standing rule:** the original terminates. The stack skips the frame and logs it visibly, naming
  M1-034 and M11-058, on all three routes, including the worker thread.
  - **Manager decision:** the skip leaves the profiler as it was after `Tic("DecodeJPEG")`, with no Toc.
- **Also read:** `EncodedImage::Save` (0x004F2EEC) has no caller, so it is unreachable. The timestamp-regression,
  WasRotatingTooFast and paused paths belong to M11-040 and are not exception paths.

## M11-059: VisionComponent::Init and VisionSystem::Init

- **C1–C5, VisionComponent::Init:**
  - **The four reads:**

    | Key | Type | Destination |
    | --- | --- | --- |
    | — | u32 | 0x0105104C |
    | "RepeatedErrorMessageInverval_ms" | u32 | 0x01051050 |
    | — | u16 | 0x01051054 |
    | — | f32 | a local starting at −1.0f |

    The compiled defaults are 3000, 5000 and 16.
  - **A missing key:** Error `VisionSystem.Init.MissingJsonParameter` "%s", then `_errG`, break-on-error, and return 1.
  - **A nonzero system Init result:** Error `VisionComponent.Init.VisionSystemInitFailed` (empty format), returning the
    same Result.
  - **C5:** `vcvt.u32.f32` clamps a negative or NaN value to 0 and saturates at 2^32−1. Store +0x10 = 1 before +0x9C.
- **A1–A7, the face album:**
  - **The robot branch:** an empty FaceAlbum, or exactly "robot".
  - **Any other value takes the file branch:** EraseAllFaces (lock, erase, unlock, save, then broadcast erase), then
    LoadFaceAlbum, then BroadcastLoadedNamesAndIDs **before** the Result is tested.
  - **The replay** sends **one** erase (0x0065159C) before the loop (0x006515B8..0x00651630). Each entry logs Info on
    channel "VisionComponent" with its id.
  - **LoadFaceAlbumFromRobot:**
    - the first read (0x184000) has an empty std::function;
    - the second (0x183000) runs only if the first returned true;
    - an Info on channel "Unnamed", key `VisionComponent.LoadFaceAlbumToRobot.Initiated`, is always logged.
- **S1–S10, VisionSystem::Init:**
  1. clear +0x338, +0x58 and +0x328;
  2. read config/engine/vision with scope 1 (NullDataPlatform is a Warning);
  3. the nine ImageQuality reads;
  4. **the profiler keys are `PerformanceLogging.TimeBetweenProfilerInfoPrints_sec` and
     `TimeBetweenProfilerDasLogs_sec`** (corrects OV16), each with a missing-key Error;
  5. SetAutoExposureParams, whose failure Result is kept;
  6. FaceTracker (4 bytes), MotionDetector (0x98 bytes), and PetTracker::Init (its failure Result is kept);
  7. InitialVisionModes: getMemberNames, then GetModeFromString, then asBool, then EnableMode;
  8. InitialModeSchedules over modes 0..15: an array, else an int, else a bool, else Error
     `UnrecognizedModeScheduleValue`. Each is push_front'ed onto +0xC8;
  9. CLAHE with clip limit 32.0 and (4,4). This is a **handoff to M11-021**, which already transcribes CLAHE_Impl;
  10. store 4/32 into +0x350/+0x354, then +0x58 = 1.
- **SetExposureParameters** (0x0085F374..0x0085F4AA) and **SetAutoExposureParams** (0x006B1858..0x006B18DC) are now
  read.
  - The checks run in this order: max-change, then mid-percentile, then subSample.
  - The bounds are 0xB727C5AC and 0x3F800054, with `bmi`/`bgt`, so NaN passes.
  - subSample ≤ 0 is rejected.
  - Failure returns 0x03000000.
  - The Info format is "subSample:%d midVal:%d midPerc:%.3f changeFrac:%.3f".
  - These come off M11-081's unread list.
- **The FaceTracker::Impl ctor:**
  - an Init failure logs Error `FaceTrackerImpl.Constructor.InitFailed`, and the object is still returned;
  - the model-path argument is never used.
- **PetTracker::Init:**
  - its key table is a `map<const char*,int>` ordered by pointer;
  - SetLostParam and SteadinessParam each pass the same value twice;
  - success sets +0x40 = 1.
- **VisionModeSchedule:**
  - the int ctor builds vector<bool>(n, false); n ≠ 0 sets bit 0, and n = 0 does push_back(false);
  - CheckTimeToProcessAndAdvance reads `[data + (c>>5)*4]`, which is a null read on an empty array (0x006AF21A). That
    is an M1-034 case owned by M11-034, and unreachable with the shipped config.
- **IsInitialized** is `ldrb [r0,#0x58]`.
- **N1, new: the Robot-ctor gate.** Robot::Robot calls VisionComponent::Init only when the data platform ([ctx]+8) is
  non-null (0x005103BC).
  - The config is [ctx+0x1C]+0x118.
  - **Init's Result is ignored.**
  - ReadAllBackupDataFromRobot follows (0x005103D4).
- **N2, new: the config source.** RobotDataLoader::LoadRobotConfigs reads `config/engine/vision_config.json` through
  readAsJson(scope 1) (0x0052267C).
  - Its failure branch (0x00522680..) is unread.
  - Under the app boundary, the data platform is an app input that the stack supplies (COMPATIBILITY_POLICY input).
- **Handoffs (named, not deferred silently):**
  - **(a) the OMCV_PD_\* return values,** which decide whether Init succeeds: M11-016 (the later OKAO layer). Until then
    the stack's seam result is a visible MISSING;
  - **(b) the FaceTracker internals:** M14-010 / M11-016;
  - **(c) FaceRecognizer::LoadAlbum,** the file branch, dormant with the shipped config: M14-011;
  - **(d) the empty-schedule null read:** M11-034;
  - **(e) the JsonCpp getMemberNames order,** and LoadRobotConfigs' failure branch: a new RECOVERABLE_GAP record.

## M11-060: the pending camera params

- **B1:** pending (+0xA0/+0xA4/+0xA8) is separate from current (+0x98/+0x9C).
- **B2:** the apply happens only on a successful decode and a ready system (+0x58 and the calibration). It comes after the
  frame counter, UpdatePoseData, the mode drain and the schedule drain, and before ApplyCLAHE and the mode dispatch. It
  doesn't depend on any mode bit.
- **B3:** copy both words bit for bit and clear the flag. The payload stays in place, with no validation, narrowing, log
  or message (0x006B50C8..0x006B50D8).
- **B4:** an earlier failure leaves the request pending, and a later failure doesn't roll it back.
- **B5, the producer** (0x006B229C):
  - it warns only when pending is already set, with (old e, old g as f64, new e, new g as f64);
  - then it stores the gain (+0xA8), the exposure (+0xA4) and pending = 1, in that order.
- **No lock (manager decision):** the native producer (the engine thread) and consumer (the vision thread) share
  +0xA0..+0xA8 with no lock or barrier. The stack follows the original: no lock. Its B-M3M4-10 critical section is
  removed. M3-021's B-M3M4-12 suppression of OverwritingPreviousParams is retired when this is built.
