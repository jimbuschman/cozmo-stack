# Opus check of OV42, OV43 and OV44 (M11-074, M11-075, M2-022), 2026-10-15

- **Checked:** `research/overnight/20261014-ov42-map-producers.md`, `-ov43-map-broadcast.md` and `-ov44-m2-022.md`
  (Codex), against libcozmoEngine.so and the Unity scripts. Read-only cozmo-extractor.
- **Adopted:** by the manager on 2026-10-15.
- **Result:** most rows hold. The corrections are mainly reachability findings the reports missed, plus some omissions.

## Manager decisions

1. **M11-075 moves to IMPLEMENTATION_GAP,** for the map aging per tick and the scheduler's early return. The memory-map
   stream to the game is **not reachable in the shipped app.**
   - **Why:** no Unity code sends SetMemoryMapBroadcastFrequency_sec (G2E 145), so the interval stays −1.0f and
     BroadcastMap returns on every tick. The debug Viz draw is dead code.
   - **The stack reproduces this exactly:** no stream. The setters' engine handlers are recorded.
   - **Operator question 1:** whether the stack API should expose the frequency setter. That's a policy input; the
     engine side would stay exact, including the infinite loop on a zero interval.
2. **M11-074 moves to IMPLEMENTATION_GAP,** for UpdateRobotPose, the object add/remove path (including the double Add)
   and ClearRobotToMarkers.
   - **Unreachable** (no reference anywhere in the binary): FlagInterestingEdgesAsUseless and ReviewInterestingEdges.
   - **New RECOVERABLE_GAP records:**
     - each concrete class's ObservableObject +0x5C/+0x50 overrides;
     - AIWhiteboard::ProcessClearQuad and its render path.
   - **FindIf's result order isn't built yet.** It follows heap addresses (an unordered_set with a murmur2 hash), and
     extending the M11-047 departure to it is the operator's call (question 2). Whether its consumer (M13-003,
     0x004FDF1C..0x004FDF8C) is order-sensitive is unread.
3. **M2-022 stays RECOVERABLE_GAP,** with new rows for the queue-clear path. No tag-0x60 E2G subscriber was found, and
   exhaustive proof needs type-resolved registrations.
4. **M8-024:** ActionWatcher callbacks **don't** fire inside ActionList::Clear. ActionEnding only pushes to a deque; the
   callbacks run only from ActionWatcher::Update (0x005418AE), called from ActionList::Update 0x0053F5E6. Local tag-0x5A
   subscribers **do** fire synchronously (0x0053FAB2). AbortAll (0x00511120) is still unread.
5. **Unreachable engine paths are recorded as unreachable and not built,** as for the SDK paths.

## OV43: M11-075, confirmed and resolved

- **The tick join:** MapComponent::Update runs after BlockFilter, CheckDisconnectedObjects and ConnectToRequestedObjects,
  and before DrawAllObjects and DrawMap (0x0051422A..0x0051424C). The early exits before it weren't re-read.
- **The ctor:** render byte +0x38 = 1; interval +0x3C = −1.0f; deadline +0x40 = 0; subscribes to G2E 0x90 and 0x91 only
  with an external interface (0x0067D9FE..0x0067DB48).
- **The setters** (resolved): tag 144 copies a byte to +0x38 (0x006807EA..0x006807F8). Tag 145 stores the raw f32 at
  +0x3C, then the timer at +0x40 (0x0068085E..0x006808A0).
- **Aging** (0x0067DC68..0x0067DD20):
  - an unknown origin or null map skips aging, but BroadcastMap still runs;
  - threshold = f32(now) − 30000 or − 120000, via `vcvt.u32`; forced to 0 when now < 30001 or < 120001;
  - a whole-map TransformContent.
- **The aging callback** (0x006808F4..0x00680962): type 8 uses 30000; types 9 and 10 use 120000. If last ≤ threshold, it
  becomes fresh type 0 with first = last = now.
- **BroadcastMap** (0x0067DDBC..0x0067DE32):
  - returns if the interval is < 0 or NaN (−0 passes);
  - returns if timer + 1e-5 < the deadline;
  - catch-up loop;
  - the deadline is stored before the lookup.
- **The stream** (0x00685810..0x00685904; leaves 0x00687B08..0x00687B7E): Begin 0x91, then chunks of up to 2046 entries,
  then End 0x93. Unreachable in the shipped app.
- **The sink** (resolved): Robot::Broadcast → UiMessageHandler::Broadcast 0x00662508 → a local synchronous emit
  0x00662590.
- **The debug Viz draw** (0x00685C18..0x00685C6C): dead. DrawMap is `bx lr` (0x0067EA5A), and nothing else references
  it.
- **M1-034,** on the unreachable path only: 0x0067DE2A, 0x00687B2A.

## OV42: M11-074, confirmed and corrected

- **R1–R6** (0x0067E23A..0x0067E486):
  - the gate, the 10/10/50 size, the corners and the cliff branch;
  - **the cliff byte's writer** is CliffSensorComponent+5, set from CliffEvent.detected (0x005356C6..0x005356D4);
  - the Robot quad insert, ProcessClearQuad, then the pose saved last.
- **O1–O8** (0x0067EA9A..0x0067F0BC): state routing and the BothStatesAreInvalid sErrorF; the cache; Add (the
  IsPoseTooHigh gate, the quad, the type, the insert, and FillBorderInternal(9, mask {3,4,5,6,7,10}, 10, ts)).
- **The caller order** (new; 0x00506F98..0x00506FB8, 0x00506296..0x005062D6):
  1. BlockWorld::OnObjectPoseChanged;
  2. UpdateObjectPose(old);
  3. BroadcastObjectPoseStateChanged, which calls UpdateObjectPose(current) again.

  So an Invalid → valid change runs Add twice.
- **D1–D3** (0x0067F4C4..0x0067F544, 0x0067F2DE..0x0067F368, 0x006810E0..0x00681172): the family table and the remove
  lambda. A charger's removal type 5 never matches.
- **C1–C5** (0x0067F5B8..0x0067F714): ClearRobotToMarkers; caller 0x00506A86..0x00506A98.
- **Q1–Q6** (0x00681674..0x006816DC, 0x006884FC..0x006886F4): FindContentIf/FindIf.
- **Virtual +0x5C:** the base returns 0; one ActiveObject slot returns 1; CustomObject returns byte +0x9C. Which class
  uses which isn't settled (new record).
- **M1-034 points on reachable paths:**
  - 0x0067E38C, 0x0067E3E4 and 0x0067E444 (a null map at an unknown origin);
  - 0x0067EF14 and 0x0067EFF6;
  - 0x0067F6D0;
  - 0x0067EC3C;
  - 0x0068878C (bad_function_call).

## OV44: M2-022, rows added

- **E2G Broadcast(&&):** DeliverToGame first, then a local synchronous emit (0x006625C6..0x006625FA).
- **ActionQueue::Clear:** **Cancel() on the current action first** (0x0053F97C), then DeleteActionAndIter for each
  (0x0053F970..0x0053F9AC).
- **DeleteActionAndIter** (0x0053F9E4..0x0053FB06):
  - a reentry guard on the tag set at queue+0x10: an insert that fails skips (0x0053FA12..0x0053FA1C);
  - INTERRUPTED (0x03000009) builds no RobotCompletedAction (0x0053FA42..0x0053FA50);
  - the order is PrepForCompletion, the message, delete, unlink, then Broadcast (0x0053FAB2).
- **Abort** loads the external interface without a null check (0x0057B3F8..0x0057B400).
- **Nested robot dispatch inside Clear:** neither shown nor excluded.

## Contradicted

**M11-046:** "the whole-map TransformContent … (caller FlagInterestingEdgesAsUseless, M11-074)". That function has no
caller. The real callers are the aging in MapComponent::Update (0x0067DCF4) and RemoveObservableObject (0x0067F368).

## Operator questions

1. Should the stack API expose SetMemoryMapBroadcastFrequency_sec? The shipped app never sends it, so the original
   never streams the memory map.
2. Should FindIf's result order follow insertion order, as M11-047 does for the border walk? The original's order
   follows heap addresses. This only matters if its consumer is order-sensitive, which is being read.
