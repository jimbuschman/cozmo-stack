not the complete object's first vptr. ActiveCube constructor 0x004E0CB0..0x004E0D40

(passive cubes/Block), and -104 (charger). All class mappings above use the named
ELF table plus its actual address point; passive construction call chains were not
exhaustively inventoried.

The Block quad thunk at 0x004E690C..1C receives result pointer r0, ObservableObject
this r1, pose r2, float pad bits r3. It loads signed adjustment `[vptr-58]`, adds it
to **r1**, and forwards to Block::GetBoundingQuadXY. Those adjustment words are
-128 for ActiveCube, -A4 for passive blocks. Treating r0 as this corrupts the result.

exactly 1, so a hypothetical stored byte 2 does not pass that test. Constructor

UNKNOWN, not assumed impossible.
