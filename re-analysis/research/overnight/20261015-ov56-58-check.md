# Opus check of OV56, OV57 and OV58 (M8-024, M11-083, M15-049), 2026-10-15

- **Checked:** `research/overnight/20261014-ov56-m8-024.md`, `-ov57-m11-083.md` and `20261015-ov58-m15-049.md` (Codex, a
  fresh fast context), against libcozmoEngine.so, libc++_shared.so and libDAS. Read-only cozmo-extractor. The binary
  hashes match the reports.
- **Adopted:** by the manager on 2026-10-15.
- **Result:**
  - **OV57** holds.
  - **OV56** is mostly right, but leaves out the gates that decide its own question.
  - **OV58** has one wrong row (the disable predicate) and one misleading label (the "platform ID").

## Manager decisions

1. **M8-024 is split.**
   - **The teardown mechanics move into M8-015's evidence,** since M8-015 owns the ActionList lifecycle and Robot
     teardown. Job B-M8-5 aligns the built code with them.
   - **M8-024 stays RECOVERABLE_GAP,** narrowed to the callback census and whether any action survives. Because of the
     Clear lock-out, the only question left is whether a survivor exists when Clear **starts**: nothing new can be added
     during Clear.
   - **M1-034 candidate:** StartActing during Clear double-deletes (0x0053DCFE, then 0x005BDC04). It's reachable only if
     an IBehavior outlives ~BehaviorManager/~BSM, which the census must settle.
2. **M11-083 moves to IMPLEMENTATION_GAP** for the to_string(float) %f path, rows F1–F7.
   - **F8 is unreachable for float input** (the proof is below). Its only callers are the two double callers, which are
     SDK-only.
   - **The rounding mode is M15-047** (BLOCKED_EXTERNAL; no departure). The stack uses IEEE round-to-nearest, the same as
     any phone in its default state. No shipped code changes it, so no operator question arises.
3. **M15-049 moves to IMPLEMENTATION_GAP** for the experiments loader and Enable(true).
   - **Unreachable:** Enable(false), and the disable/forced-assignment machinery. HandleABTestingForceURL has no caller.
   - **A new RECOVERABLE_GAP record:** AutoActivate's descendants and the audience-tag qualification.
   - **The Lab user ID is the DAS device ID,** a UUID from the app's Java DAS layer. It's an app input: the stack supplies
     it from a stack setting (COMPATIBILITY_POLICY), under the app-boundary rule.
   - **The app's `cozmo_activate_experiment`** (0x00666B84) isn't called by the stack. The stack replaces the app, and A/B
     experiments are Anki telemetry. So it's recorded as unreachable.
4. **The ric+0x24 question is answered:** it's mfgId word 0 (0x0052E30A), the first of three sequential words.

## OV56: M8-024 rows (teardown mechanics → M8-015)

- **~Robot's order:**
  1. the DAS event (0x005110EE);
  2. ForceUpdate (0x0051111A);
  3. AbortAll (0x00511120);
  4. ~BehaviorManager;
  5. ~BSM;
  6. ActionList::Clear (0x00511146);
  7. ~ActionList (0x00511156).
- **AbortAll** (0x00511952..0x0051198C):
  1. ActionList::Cancel(−1);
  2. PathComponent::Abort;
  3. AbortDocking (sends to the robot, 0x0063BE2A..0x0063BE36);
  4. SendAbortAnimation;
  5. StopAllMotors (0x00517DFE..0x00517E0A).

  It returns 1 if Path, Docking or Anim returned nonzero, and doesn't write any IBehavior flag. PathComponent::Abort's
  virtual call (0x00649152) and SetDriveToPoseStatus (0x00649188) are unread.
- **ActionList::Cancel** (0x0053DE18..0x0053DE54):
  - if +0xC is set (clearing), it returns 1 at once;
  - it walks the slots in key order, finding the successor **after** each Cancel.
- **ActionQueue::Cancel(type)** (0x0053E69A..0x0053E6FA): the current action gets Cancel, then Delete; pending actions
  are deleted without Cancel. It exits early when Delete doesn't return 1 (0x0053E6E4..0x0053E6E6).
- **QueueNow / QueueAtEnd** (0x0053E25A..0x0053E2F2, 0x0053E34E..0x0053E36E).
- **DeleteActionAndIter** (0x0053F9E4..0x0053FAB2):
  - a re-entrancy set at queue+0x10 (0x0053F9FE..0x0053FA1C);
  - destroy (0x0053FA78), unlink (0x0053FA86..0x0053FA9C), broadcast (0x0053FAB2);
  - no broadcast without an external interface, or for INTERRUPTED (0x0053FA3A..0x0053FA50).
- **The result codes:** the ctor sets NOT_STARTED 0x02000001 (0x0053FDBA..0x0053FDD4). Cancel() writes
  CANCELLED_WHILE_RUNNING 0x02000000, unless the action is NOT_STARTED (0x005409E2..0x00540A40).
- **The Clear lock-out** (Clear 0x0053D91A..0x0053D938):
  - IsDuplicateOrCurrentlyClearing (0x0053DCEA..0x0053DD00) calls PrepForCompletion, deletes the new action and returns 1.
    This is on the Now path (0x0053DCAA) and the IN_PARALLEL path (0x0053DF40);
  - ~ActionQueue → ActionQueue::Clear (0x0053F93C, 0x0053F970..0x0053F9AC);
  - ~ActionList calls Clear a second time (0x0053D8F6..0x0053D90E).
- **The IBehavior side:**
  - StartActing's reject paths delete the action (0x005BDC04);
  - Init clears the callback and A1 on failure (0x005BCCC6..0x005BCD06);
  - the flags (0x005BBCCE/0x005BBCD2, 0x005BCCCA, 0x005BCF80..0x005BCFA8, 0x005BD10C/0x005BD126);
  - HandleActionComplete (0x005BE1EC..0x005BE224) and StartActing (0x005BDAD4..0x005BDB72).
- **For the census (M8-024):**
  - **ExploreLookAround's chain** (0x005E2932..0x005E2CD2). Its RNG draws happen during teardown.
  - **RemoveRobot's virtual call** at 0x0052F2AC comes before the broadcast. Its recipients are unread.
  - **A lambda that reads its captures after a nested StartActing** reassigns +0x88 while the old target is still running
    (0x005BE220, 0x005BDB46). That has to be checked in the census.

## OV57: M11-083 (F1–F7)

- **The libc++ entry** (0x0006651A..0x00066580): resize(10); `vcvt.f64.f32`; "%f"; the grow-and-retry.
- **vsnprintf** (0x00082550..0x000825A6).
- **Sign, NaN and inf** (0x000815BC..0x000816EA).
- **The fraction setup** (0x000816F4..0x00081712).
- **The limbs:** p/9 + 2 (0x0008199C..0x00081A2A).
- **j = p for %f** (0x00081A66..0x00081A96).
- **Rounding:** 2^53 + 2 for odd, 2^53 for even (literals 0x000824D0/0x000824D8; 0x000821B8).
- **The callers:** 20 float and 2 double direct calls.
- **F8, the carry loop with no guard** (0x000821DC..0x000821FA), **can't happen for float:**
  - a float with any fraction is < 2^24, so the top limb holds the integer part and can't carry;
  - a float with e2 ≥ 0 is an integer, so the rounding branch is skipped.

  Only the double callers 0x0065E39E and 0x0065E548 (SDK) could reach it.

## OV58: M15-049

- **Init:** LoadRobotConfigs, then InitExperiments (0x004EC9CE, 0x004EC9D6).
- **The loader** (0x00522EFC..0x00522F44): "config/experiments.json", scope 1. Load's result is ignored.
- **Load** (0x007EBDEA..0x007EBE98): parse, then SetFromJSON. On failure, sErrorF "AnkiLab.Load" "Invalid json format in
  AnkiLab file", then `_errG` and break.
- **The setters:**
  - top level 0x008F9C7C..0x008F9CEE;
  - meta 0x008F81B8..0x008F8234;
  - experiment 0x008F959A..0x008F98BE (key `pop_frac_pct`);
  - variation 0x008F8472..0x008F84D2;
  - ActivationMode 0x008F887E..0x008F8964: unknown → std::cerr, then 0 (manual).
- **Enable(true)** (0x007EBC3C..0x007EBC7C) and **the InitExperiments order** (0x006A5614..0x006A56CE). The behaviour-
  changing tail is 0x006A5626..0x006A56CE; the record's 0x006A56D0..0x006A5744 is mostly the epilogue.
- **The disable predicate:** OV58 has it wrong. It's kForceDisableABTesting && forcedAssignments.empty(), where the
  second operand is the size of the forced-assignment map at 0x0105D978 (0x004D9234..0x004D9244, 0x007EE96C..0x007EE984).
  kForceDisableABTesting's only writer chain ends at HandleABTestingForceURL, which has no caller. So the lab is always
  enabled, and logs "Enabling the lab".
- **The user ID:** DASGetPlatform()->vt+0x10 → libDAS 0x00028AF6 = the device ID, from Java `DAS.getDeviceID`
  (libDAS 0x0002833A..0x0002837E; DAS.java:159).
- **mfgId:** three words (0x007B1756..0x007B1772).
  - word 0 → ric+0x24;
  - word 1 → +0x28;
  - the colour byte, if it's in {0, 2, 3, 4}, goes to +0x2C; otherwise the InvalidBodyColor log is written.
  - ReadLab and ConnectRobotToNeedsManager use word 0 (0x0052E3A8..0x0052E3B2).
- **The shipped experiments.json** has 3 experiments. It matches.
- **Not re-checked:** VerifyTags 0x007EF274..0x007EF310, the qualified tags 0x007EF370..0x007EF4E2, and
  InitializeABInterface 0x007EE7EC..0x007EE808.
- **Also named:** the session global sSetGlobal("$session_id") (0x0052E374..0x0052E38A), which is M3/DAS's.
