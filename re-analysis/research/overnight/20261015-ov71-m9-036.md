All five perform these exact operations (F is one f32 instruction result):

1. Build lanes `[+0,h,F(h+h),F(h*3.0f)]`, native scratch-store order 0,1,3,2.
2. First output=`VADD.F32(offsets,duplicate(b))`; store four floats. First lane includes signed-zero behavior of +0+b.
3. step4=F(h*4.0f). Each later block **loads the previous stored block**, adds duplicate(step4), stores. Neither b+i*h recomputation nor four sequential scalar additions.
4. Add step4 to the last block once more, choose lane 0 as carry **after** emitted samples.
5. Clamp carry only: MI (ordered <0) gives +0; GT (ordered >1) gives 1. NaN and -0 survive. Low-clamp branches `0x009E5E64..0x009E5E88` load +0 literal `0x009E5E8C`.
6. Compare b vs carry: PL chooses b, MI carry (unordered chooses b). Compare old maximum vs candidate: update only on MI; unordered retains old maximum. Store OC. Advance p by N*4; continuation advances position/subtracts N.

N is already a multiple of four under the buffered frame/alignment contract. These bodies have no arbitrary-length scalar tail. **Stored lanes are not clamped here.** Maximum uses start and clamped carry, not a scan of samples. This is modulation and must remain exact under ADP-1.
