# Opus check of OV48 and OV49 (M13-037, M11-042), 2026-10-15

- **Checked:** `research/overnight/20261014-ov48-m13-037.md` and `-ov49-m11-042.md` (Codex), against libcozmoEngine.so
  and the Unity scripts. Read-only cozmo-extractor.
- **Adopted:** by the manager on 2026-10-15.
- **Result:** every behaviour-changing range cited matches the binary, including the f32/f64 order and the
  ordered/unordered branches. Two omissions are material:
  - **OV48:** the M13-037 path is unreachable from the shipped app.
  - **OV49:** two BehaviorAudioClient instances subscribe, and the app input SetSparkedMusicState isn't covered.

## Manager decisions

1. **M13-037 is unreachable from the shipped app.**
   - **Why:** every in-engine TurnTowardsObjectAction passes headTrack = 0; all six app calls pass headTrackWhenDone =
     false; and the app's TrackToObject is sent only with ID −1, which InitInternal rejects (0x00567A3A..0x00567A44).
   - **So it stays RECOVERABLE_GAP,** with live_path false, and isn't built. M13-036 shares the same unreachability: it's
     noted, and its status is unchanged.
   - **Operator question 1:** whether the stack API exposes TrackToObject with a real ID, or headTrackWhenDone = true. If
     yes, the build rows below apply.
2. **M11-042 is dissolved,** and becomes IMPLEMENTATION_GAP with nothing of its own to build.
   - **The visibility rows go to M11-010:** they supply the bodies that were MISSING.
   - **returnFirst = 0** is already M11-004.
   - **The calibration null reads are unreachable** on the shipped route.
   - **The subscriber goes to new records** in M13.
3. **BehaviorAudioClient** (spark and activity music):
   - **New RECOVERABLE_GAP:** whether both instances stay subscribed (the BehaviorManager+0x68 and
     BehaviorSystemManager+0x10 lifecycles), and the re-entrant double activation (the writers of broadcaster state+0).
     The handler can't be built until this is read, because two instances means two handler runs per publication.
   - **New IMPLEMENTATION_GAP:** the handler and helper bodies (rows below), waiting on the record above.
   - **Operator question 2, SetSparkedMusicState** (tag 0xA3, an app input):
     - **What it does:** it sets client+0xC, which starts at 0. Without it, every spark logs InvalidMusicState and no spark
       music plays.
     - **Why it's tied to sparks:** the operator has already decided to expose spark requests (ActivateSpark), and the
       app sends this message alongside them (SparksDetailModal.cs:309, OnboardingDoTrickStage.cs:82).
     - **The manager's recommendation:** the stack API passes it as well, as a COMPATIBILITY_POLICY input.
4. **M11-004's predicate citation is contradicted.**
   - **What the source shows:** 0x0061FA68 installs vtable 0x0102DDD4, whose operator is 0x006280DA. That operator requires
     +0x4C **and** +0x48 equality and calls ObservableObject::IsSameAs (0x0062810E). 0x006281DA is the type helper's
     predicate (M13-037).
   - **The built code must be re-checked against this.** An overnight request is queued.
