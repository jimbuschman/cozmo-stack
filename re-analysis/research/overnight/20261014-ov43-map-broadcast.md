## Tick aging and map changes

Use M for MapComponent, Q for its contained QuadTree and D for MemoryMapData. Update first compares M+0x1C with UnknownOriginID. With known origin it finds that entry in the M+0x10 map and requires a nonnull map value. Missing or unknown origin and null map skip aging, then still reach BroadcastMap at 0x0067DD1E. Normal return is zero. Exceptions clean up function objects and resume unwinding; they do not go through the normal broadcast tail.

For aging, now is the raw u32 loaded from Robot+0x2C, not the scheduler's seconds timer. At 0x0067DC98..0x0067DCE0 the exact order is U32-to-f32(now), two separate f32 additions of -30000 (`0xC6EA6000`) and -120000 (`0xC7EA6000`), then separate VCVT.U32.F32 conversions. The first result is overridden to u32 zero when the original unsigned now <30001; the second when now <120001. Do not replace this with integer subtraction: sufficiently large timestamps round before subtraction. No f64 arithmetic occurs in this body. The callback captures both thresholds and the original now.

The whole-map virtual +0x10 applies that callback. Its address-point is 0x01030834; operator slot +0x18 resolves to 0x006808F4. The callback reads D+4 type and D+0xC last timestamp. Type 8 selects the 30,000 threshold, types 9 and 10 select the 120,000 threshold; all other types retain their original shared data. For selected types, an unsigned last > threshold also retains it. At <= threshold it allocates a fresh base MemoryMapData: type byte 0, first and last both original now. It releases the old shared owner after publishing the replacement. Thus this is content replacement with Unknown, not polygon insertion, map clearing, deletion of nodes or removal of all old obstacles. An input timestamp of zero can already meet a clamped threshold of zero. There is no age-duration division or elapsed-time wrap subtraction.

There are **no polygon inserts** in the four requested parent functions. The Update callback changes data through existing map traversal. Neither it nor BroadcastMap explicitly stores the render/dirty flag. Any dirty marking, node collapse or shared-content visitation done by MemoryMap::TransformContent belongs to that dependency and must not be invented from the lambda. OV42 and the earlier quadtree research identify that separate transform path.

## Broadcast schedule and settings

M+0x3C is named “frequency” by the incoming message, but the body uses it as an additive interval in seconds. Constructor stores -1.0f and next=0.0f at 0x0067DA06..0x0067DA0E. Setting the interval copies its four bytes unchanged at 0x0067DC3C..0x0067DC3E, reads BaseStationTimer::GetCurrentTimeInSeconds and stores that returned f32 at M+0x40. It does not send a map immediately inside the handler; the next eligible Update may send one. Setting render enabled only copies a byte at M+0x38. BroadcastMap does not read it.

Exact scheduler order at 0x0067DDBC..0x0067DE06:

1. Load f32 interval; VCMPE against zero, then BLT. ARM unordered comparison has N!=V here, so a NaN interval returns along with negative intervals. Negative zero passes.
2. Get timer seconds, add f32 epsilon bits `0x3727C5AC` (approximately 1e-5), with a distinct f32 VADD. Load f32 deadline. VCMPE timerPlusEpsilon vs deadline; BMI returns on ordered less-than. Do not change this to a host double comparison.
3. Load interval, execute at least one f32 `deadline = interval + deadline`, then VCMPE timerPlusEpsilon vs new deadline and BGE back to that addition. This advances the old schedule repeatedly, rather than using now+interval or sending a map for each missed period.
4. Store final deadline before origin lookup. Missing map and UnknownOriginID therefore consume this scheduling opportunity as well. A found, known map invokes virtual +0x44 with its origin ID.

Zero or negative-zero interval with an ordinary due deadline does not advance and loops forever. A positive interval too small to change a large f32 deadline can do the same. The handler shown here does not reject either case. This is a defined native loop, **not** evidence of a crash/undefined-memory path covered by M1-034. Do not silently add a clamp, turn zero into “disabled,” or impose a new compatibility policy. Positive infinity advances to infinity for finite deadlines; unusual timer/deadline NaNs follow the actual BMI/BGE flag tests rather than a presumed finite-only contract. Recovering the input producer's restrictions remains separate from this raw handler behavior.

Unlike Update's aging lookup, BroadcastMap does not check the found map value for null before loading its vtable at 0x0067DE2A. If that invalid state is reachable it is a null dereference, covered by the standing M1-034 rule: skip the broadcast unit, retain prior state and log the owning record. The deadline has already been stored; no evidence supports rolling it back. Normal native operation has no corresponding log.

## Game message contents and order

MemoryMap::Broadcast at 0x006817BA adjusts this by 8 and tail-calls QuadTree::Broadcast. The tree uses Robot pointer Q+0xE0, embedded root Q+0x50, centroid words Q+0x5C/+0x60, side Q+0x68 and root level byte Q+0xD0. The first send happens **before** leaf collection and reserve:

- `MemoryMapMessageBegin`: origin argument, root level widened to a 32-bit word, side bits, centroid x bits, centroid y bits. Constructor 0x00728918..0x0072892C sets MessageEngineToGame tag **0x91**. Payload packer 0x0071C9A6..0x0071C9FE writes those five words in that order, four bytes each. Geometry words are copied, with no f32/f64 recomputation.
- `MemoryMapMessage`: vector of two-byte leaf entries. Constructor 0x007289E6..0x00728A06 moves the vector and sets tag **0x92**. Packer 0x0071CB40..0x0071CB80 writes a two-byte element count, then each entry via 0x00781544..0x0078157A, content byte first and level byte second. There is no origin field in this chunk payload.
- `MemoryMapMessageEnd`: tag **0x93** from 0x00728A94..0x00728A9A; no payload fields are filled by Broadcast. Empty collection still produces Begin then End, with no empty chunk.

At 0x00687B08 the recursive collector tests child-vector begin/end. Nonempty children are visited from begin to end in their actual stored pointer order, recursively; internal content is omitted. Each leaf dereferences its current data, translates type and appends the node's +0x80 byte. The table bytes at 0x00687B38 are `05 05 05 05 0C 09 0C 0B 07 07`, indexed by type-1 with unsigned range checking. Exact ordinary mapping is: 1→1, 2→2, 3→3, 4→4, 5→0, 6→5, 7→0, 8→6, 9→7, 10→7; zero and values outside 1..10→0. Do not serialize the native enum directly. There is no filter dropping Unknown leaves, no sorting by ObjectID, and no geometry or timestamps per leaf. Stored child order must come from the native tree; labeling it with compass directions without checking tree construction would exceed this extraction.

After collecting, Broadcast reserves 2046 entries for a reusable batch. Remaining=(end-begin)/2; each batch has min(2046, remaining), with contiguous forward slices from the collected vector. Each batch is copied to a message vector, moved into the union, broadcast, cleared and destroyed before advancing to the next. A 2047-entry collection sends two chunks of 2046 and 1, then End. The limit is **entries**, not 2046 bytes. Broadcast sends at most one complete stream per scheduler invocation; it does not wait for game acknowledgement. Dirty and render flags are not tested or cleared here.

Every Robot::Broadcast result is ignored. At 0x00511DE8 the external interface is loaded through Robot's context +4. If absent the helper returns false, otherwise calls interface virtual +0x18 and returns true. This establishes an external engine message path; it does not establish successful delivery to a game, network packetization or a C# callback. Under the operator's app-boundary rule, reproduce the engine's payload/order/timing and deliver through the stack API. Discarding these messages merely because Unity is replaced is unsupported.

If collection, allocation or a downstream call throws after Begin, cleanup releases vectors/unions and unwinds; no compensating End, retransmission or transaction rollback appears in 0x00685960..0x00685A04. A null leaf-data pointer faults at 0x00687B2A, also a standing M1-034 case if reachable; do not turn it into a fabricated Unknown entry.
