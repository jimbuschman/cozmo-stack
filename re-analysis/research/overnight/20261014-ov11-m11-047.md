## Layout and exact neighbours

The node has children begin/end/capacity at +0/+4/+8, centre XYZ at +0xC/+0x10/+0x14, side length +0x18, parent +0x7C, unsigned level byte +0x80, quadrant byte +0x81, and content pointer/control block +0x84/+0x88. Content type is byte +4 of the pointed-to MemoryMapData. An empty child vector means leaf. Child quadrants are Q0=(+X,+Y), Q1=(+X,-Y), Q2=(-X,+Y), Q3=(-X,-Y), as independently established by child construction 0x00687784..0x006878CE in P1. Root quadrant is 4; the neighbour function returns null immediately for it (0x006881BA..0x006881C0).

Direction-to-string's relocated table at 0x01030AA0 gives `N,E,S,W,Invalid`. Normal-vector tables at 0x0068C56C and 0x0068C57C, consumed in Y-then-X table order by 0x0068C538..0x0068C566, establish d0=(1,0,0), d1=(0,-1,0), d2=(-1,0,0), d3=(0,1,0). Thus incrementing direction cycles +X,-Y,-X,+Y. Values outside 0..3 produce a zero normal in that helper, but do not thereby become safe neighbour inputs.

The neighbour table stores `(destination quadrant, use sibling)` for each `(quadrant,direction)`. In direction order 0,1,2,3 its four rows are:

- Q0: `(2,0), (1,1), (2,1), (1,0)`.
- Q1: `(3,0), (0,0), (3,1), (0,1)`.
- Q2: `(0,1), (3,1), (0,0), (3,0)`.
- Q3: `(1,1), (2,0), (1,0), (2,1)`.

These are the actual 32 bytes at 0x01051064, indexed by `q*8+d*2` at 0x006881C6..0x006881E0. They are not a table inferred from geometric proximity.

1. **FindSingleNeighbor** (0x006881B4..0x00688214; M11-047, candidate IMPLEMENTATION_GAP): if q==4 return null. If the second table byte is nonzero, inspect the parent: return its child at the first table byte if it has children, otherwise null. If the second byte is zero, recursively find the parent's neighbour in the same direction. Null remains null. If that returned node has children, choose its child at the first table byte; otherwise retain the returned leaf. This yields the adjacent node at the current depth, or a larger leaf. It never manufactures an outside-of-root node.
2. **AddSmallestDescendants** (0x00688104..0x006881B0; M11-047, candidate IMPLEMENTATION_GAP): a leaf appends itself. An internal node recursively visits just two children on the requested side. For `clock==0`, the child pairs by d0..d3 are **(0,1), (1,3), (3,2), (2,0)**. For nonzero clock they are **(1,0), (3,1), (2,3), (0,2)**. The first child is visited to completion before the second. The TBB bytes at 0x00688122 are `[2,30,39,48]`, selecting bodies 0x00688126, 0x0068815E, 0x00688170, 0x00688182. This is side-only recursive descent, not all-descendant traversal.
3. **AddSmallestNeighbors** (0x00688220..0x0068824E; M11-047, candidate IMPLEMENTATION_GAP): find the single neighbour; if absent append nothing. Otherwise descend its facing side using signed remainder `(d+2)%4` and inverted Boolean clock (`clock==0 ? 1 : 0`). The live walk always passes clock 0. Thus its descent on the neighbour uses the second pair list above. It appends to the supplied vector; clearing that vector belongs to the caller.

All of these choices use integer indices, pointers and byte enums. There is no distance, epsilon, f32/f64 arithmetic or diagonal-neighbour test. Mixed levels are handled by the recursion: a large leaf appears once, while a subdivided adjacent side yields all of its contacting leaves in the specified order. Valid tree topology makes the relationship reciprocal, though the opposite-side index need not be the same index.

## Cache and seed order

4. **Combination selection** (0x00689AA8..0x00689AE8, 0x0068C18A..0x0068C216; M11-047, candidate IMPLEMENTATION_GAP): key is the unsigned 64-bit pair `((uint64)seedType<<32)|flags`. The ordered map is at processor+0x14. A new mapped value is 16 bytes: dirty byte 1 and empty waypoint vector at +4/+8/+0xC. Refresh calls FindBorders only when dirty is nonzero, then returns this value. The address loaded at 0x00689AB8 is **0x00C88161**, the empty construction tag, not a read or branch on `kDebugFindBorders` at 0x00C88160.
5. **Seed population** (0x00688F12..0x006890A0; M11-045 producer / M11-047 consumer): the maintained type-node sets cover mask **0x7C8 = {3,6,7,8,9,10}**. A type-change callback removes the node from an old cached type, inserts it in the new cached type, then invalidates borders. Same-type ForceSet does not call this callback; see 0x00687518..0x006875E4 and P1. FindBorders uses `processor.typeSets[seedType]`, including creation of an empty set if missing, rather than scanning every leaf for arbitrary seed types. There is no filter by neighbour mask at seed-set construction.
6. **Pointer hash** (0x00688F56..0x00688F64 calls 0x005198E0 with length 4; M11-047, candidate IMPLEMENTATION_GAP): with all operations wrapping uint32 and logical right shifts, let `m=0x5BD1E995`, `p` be the four-byte pointer value, `k=p*m`, `k=(k^(k>>24))*m`, `h=(4*m)^k`, `h=(h^(h>>13))*m`; result is `h^(h>>15)`. This is not the raw pointer, a coordinate hash, or a language runtime's default object hash.
7. **Insertion and rehash ordering** (0x00688F66..0x0068909A, 0x0068B68A..0x0068B7F6; M11-047, candidate IMPLEMENTATION_GAP): buckets hold pointers to predecessor links in one global linked list. Bucket index is `hash&(bucketCount-1)` for a power of two, otherwise unsigned remainder. Equality compares stored node pointers. Existing key is retained without insertion. For an occupied bucket a new node goes immediately after that bucket's predecessor. For an empty bucket it goes at global list head, and the displaced head's bucket predecessor is repaired. Size increments only for insertion. The node stores next at +0, hash at +4 and node pointer at +8.

Growth tests use f32: convert unsigned bucket count and `(size+1)` to f32, compare `F(loadFactor*F(bucketCount))` against `F(size+1)`, grow when smaller or count zero. New requested count is the unsigned maximum of `(2*oldCount)|nonPowerOfTwoOrSmall` and the truncating u32 conversion of `ceilf(F(F(size+1)/loadFactor))`; `nonPowerOfTwoOrSmall` is 1 when oldCount<3 or oldCount is not a power of two, otherwise 0 (0x00688FCE..0x00689036). Default load factor is 1.0f. Rehash maps request 1 to 2, preserves powers of two, otherwise requests `__next_prime`; equal count is a no-op. Its physical list rewrite at 0x0068B74E..0x0068B7F2 preserves a run already in its bucket, records a predecessor for a newly encountered bucket, and splices a later run of an already seen bucket behind its recorded predecessor. It does not sort by hash, address or coordinates. The shipped rehash instructions are the ordering authority; a merely set-equivalent container is insufficient.

The normal unreserved insertion-growth sequence starts 2,5,11,..., so the prime-sizing call is a real interface, not dead code. Its exported library entry is PLT 0x004A85D8; this report does not claim to have extracted that generic library routine's extreme-size exception behavior. The seed list and pointer values at the start of a walk, however, completely specify the walk's seed order without invoking a hash operation during iteration. Membership lookup in the temporary checked map cannot reorder the seed set.

## Complete walk transitions

8. **Initialization** (0x0068AB98..0x0068AC24; M11-047, candidate IMPLEMENTATION_GAP): obtain the same combination, store its address in processor+0x20, clear its waypoint vector without releasing capacity, obtain the seed set, set processor byte +0x28 to 1, construct a fresh checked-state hash map and neighbour vector, and reserve `1 << unsigned(root.level)` neighbour slots. The live root level is bounded by the quadtree's construction/expansion rules; there is no floating-point conversion here. Iteration starts at the seed set's global head (+8), takes the node pointer from hash-node+8 and advances via hash-node+0 (0x0068AC24..0x0068AC34, 0x0068B05C..0x0068B062).
9. **Checked state** (0x0068A9F4..0x0068AA1C, 0x0068AB1C..0x0068AB94, generated construction 0x0068C244..0x0068C286; M11-047, candidate IMPLEMENTATION_GAP): each node has four 16-byte direction records. Each contains a vector<bool> and signed remaining count initially **-1**, not zero. Initialize a direction only if its bit-vector size is zero: resize to current neighbour count with false bits and set remaining to that count. A direction with no neighbours therefore becomes complete immediately. Marking bit i sets it and decrements remaining exactly once. A direction is complete iff remaining==0; all directions complete iff all four counts are zero. The per-direction sequence is fixed by the unchanged topology; no re-sorting is done after initialization.
10. **Select first unvisited flagged contact** (0x0068AC3A..0x0068AD98; M11-047, candidate IMPLEMENTATION_GAP): skip a seed whose four counts are zero. Otherwise begin direction 0 and neighbour index 0. Skip completed directions; for others clear/repopulate ordered neighbours with clock 0 and initialize that direction. Walk indices ascending. Already-checked entries are skipped. For each unchecked entry, mark it **before** checking its type. Compute `EContentTypeToFlag(type)` at 0x00684970..0x00684976 (32-bit register shift of 1); accept iff `(flag & requestedMask)!=0`. If none matches, rotate `(d+1)&3`, reset index 0 and continue until all four directions complete. No matching contact means no waypoint for that attempt. A node can start several walks: after a walk ends, the outer seed is revisited until its four directions are complete.
11. **First emission** (0x0068AD9C..0x0068ADC2; M11-047, candidate IMPLEMENTATION_GAP): append `(seed,neighbour,d)` through call site **0x0068ADAA**, then set byte +0xD of that appended waypoint to 1. Store current node=seed and set index to the accepted index+1. Continue with the current direction's existing neighbour vector, not direction 0 or the next direction unconditionally.
12. **Side exhaustion** (0x0068ADC4..0x0068AE28; M11-047, candidate IMPLEMENTATION_GAP): when index reaches neighbour count, look up the current node's checked state, rotate `(d+1)&3`, clear/repopulate ordered neighbours with clock 0, initialize checked state if necessary, and set index=0. Empty sides rotate again. This branch does not use `remaining==0` to skip the side: closure detection below must still see checked contacts.
13. **Cross another seed node** (0x0068AE2A..0x0068AEB8, 0x0068AED6..0x0068AF2A; M11-047, candidate IMPLEMENTATION_GAP): first test `neighbour.type==seedType`. This wins even if the mask also contains seedType. On equality, replace d with signed `(d+2)%4`, rebuild neighbours of the new node on that reverse side, search from index 0 for the old current-node pointer, and select its index. Initialize the new node's direction state, mark that reverse contact, set current node to the new node, then advance index once and continue. **No waypoint is appended for this interior crossing, and the old current node's outgoing contact is not marked by this branch.** It is not a breadth-first or depth-first flood fill of seed cells.
14. **Neighbour is a different, masked type and contact is new** (0x0068AF30..0x0068AF74, 0x0068AFEC..0x0068B034; M11-047, candidate IMPLEMENTATION_GAP): append `(current,neighbour,d)`, mark the current direction/index, advance index and continue. Newly appended flags are zero. There is no automatic start-flag write merely because the previous waypoint's end flag is already one.
15. **Neighbour is a different, masked type and contact was checked** (0x0068AF76..0x0068AFA8, 0x0068B004..0x0068B03A; M11-047, candidate IMPLEMENTATION_GAP): if there are waypoints and the last one's end flag is zero, append this same closing contact once more. Then set the last waypoint's end flag to 1. If already ended, append nothing. Mark is idempotent, and the continuation Boolean is zero, ending this walk. This is why an exact waypoint vector can contain a duplicate closure contact. Termination is not simply equality with the first seed node or a fixed step budget.
16. **Neighbour is a different, unmasked type** (0x0068AFAA..0x0068AFEA; M11-047, candidate IMPLEMENTATION_GAP): set the last waypoint's end flag to 1 if the vector is nonempty; mark this current contact; **continue** the traversal. Unmasked contact splits output but does not terminate the contour walk. This branch does not test whether a checked unmasked contact should close the walk. The distinction from row 15 is material.
17. **Finish** (0x0068B03E..0x0068B096; M11-047, candidate IMPLEMENTATION_GAP): return to the original outer seed; repeat first-contact search until its four remaining counts are zero, then advance the seed list. After all seeds, set the combination dirty byte to 0 and processor+0x20 to null; destroy local neighbours and checked map. Processor+0x28 is not reset by this function. There are no direct logs, robot commands or game broadcasts in FindBorders.

These rules establish side-contact membership and its processing order on a valid finite tree. A checked bit is associated with one specific side-contact occurrence, not with all contacts to the same neighbouring object. Shared corners do not qualify. The walk can continue through unmasked contacts and same-type cells, and can output multiple runs and repeated closing waypoints; “all border nodes once” does not describe its output. The source's complete-direction counts ensure subsequent starts cover still-unchecked contacts of each cached seed. This is a reading of the state machine, not a claimed emulator proof for every arbitrary corrupted graph.

The fast path writes the three words and a zero halfword at +0xC, then advances end by 16. The growth path initializes end from the supplied false Boolean and start to zero, copies the existing vector bytes in order and replaces begin/end/capacity. It does not deduplicate. Neither `to`, direction, start/end flag nor the geometric centre of the interface supplies the fill point. ## Address dependence and failure boundaries

The current record asks whether the operator will accept only the resulting border set. The standing instruction already answers that policy question: **exact behavior remains required; no set-only departure is approved.** There is no need to ask that question again. The following are distinct facts:

- The walk and container algorithms are shipped and recoverable. This report supplies their branches rather than replacing them with a plausible contour algorithm.
- The initial pointer-valued seed list and its history are runtime state. Two runs can place identical geometric nodes at different addresses and therefore begin at different seeds. Hash order is not described by the final geometric map alone.
- The particular heap addresses of an unspecified original run cannot be recovered from this `.so`; a capture/replay with that state would be needed to claim that run's exact sequence. A different runtime's allocation/object-hash choices are not automatically the same input.
- This read does not prove all production outputs independent of that order. GetBorders demonstrates where order and accumulation are consumed. Therefore the full record should not be marked settled by a border-set comparison alone. The known algorithm can be checked against supplied pointer identities and container histories; the wider production ordering claim must retain an explicit gap until its input contract or an exact invariance proof is established.

Undefined paths are covered by the existing M1-034 policy, not by invented normal semantics. FindSingleNeighbor has no range validation for q outside 0..3 other than q==4, nor for direction; its table read at 0x006881E0 and child accesses at 0x006881F0/0x00688206 can be invalid on malformed topology. AddSmallestDescendants uses child index 255 for invalid direction and dereferences it at 0x00688190. Valid walk inputs always use d0..3. The reverse contact search has no not-found guard: if a corrupted tree's new-side neighbour vector does not contain the old node, index remains count, and 0x0068AF10 reads/updates the bit vector at that index. This can be an out-of-bounds read (or a spare-capacity bit with a corrupted remaining count); no safe result follows. A content pointer is also dereferenced without a null guard at 0x0068AD2C/0x0068AE4C. None of these is established as reachable from valid normal tree construction.

For a terminating/undefined case, the proposed policy disposition is skip the failed border refresh/fill operation, preserve previously valid map/cache state and visibly log **M1-034 and M11-047** with the failing boundary. Do not publish a partly constructed waypoint cache as a valid replacement. This is the standing policy's required behavior, not what the original does. Allocation/length errors unwind through 0x0068B0B6..0x0068B0EA; the original has no local recovery that restores processor+0x20. Waypoint growth checks its maximum at 0x0068BCAE..0x0068BCB6; oversized rehash allocation throws at 0x0068B7FA..0x0068B82C. Ordinary valid execution does not reach the malformed-topology paths above. There are no firmware effects to test here, and this work did not start hardware acceptance.
