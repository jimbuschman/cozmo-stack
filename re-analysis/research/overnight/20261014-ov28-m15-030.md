## Exact branch and operand contract

The VFP comparison result copied to APSR has the following observed/decoded condition meanings. For unordered, NZCV=0011: **BGE false, BLE true, BMI false, BPL true, BLS false, BHI true, BGT false, BEQ false, BNE true**. These are ARM conditions, not interchangeable language operators. In particular, translating BLE as a C# `<=` loses its unordered branch.

All arithmetic in F2–F7 is binary32 and separately rounded. No fused multiply/subtract and no f64 decay accumulator appears. A direct move/load/store can preserve a signaling NaN bit pattern that would have been quieted if it went through arithmetic. The Info argument widening is a separate operation; it does not overwrite the original stored map level or elapsed input register saved in s16.

The literal f32 +0 minimum/elapsed comparison is not a NaN sanitization step. Invalid FP arithmetic normally produces an exceptional value and sets FPSCR flags when exceptions are disabled; it is not by itself an M1-034 crash. Do not substitute a “skip malformed value” policy for defined NaN branches.
