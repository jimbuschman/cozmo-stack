# Opus check of OV125 (M1-056) and OV126 (M1-054/055/056, M2-020), 2026-10-17

- **Checked:** one read-only cozmo-extractor pass (Opus), Capstone/LIEF, with stores/callers/subscription censuses.
  Scripts: session scratchpad `d.py`, `scan.py`, `callers.py`, `e2gsub.py`. OV126 was checked against its tightened
  request (7c5bfd3b) and its updated answer (d287f07a).
- **Verdict:** no claim in either answer contradicted. OV125 omits the engine's own UI auto-connect and the StartEngine
  prerequisite (N1–N6 below), which change the readiness picture. OV126's verdicts hold; routine 6 narrowed.
- **Adopted:** by the manager on 2026-10-17, under AGENTS.md "What we reproduce".

## OV125: states 0 → 3 (checker's citations)

- **Switch:** 0x004ED5C4 ldrb engine+0x62; tbb 0x004ED5CC: state 0 does nothing (tail 0x004ED6BE), 1 → 0x004ED5D6,
  2 → 0x004ED5F0, 3 → 0x004ED61E, 4 → 0x004ED654.
- **State 0 → 1 needs G2E StartEngine** (N5): handler 0x004ECBDA sets the random seed, SetLocale 0x004ECBE2, then
  SetEngineState(1) unless already 3 (0x004ECC40..0x004ECC4A); state 3 only logs an error. No other path sets 1 (the
  firmware path aside, unsupported).
- **State 1 → 2 gate:** some comms slot with count ≠ 0 and count ≥ desired (0x006632F4..0x0066330E). Desired stays 0 for
  Direct and TCP (0x0065DC50; only UDP Init stores +0x84, 0x0065FBD0). Slot 0 is Direct.
- **Direct's count** (N1–N3): UiMessageHandler::Update, after ProcessMessages, asks each slot for advertising IDs
  (0x00662ACE); Direct offers its own id while +0x98 == 0 (0x0065C500..0x0065C514), which equals UI+0xE8 (0x0065FF98,
  0x0065C3C4), so the engine auto-connects slot 0 (ConnectToUiDevice 0x00662AEE; 0 → 1 at 0x0065C4C4..0x0065C4D0).
  1 → 2 happens when the first game message is received (RecvMessageInternal 0x0065C44C..0x0065C458, called from
  ProcessMessages 0x00662860, gated by UI+0xF1). In the original that first message is StartEngine itself.
- **ConnectToUiDevice also sends** E2G UiDeviceConnected (two 16-byte CLAD hashes; 0x00662DE0..0x00662E3E) and, on a
  successful connect, a local G2E RequestRobotSettings (0x00662E56/0x00662E5E); its only named handler is
  Robot::HandleMessage<RequestRobotSettings> 0x00516C50, live only once a Robot exists (effect not read).
  Otherwise a non-matching id sends E2G UiDeviceAvailable (0x00662B2A..0x00662B32).
- **Ping** (N4): every UI Update with counter UI+0xEC % 20 == 0 (0x00662A0E..0x00662A22), per slot with count ≠ 0, Ping
  {counter, timeSent_ms, isResponse 0} to the game only, no local dispatch (0x00662A46..0x00662A76).
- **Transition:** gate (0x004ED5D8, cmp #1 0x004ED5DC) → SendSupportInfo 0x004ED5E2 → SetEngineState(2) 0x004ED5EA →
  exit (0x004ED5EE).
- **SetEngineState** 0x004ECCBC: same state does nothing (0x004ECCC4..0x004ECCCE); store +0x62 first (0x004ECCD2); then
  E2G UpdateEngineState {old, new}, tag 0x7B, one byte each, old first (wrapper 0x004EDC12..0x004EDC2E; ctor 0x007276F8;
  Pack 0x00719F7E..0x00719F9E); then telemetry `app.engine.state` (0x004ECD2A). No engine code reads the payload. The
  stored state selects the Update case; state 3 runs robot connection and robot updates.
- **Progress writers:** ctor zero (0x0051EF3E/0x0051EF46); per-file 0.7f/N (0x0051F9B0..0x0051F9C0, 0x3F333333) added
  at 0x005216A6/0x005216D8 unless the file failed (0x00521684); +0.2f twice (0x0051F3F2, 0x0051F424; 0x3E4CCCCD); 1.0 at
  0x0051F480..0x0051F48C; AddToLoadingRatio 0x005203E8.
- **Poll:** copies progress out (0x00523576..0x0052357E), done short-circuit (0x00523580), join only at ≥ 1.0f
  (0x005235A2/0x005235AA), worker created at 0x005235E2. It does not read engine state; only the state-2 case calls it.
- **N6:** a null DataPlatform makes LoadNonConfigData return at 0x0051F394 without 1.0, so the engine stays in state 2
  forever (a hang).

## Manager decisions (2026-10-17)

- **App inputs that start the engine** (app-boundary scope; recorded as COMPATIBILITY_POLICY M1-058): the stack
  supplies (1) a StartEngine equivalent (host random seed and locale, then the native handler path: seed, SetLocale,
  SetEngineState(1)); (2) the connected-UI condition: the stack's C# API host is the one UI device, connected from
  engine start, standing in for Direct's count; (3) the data platform: the resources root. A missing resources root is a
  failure that can happen here: the API reports **failed** (operator decision, M1-056) instead of the native hang (N6,
  M1-034 hang rule).
- **Not supported (manager, game-socket plumbing; M1-059):** UiDeviceAvailable, UiDeviceConnected and Ping to the game.
  The C# API is the interface; these exist to manage the phone app's socket.
- **Readiness for the C# API:** UpdateEngineState (0x7B) is the source of the loading / ready transitions the operator
  asked for; progress from the writers above.
- **Open for the operator (API features):** whether the API offers SupportInfo (support/diagnostic identity), and whether
  it supports game-posted audio (PostAudio* G2E 1–6, which decides AudioUnityInput).
- **Kept UNKNOWN, not scheduled:** the local RequestRobotSettings at UI connect (no Robot exists that early, by M2-021's
  order; not read); routine 6's tag-only raw callback; F5/F6's reader; FactoryTestLogger archive. Each is named in its
  record's `unresolved`.
