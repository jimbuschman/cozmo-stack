## The rows

- **F1, CreateActiveObjectByType:**
  - the light cubes (types 1–3) give an ActiveCube: 0x180 bytes, returning +0xA4;
  - type 13 gives a Charger: 0x15C bytes, returning +0x70;
  - any other type: sErrorF `CreateActiveObjectByType.UnsupportedObjectType` "Cannot create active object for given '%s'
    object type", then `_errG` and break-on-error, then return null. The caller (0x00623296) then sets ID −1, with no
    further log.
- **F2:**
  - **the clones** (by vtable): Charger CloneType 0x004EA528, Ramp 0x0050F890 (unreachable), MarkerlessObject 0x00502DAC
    (type +0x4C, 0x74 bytes);
  - **the Charger's slots:** IsActive (+0xC) = 1, +0x18 = 0;
  - **vtable +0x58:** ActiveCube 0, Charger 1, Markerless 1.
- **F3, SetID:** the +0x5C uniqueness test (ActiveCube and Charger 1; Markerless 0), the guarded static map
  0x010591C0/0x010591CC, and ObjectID::Set 0x008412D8 (store the counter, then postincrement).
- **F5, AddMarkerlessObject, corrected:**
  - (a) **families {2, 6} go to filter+0x3C, the allowed set** (0x00622530..0x00622550; evaluated at
    0x0061EC60..0x0061EC96). When the robot is localized, only families 2 and 6 are intersection candidates. Otherwise
    every family is.
  - (b) the overlap stage runs only if world+0x40 has an entry for the current origin (0x00622440..0x00622478).
  - (c) the family-6 access is `operator[]`, so it creates an empty family-6 map in that origin (0x0062249A).
  - (d) the refresh of an overlapping object is a plain store, +0x1C = robot+0x2C (0x006224BC), not a max.
  - **The rest is as M11-062 already has it:**
    - the local (0, 0, size.z·0.5), then supplied·local;
    - SetID only on an empty intersection;
    - AddLocatedObject, then +0x54 = 1;
    - type 15 Cliff and type 14 ProxObstacle quads from the original pose;
    - the fmax tail; return 0.
- **C1, HandleActiveObjectConnectionState:**
  - **A slot > 4** returns **silently** (0x00533B58).
  - **The DAS event:** sEventF `robot.accessory_connection` "0x%x,%s", with `$data` connected or disconnected.
  - **On connect:** an Info log (ID, slot, factory, type), then HandleConnectedToObject.
  - **On disconnect:** 0x00533CB2.
  - **ID −1** lands at 0x00533CB8 and falls into the Recvd log "FactoryID 0x%x, connected %d".
  - **The VizManager message** is built and cleared, with no send.
  - **The broadcast happens only when ID ≠ −1:** tag 0x0D with (ID, factory, type, raw byte).
- **C2, RemoveConnectedActiveObject:**
  - match on observable+0x40; save +0x18; null and release the shared pointer; erase (0x00624432);
  - **when the erased entry's ID is −1:** the walk skips the rest of that type and continues with the next type and
    family (0x00624436..0x0062443E);
  - the filter is allowedIDs = {ID}, OriginMode 2, returnFirst 0;
  - the NotActive warnings "ID: %d" (0x0062A1DC, 0x0062A226).
- **C3, Robot::HandleConnectedToObject:**
  - the slot is robot + slot·24 (+0x494, +0x498, +0x49C);
  - **a mismatch:** `Robot.HandleConnectedToObject` on channel BlockPool, with no change;
  - **a state other than 1 or 4:** `…InvalidState`, with `_errG`, then it continues;
  - `Robot.HandleConnectToObject`;
  - a hash erase at +0x47C; state = 2; +0x4A8 = 0.
- **C4, MarkObjectUnknown:**
  - **The broadcast** is RobotMarkedObjectPoseUnknown (tag 0x52, one word). It carries the **original** object's ID on
    every iteration (0x005073AA..0x005073B0).
  - DeleteLocatedObjects then runs, followed by nulling the reference.
  - **The deletion filter** is OriginMode 0, current origin only (0x00507386).
- **O2, CheckForCollisionWithRobot:**
  - **The gates, in order:**
    1. vt+0x58 ≠ 0;
    2. +0x1C ≥ the last image;
    3. +0x24 ≠ 1;
    4. carried;
    5. the docking target's ID.
  - **The test:**
    - the z window (constant 0x42876666; NaN rejects);
    - quad padding 0 and robot padding −10.0;
    - `robotQuad.Intersects(objQuad) == 1`;
    - an Info log with (type, ID, robot ID).
  - **The caller** (0x006250D8):
    - stores +0x74 = 0;
    - is skipped while docking (+4);
    - uses OriginMode 0, then MarkObjectDirty with confirmer robot+0x26C.
- **O3, the pads** (0x00621E8C..0x00622102):
  - **D = 250.0f** (GetMaxLocalizationDistance_mm 0x004EF460). `VCVT.U32.F32` saturates negative and NaN values to 0,
    so pads are 0 beyond 500 mm.
  - **IsWithinFieldOfView** (0x0085E13C):
    - NaN rejects;
    - y ≥ yPad and x ≥ xPad;
    - x < f32(s32(calib[2] − xPad)) and y < f32(s32(calib[0] − yPad));
    - a NotCalibrated warning.
  - **A crash candidate (M1-034 standing rule, if reachable):** the calibration shared_ptr at VisionComponent+0x28 is
    dereferenced with no null check (0x00621F58, 0x00622060/0x00622064). Its reachability is unread.
- **O4:**

  - then UpdateMarkerObservationTimes (0x00876C9C..0x00876CCA; 0x00877706..0x00877740) does the positional unsigned-max
    merge.
- **O5, DeleteIntersectingObjects:** as M11-062 has it. The object overload can delete the target itself if the filter

- **O6, AnyRemainingLocalizableObjects:** filter +0x6D = 3; allowedOrigins is filled only for a non-zero origin;

- **O7, OnObjectPoseChanged:** the append gate is **PoseState ≠ Invalid** (`cbz r3` at 0x0062487C). The pose pointer is

- **H1:** field identities (MovementComponent+0x20, Robot+0x280+4, +0x355), confirmed.
- **H2, Interpolate** (0x0053068C..0x00530848; ctor memcpy 0x5B at 0x005304F4): only cliff channel 0 is blended.
  Channels 1–3 stay 0xFFFF.
- **H3, SetLocalizedTo:** a MarkerOriginProblem returns 1 after an earlier replacement but leaves the +0x2C8 store

- **K2–K5:**

## Contradicted (notes appended to each record)

- **M11-041:**
  - its "a type other than a light cube throws": the Charger is accepted, and other types return null with an error;
  - its "0x00533B58 and 0x00533CB8 logged only": the first is silent, and the second goes to Recvd plus viz with no
    broadcast;
  - its "VisionSystem forgets the cube's object on disconnect": C2 is what actually happens.
- **M11-007:** the broadcast is RobotMarkedObjectPoseUnknown (0x52) with the original ID, not PoseStateChanged.
- **M11-037:**
  - "both pads are 0": O3;
  - "a null old pose appends nothing": the gate is PoseState, not the pointer.
- **M11-013:** the UpdateMarkerObservationTimes stand-in (O4).
- **M11-044** is too strong: +0x2C8 can already be written when the marker loop fails.
- **M11-042's own stand-ins** (the Charger passive, the pads 0, the counted stub) are superseded.
