## OV62: M7-029

- **The callbacks** (vtables 0x0102B04C/8C/CC/10C; +0x18 at 0x005FC68D, 0x005FC79D, 0x005FC9C7 and 0x005FCA45).
- **The transitions,** through the GOT (0x0103F520/0x0103F524).
- **The update table:** TBB bytes 04 10 34 3B 85 85 86 at 0x005FB218 for states 4..10.
  - states 8 and 9 return 1;
  - state 10 returns 2;
  - every other state goes to CheckForTimeout.
- **InitialSearch's RNG order** (0x005FAF70..0x005FB163), with the head global 0x0105B354 = 0xBEDF66F3. It's unreachable
  with the shipped config.
- **Rotate:** q = 140/(140 − deg(+0x11C)), compared with `bpl`; then +0x11C += the change, and +0x198 = 0
  (0x005FB8D0..0x005FBA09). **+0x11C is reset only in the ctor,** so the direction bias carries over between activations.
- **CheckForTimeout** (0x005FB5B0..0x005FB7DD): strict <, and NaN skips.
- **The track setup** (0x005FBE84..0x005FC04A): SetStopCriteria; the track callback goes to Pounce or Rotate.
  - **Wording:** "SetUpdateTimeout(f32 158)" means field +0x158.
  - **Wording:** the `strh` at 0x005FBF32 writes +0x145 = 0 and +0x146 = 1.
- **Pounce:** ObjectiveAchieved(0x0E), then BringingHeadDown.
- **The observation path** (0x005FC1D8..0x005FC4DC), on channel "Behaviors".
- **The ctor** (0x005FA250..0x005FA31E):
  - +0x11C = 0;
  - the graph at +0x144;
  - field resets;
  - SubscribeToTags {0x4A, 0x43} (0x00C715D0);
  - SetParamsFromConfig;
  - state 0;
  - +0x198/+0x19C/+0x1A0 = 0.
- **SetParamsFromConfig** (0x005FA374..0x005FA955): the key → offset map is in the extractor report, all ParseFloat. Also:
  - skipGetOutAnim (optional) goes to +0x194;
  - maxLostLaserTimeoutGraph_sec is read through GraphEvaluator2d::ReadFromJson;
  - a missing graph key gives sVerifyFailedReturnFalse "No key found for lost laser timeout graph".
- **The lifecycle rows** (M7-025's ranges, owned here for everything that isn't colour):
  - **InitInternal** (0x005FAC10..0x005FAC4C): with the shipped config, it always goes to WaitForExposure;
  - **InitHelper;**
  - **Resume** (0x005FBBAC..0x005FBBC8);
  - **Stop** (0x005FBD14..0x005FBD3A): ObjectiveAchieved(0x0F) and NeedActionCompleted(0) when +0x1AE is set;
  - **Cleanup** (0x005FBD40..0x005FBDDA): state 11, then the resets.

  +0x1AE is consumed only by Stop.

## OV63: M11-087

- **IsExposureValid** (0x006B9DA4..0x006B9E02): signed and inclusive. On rejection, it warns `…IsExposureValid.OOR` with
  (e, min, max).
- **IsGainValid** (0x006B9E78..0x006B9EFC): an ordered f32 compare, so NaN rejects. It warns `…IsGainValid.OOR`.
- **SetCameraSettings** checks exposure first. If exposure is invalid, gain isn't checked.
- **The ctor bounds:** exposure 1..66; gain 0.1..4.0. SetCameraExposureParams turns a minimum ≤ 0 into 1.
- **The darken value is validated as the full u32,** read as a signed int (0x005FAD1C..0x005FAD20, 0x00657EFA). Only the
  message stores the low 16 bits.
- **The darken answer:** it passes at the ctor bounds. For robot bounds, it passes iff max(1, pkt.min) ≤ 1 ≤ pkt.max and
  0.1 ≤ pkt.maxGain.
- **The operator's robot** reported exposure [0, 67] and gain [0.100, 3.984] (hardware bundle 20261012-062328-M3M4-HW). So
  the darken values pass there. That's a hardware observation, not provenance.

## OV64: M6-031 (ARM, pc+8)

- **G = 0x0108D868, P = 0x01052418.**
- **The head** (0x0099DCEC..0x0099DDB8) and **the +8..+EC tail** (0x0099DDC0..0x0099E318), in OV64's order:
  - +0x78 is read first, with no null check;
  - +0x8C's cond/mutex destroy;
  - 14 mutexes;
  - P = −1 at the end.
- **9B0350** dispatches on config +0x3D: either 9D4058 → 9EAF90, or A40B18 (thread join/post/destroy/init).
- **The active drain** (A40D44..A40DC8).
- **The bus loop:** reverse order, with a null skipped.
- **The pending drain** (9D3EC4..9D3F38).
- **Memory Term** (A7A6F0..A7A784; A7AEC4..A7AF78): the live-count decrement doesn't end the loop early.
- **M1-034 points** (list-invariant traps; whether they're reachable is unknown): 0x00A40D84/0x00A40D88,
  0x009D3F04/0x009D3F08 and 0x009EAFD8/0x009EAFDC.
- **No logs, sends or DSP** in this path.
