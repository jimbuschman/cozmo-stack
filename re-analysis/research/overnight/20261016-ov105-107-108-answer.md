## M15-031: ActivateHighLevelActivity (G2E 0x92), now in scope

- **S1, the wire:** G2E tag 146 (0x92), a 1-byte `activityType`, with no range check (Unpack 0x00738A94; Get
  0x0074D90A).
- **S2, the subscription:** only when HasExternalInterface (0x005A0F5A..0x005A0F64). Subscribe tag 0x92 at
  0x005A147E..0x005A14C8. The functor is trivial, and its handle goes to manager+0x6C. This is the only tag-0x92
  subscription.
- **S3–S5, the adapter** (0x005A4FA2..0x005A4FE0):
  1. SetCurrentActivity(v, false);
  2. **then, always,** even after "already set":
     - **v == 1 (Freeplay):** if f32 +0x54 < 0 (N set; NaN doesn't count), +0x54 = GetCurrentTimeInSeconds. That stamps
       the first Freeplay activation, since the ctor writes −1.0f at 0x005A08F0;
     - **v ≠ 1:** +0x60 = 0x55, then +0x58 = 0x55. Nothing else is cleared.
- **SetCurrentActivity** (0x005A106C..0x005A1230):
  - **S6:** if byte +0x20 == v, the Info "Behaviors" / "BehaviorManager.SetCurrentActivity" "Activity '%s' already set",
    then return. This check comes before the bool test.
  - **S7–S9, when the bool is false:** GetCurrentActivity (operator[] inserts null if the key is missing), then
    OnDeselected(robot); then the sEvent "BehaviorManager.SetBehaviorChooser" "Switching behavior chooser from '%s' to
    '%s'" (the old activity's ActivityID name, then the new HighLevelActivity name); then an Info with the same text.
  - **S10:** if the running trigger (+0x1C → +0x10) == 0x16 (NoneTrigger), SwitchToBehaviorBase({null, null, 0x16})
    (M8-012).
  - **S11:** always clear the resume behaviour (0x005A270E).
  - **S12:** store v at +0x20.
  - **S13:** OnSelected on the new activity.
  - **S14:** +0x50 = the time.
  - **S15:** v ≠ 1 → ClearFreeplayPauseFlag(GameControl); v == 1 → SetFreeplayPauseFlag(GameControl) (M15-015 bodies).
  - **S16:** if the trigger was 0x16, ChooseNextScoredBehaviorAndSwitch.
- **S17:** the activity map from `activities_config.json`: Selection, MeetCozmoFindFaces, Feeding and Freeplay.
- **S18:** at init, SetCurrentActivity(Selection, true) from the Robot ctor (0x005A0F44..0x005A0F4C). With a null config,
  SetFreeplayPauseFlag(true, 0) instead.
- **S19:** EnumToString(HighLevelActivity): Feeding 0, Freeplay 1, Selection 2, MeetCozmoFindFaces 3, Count 4; above 4
  it returns null.
- **What the Unity app sends:** Freeplay 1, Selection 2, Feeding 0 and MeetCozmoFindFaces 3, from NeedsHub,
  NeedsEnergyModal, FaceEnrollmentGame, the onboarding stages, and ResetRobotState / RobotStartIdle.
  `SetEnableFreeplayActivity(false)` sends Selection, then ExecuteBehaviorByExecutableType(Wait).
- **M1-034:** v ≥ 4 eventually calls OnSelected(null), which faults at 0x005B3140 (from 0x005A11F4).
- **Still open:** who reads +0x54 (the first-Freeplay timestamp).

## M8-027: the ProtoHandle callables (settled)

- **The void() signal** (global 0x0105DF8C) holds one subscriber: WifiUtil::RegisterTransport's
  `bind(0x0083BAD0, UDPTransport*)`, which is trivial. Dispatch through it is app input (M1-049).
- **The Dispatch signal** (TransferQueueMgr+0xC) holds two RegisterTask::$_0 callables, for the DAS and game-log
  transfer tasks. Their destroy only destroys an inner trivial bind, so it's memory only. Dispatch through it is app
  input (M3-059).
- **None of the 10 non-trivial void() callables** (10, not 9: ReliableTransport::QueueAction::$_1, vt 0x010376A0, was
  missed) is held by any signal.
- **All 8 release bodies are identical:** lock the weak pointer, find the node, then tail-call remove (as at
  0x006634F4). No log, no message, no invocation.
- **Teardown:** ~TransferQueueMgr (0x006A3860..0x006A3898); the void() signal is destroyed at exit.

So destroying the subscriber callables has **no observable effect beyond freeing memory.**

## Corrections

- **M8-012:** an app-requested undefined activity (v ≥ 4) faults first at 0x005B3140, inside SetCurrentActivity, not
  at 0x005A2F7E.
- **M15-058:** the adapter summary missed the v == 1 stamp of +0x54. The clear also runs after "already set".
- **M15-031:** its title and effect ("SDK…") are stale. The receiver is the app path; ResetRobot's two sends
  (0x0065DDBA and 0x0065DE24, value 2) are SDK-only (M8-018).

## Manager decisions

1. **The stack API takes the four-value HighLevelActivity enum** (Feeding, Freeplay, Selection, MeetCozmoFindFaces),
   which is what the app sends. So v ≥ 4 can't occur, and no M1-034 skip is needed.
2. **The API's "stop freeplay"** follows the app's `SetEnableFreeplayActivity(false)`: Selection, then
   ExecuteBehaviorByExecutableType(Wait). That falls within the operator's decision to expose activity activation.
