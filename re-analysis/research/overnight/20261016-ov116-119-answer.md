# Opus answers to OV116–OV119 (M6-042, M6-040, M6-041, M6-043), 2026-10-16

- **Method:** a read-only Opus cozmo-extractor, against libcozmoEngine.so: ARM for Wwise, Thumb for Anki, capstone with
  skipdata, no decompiler output. "No static caller" means four scans came back empty: ARM b/bl, Thumb bl/blx, raw
  literal, and pc-relative address building. Scripts are in the session scratchpad `r116\`.
- **Adopted:** by the manager on 2026-10-16. An Opus answer is the checked evidence; no second pass.

## OV116: M6-042, Term-time notifications (moves to IMPLEMENTATION_GAP; N12 waits on an operator decision)

**The candidate use-after-free is contradicted:**
- the callback cookie is leaked, never freed;
- Anki's HandleCallback is never taken at Term.

**Instead,** the first end-of-event notification fired during Wwise Term blocks the shutdown thread indefinitely on a
condition variable (N12). This is defined behaviour, not a crash, so the M1-034 standing rule doesn't cover it.

**Reachability:**
- **When N12 happens:** at Term, whenever a playing item with a context is still alive (an animation event with a
  callback, or a game event with a callbackId). That depends on runtime state, so whether it happens on a given shutdown
  is HARDWARE_ONLY.
- **Music:** MusicConductor's own posts have no context. A music event posted with a callbackId can still reach N12,
  through 0x97E7F4 in the music Term.
- **Ordering:** M6-032's destroy-lambda fault (inside 0xA40D44) comes before this block (0xA38890).
- **Shutdown input:** shutdown comes from the app's OnDisable → `cozmo_shutdown` (an existing app input, M5-055).

**Remainder (M6-043):** these were not read:
- N15: the vt[0] of the transition users created by 0x9F53E8, 0x9F566C, 0xA0DD78 and 0xA28AEC (0x9C9770 is read);
- 0xA01684's node vt+0x94;
- the PBI dtor 0x9FF54C and the derived PBI vt[0] overrides;
- the ~CozmoEngine members and ~CozmoAPI;
- a binary-wide scan for +0x38 writers.

## OV118: M6-041, the music stop tree (stays RECOVERABLE_GAP; first level read)

- **0x9854E0** (0x9854E0..0x9855AC):
  1. +0x24++;
  2. each child: vt+0x20 (0x984EEC, +0x24++), then vt+8(child, frame);
  3. a second pass, saving next first: child vt+0x24 (Release);
  4. frame ≠ −1 and frame < [+0x30] (unsigned) → store it;
  5. [+0x30] ≠ 0, nibble(+0x36) ≠ 0 and bit4 clear → nibble = 2 if ≤ 2 and **skip** vt+0x38; otherwise vt+0x38. At
     Term the frame is 0, so vt+0x38 runs;
  6. +0x24−−; at 0, destroy.
- **Destroy 0x9851A0 and Release 0x9857E8:**
  - with a parent: unlink from the parent's +0x18 list and do parent +0x24−−; at 0 the parent is destroyed first;
  - with no parent: 0x97E774(renderer 0x108D7D8, ctx);
  - then vt+0x28 and free.
- **The seven vt+0x38 bodies, first level:** 0x98233C, 0x984ED8, 0x990500, 0x990540, 0x998294, 0x999710, 0x99CDC8 (in
  the extractor's report).
- **0x97E774:**
  1. unlink ctx from the renderer list;
  2. holder = [ctx+0x38], null → return;
  3. if holder+0x28 (playingID) ≠ 0:
     - ctx+0x10 bit 0x200000 → 0x981F7C;
     - **0xA04DE8**([0x108D8F4], id, ctx+0xC), which can notify (N10);
     - ctx vt+0x58() ≠ 0 → result vt+0x9C(obj, 3);
  4. 0x983204(holder), free.
- **0xA36618:** search the users (+0x20, count +0x24); not found → 0x1D; found → swap with the last and count−−; at 0,
  state +0x30 = 6; return 1.
- **List-invariant M1-034 traps** (unreachable): 0x9833E0..0x9833E8, 0x9905D4..0x9905DC, 0x983244..0x98324C.
- **Unread:**
  - the seven vt+0x28 bodies: 0x984FB8, 0x98C248, 0x98C630, 0x998314, 0x9998A8, 0x99A000, 0x99AFA8;
  - 0x9828C4, 0x982EDC, vt+0x8C, 0x99D710, 0x99871C, and the 0x990570 element vt[0];

## Corrections

- **OV97 answer B7:** the 0x9D4228 call at 0xA4B74C is dead.
- **OV97 answer B11:** 0xA435FC takes the 64-bit device id and ignores the mask.
- **OV97 answer, the 0xA04F54 row:** it is the playing-item reference count (+0x1C) in the playing-manager hash. Its
  counterpart, 0xA04DE8, decrements the active count (+0x18).
- **Repo note `research/20260928-B-M6b-voice-callees.md`:** "[0x108DF4C] (bus array base)" is wrong. 0x108DF4C is the
  audio-thread id; the bus manager base is 0x108DF54. No record cites it.
- **M6-042's candidate M1-034 use-after-free is contradicted:** see N4, N11 and N12.
