## Object selection: stateful narrowing, predicate order and return value

When action+0x120 is nonzero, UpdateTracking constructs an otherwise empty BlockWorldFilter, sets its final halfword to 1 (byte +0x6C=1, origin mode +0x6D=0), fills three float bounds with **1000.0f / 0x447A0000**, constructs Radians from **pi_f / 0x40490FDB**, and calls FindLocatedClosestMatchingTypeHelper at 0x00567D1C with type action+0x11C and reference pose action+0x124. It publishes a nonnull selection's ObjectID before processing markers (0x00567D28..32, M13-036 ownership). The +0x120==0 path instead looks up its fixed ObjectID at 0x00567D98.

FindLocatedClosestMatchingTypeHelper copies the XYZ bound bits into local sp+0x78 and the Radians bound into sp+0x70, copies the caller's filter, and appends a heap-allocated callable with vtable 0x0102DE14+8. Its capture fields are type, reference-pose pointer, pointer to mutable XYZ bound, pointer to mutable Radians bound. It passes this filter to FindLocatedObjectHelper with an **empty callback and stop-on-first=false** (0x0061FC6E..7E), then returns that helper's raw selected pointer after cleanup. There is no independent scalar best-distance comparator in this wrapper.

The predicate (0x006281DA..0x00628264) dereferences the candidate, requires candidate+0x4C == captured ObjectType, initializes a zero delta vector and default Radians(0), calls candidate.GetPose().IsSameAs(referencePose, currentXYZBounds, currentAngleBound, deltaOut, angleOut), and accepts only return value 1. On acceptance it writes **vabs.f32(deltaOut.X/Y/Z)** into the shared XYZ bounds, computes angleOut.getAbsoluteVal(), copies that Radians result into the shared angular bound, and returns true. On failure it leaves the shared bounds unchanged. Thus it progressively changes the test applied to later candidates. It does not compare each candidate's norm to a single stored best norm.

FindLocatedObjectHelper is the native nested tree walk at 0x0061EB78..0x0061F030, already expanded in OV46 and reread for predicate order. For origin mode 0 it takes only the robot origin ID (0x0061EC22..26); then it walks family, type and object trees in their native in-order traversal and applies inclusion/exclusion sets followed by the callable list. The empty callback does not stop selection. With stop-on-first=false, it retains the **last candidate that passes the complete filter**, or null when none passes. This is not necessarily the first candidate or the globally smallest Euclidean-distance candidate. Equal accepted candidates can replace that pointer.

There is an additional order-sensitive effect. When filter+0x6C is set, this helper copies the predicate list and appends a final callable captured from **BlockWorld+0x90** (0x0061EB98..0x0061EBCE). Its actual operator at 0x00627EAA..B8 is the integer equality **candidate+0x1C == capturedWord**, not a >= comparison. The stateful closest predicate was already in the list, so it runs **before** this last predicate (list walk 0x0061ED50..70). A candidate can pass the pose/type test and narrow the shared bounds, then fail the observation-word equality and not become the returned selection. That narrowing is not rolled back. The TrackObject caller enables this exact path. Preserve the predicate order and mutation even for rejected final candidates.

The filter copy at 0x005C6A88 copies the tree sets, then copies the callable list at 0x005C6CE4, then copies the +0x6C/+0x6D halfword at 0x005C6CE8..EC. This is not rebuilding a fresh stateless predicate for every candidate. The closest predicate captures pointers to the wrapper's local bounds; copying its callable preserves those pointer captures.

## What IsSameAs actually tests

The no-ambiguity wrapper 0x00846EA4 delegates to IsSameAs_WithAmbiguity with a statically initialized empty RotationAmbiguities (ctor 0x0084B496 zeros begin/end/capacity and its bool). The full comparison body 0x00846F3C..0x008471FC was read.

It obtains a common pose frame using the parent / GetWithRespectTo paths, returning false if that conversion fails. A same-wrapper-address call returns true early without assigning output differences (0x0084700A); the predicate's candidate.GetPose wrapper and captured action pose normally have distinct addresses, so this is not assumed as its normal selection path. The ordinary path writes **f32(otherTranslation[k] - thisTranslation[k])** to deltaOut, in X/Y/Z order (0x00847016..52). It then chooses a translation criterion:

- Compute f32(Tx−Ty), take its absolute value by strict negative selection, compare with epsilon **0x3727C5AC** using `bpl`; do the same for Tx−Tz. Both absolute differences must be **strictly below epsilon** to select the sphere branch. Equal epsilon or unordered goes to the oriented component branch.
- Sphere: squared norm is f32(f32(dx*dx)+f32(dy*dy)), then add f32(dz*dz), compared against f32(Tx*Tx) (0x008470A4..D2). The `ble` acceptance branch includes equality and unordered. Do not rewrite it as a managed-language comparison that rejects NaN. All these products/sums are f32.
- Component branch: inverse of the candidate pose's quaternion rotation, then rotate delta, take f32 absolute values and reject an axis only on **ordered greater-than its bound** (`bgt` at 0x00847126). Equality and unordered do not reject at this gate. The output delta written before this branch remains the original common-frame delta; the rotated absolute temporary is used only for the gate.

For the component rotation, GetInverse copies the four f64 quaternion members and negates the last three in f64 (0x0084AD4A). Rotation3d::operator*(Point3f) narrows each of the four members from f64 to f32 in member order, then calls UnitQuaternion<float>::operator*(Point3f), whose complete 0x00849C1C..0x00849CFA body uses f32 products and explicit adds/subtracts. No f64 point-matrix multiplication or automatic quaternion normalization is inserted here. Preserve that instruction order rather than reassociating the expression.

The angular gate first tests **angleBound >= Radians(pi_f)** at 0x00847132..48. Radians >= is implemented as greater-than OR IsNear with epsilon, not plain >= (0x0084CCDC). If true, it accepts without computing/writing angleOut. Because the predicate initializes angleOut to zero each time, **the first successful pose match with the initial pi bound stores a zero angular bound for subsequent candidates**. This can happen even if that candidate later fails the appended observation-word filter. Do not substitute the actual first candidate's angular difference on this path.

Otherwise GetAngleDiffFrom writes angleOut (0x0084714A..5A) and comparison uses Radians <=, implemented by swapping arguments into >=. Radians greater-than checks positive raw f32 difference and excludes IsNear; IsNear rescales a copy of its first angle, subtracts the other in f32, rescales the difference, takes absolute values and compares **strictly less** than absolute epsilon (0x0084CC0A..5E). NaN does not satisfy the strict less-than; the raw positive-difference test also rejects unordered. Therefore do not reduce this gate to a raw <= or a blanket “NaNs always fail/always pass” rule across both position and angle gates.

GetAngleDiffFrom (0x0084A694) first compares all four f64 quaternion members for equality and returns Radians(0) if all equal. Otherwise it computes the f64 dot in member order: multiply components separately, add p0+p1, then p2, then p3; clamp using ordered branches against -1 and +1; compute in f64 `q = dot * (dot+dot) - 1`; call double acos, convert its result to f32, and construct/copy Radians. An unordered dot comparison keeps the -1 lower clamp, which then leads to acos(1); this is a concrete native branch, not an added invalid-quaternion policy. The empty ambiguity vector provides no alternate rotation candidates when the normal angular test fails.

## Marker collection and ranking

After selection the action copies the selected object's pose to **action+0x124** at 0x00567DB4, **before** collecting or validating markers. Failure later in the tick does not undo this reference-pose update. It requests GetObservedMarkers with the object's timestamp at +0x1C.

The collector 0x00876C50..0x00876C9C returns immediately when the requested timestamp is zero. Otherwise it traverses the object's marker list forward and appends each marker whose unsigned timestamp is **>= requested timestamp** (`blo` skips at 0x00876C6E). A zero timestamp is not a request for all markers. The returned order is list order; this routine does not sort by marker code or by distance.

An empty vector takes NoObservedMarkers. A nonempty vector starts the best squared XY distance at **FLT_MAX / 0x7F7FFFFF**, selected pointer=null and stored x/y/zOffset=0. For every marker in vector order:

1. Construct a temporary pose and compute marker pose (marker+4) with respect to Robot::GetPose at 0x00567E4C.
2. If that conversion fails, log PoseOriginError, set error state, destroy the temporary and abort the whole update, returning false. It does **not** continue to the next marker or use an earlier selected marker.
3. Load x and y from the resulting transform. Compute **dxy2=f32(f32(x*x)+f32(y*y))** at 0x00567E66..6E. Only ordered strict **dxy2 < best** replaces the selected marker (`bpl` at 0x00567E7A skips equality and unordered).
4. On replacement save x, y, dxy2 and **f32(z + -49.0f)** (literal 0xC2440000 at 0x00568180; add at 0x00567E90), plus the marker pointer. Continue forward.

This is a genuine scalar closest-by-XY-squared-distance choice, unlike the earlier object helper. Equal distances retain the first marker; a NaN, +infinity or exactly FLT_MAX does not beat the initial FLT_MAX. Overflowed squares can therefore leave a nonempty vector with no selected marker, reaching NoClosestMarker. Z is not used to select the marker. The finite x/y domain normally gives a nonnegative squared sum; no clamp or fallback is added if the arithmetic becomes nonfinite.

## Output angles: widths, frame and rescaling

If a marker was selected, the code computes and assigns the **second Radians&** first (head angle):

```
r = vsqrt.f32(bestXY2)
if r is NaN: r = sqrtf(bestXY2)  // 0x00567F06..1C
ratio = vdiv.f32(selectedZMinus49, r)
head = atanf(ratio)             // 0x00567F20..28
secondRadians = head           // float assignment at 0x00567F30
```

This is atanf of a quotient, not atan2f(z,r), and there is no zero-distance guard. For r=0, nonzero numerator yields signed infinity before atanf; zero/zero yields NaN. The float assignment helper stores the f32 value then invokes rescale using the destination's existing flag (0x0084C846). No f64 arithmetic is introduced in these marker-distance/head steps.

Then it computes body/pan for the **first Radians&**: local bearing=atan2f(selectedY, selectedX) at 0x00567F3C; obtains Robot::GetPose's quaternion rotation, calls GetAngleAroundZaxis at 0x00567F52; calls float+Radians with bearing and robot yaw at 0x00567F5C; copies the result to the first output at 0x00567F64. Thus pan is an absolute orientation in the robot pose's parent frame, built from robot-relative marker bearing plus robot yaw. It is not just the relative bearing and not a head-angle-to-world-pose solver. The reference object pose saved for next tick is independent of the chosen marker's pose.

Yaw's complete 0x0084AA1C..0x0084AABA body is mixed width. Let q0..q3 denote the four f64 members in storage order. Form the following f64 products and sums in the instruction order:

- A=q1*q1; B=q3*q3; C=q2*q2; D=q3*q0; E=q1*q2.
- L=A+B; M=C+B; N=E-D; P=E+D.
- u=f32(N+N); v=f32(1-(L+L)); w=f32(P+P); z=f32(1-(M+M)).
- In f32 form s=f32(f32(u*u)+f32(v*v)) and t=f32(f32(w*w)+f32(z*z)).
- If ordered t>s use atan2f(w,z); equality or unordered (`ble` 0x0084AA94) uses atan2f(-u,v), with the sign-bit flip on u. Construct Radians from the result.

The float+Radians helper first constructs/rescales a temporary from the bearing, then adds that f32 value to yaw in f32, sets its output flag=1 and rescales again (0x0084C97A..AC). Copy assignment carries both float and flag. It is not a single unconstrained f64 addition followed by one final cast.

Radians::rescale at 0x0084C87C..0x0084C938 returns immediately if flag=0. For flag=1, an angle in **(-pi_f,+pi_f]** returns unchanged. Outside it: when abs(angle)<10 it adds/subtracts f32 2*pi in loops, mapping -pi to +pi; otherwise it performs f32 divide by 2*pi, f32 add(-0.5), ceilf, conversion f32->signed32->f32, f32 multiply by 2*pi, and f32 subtraction from original angle. Unordered comparisons route to this latter arithmetic, rather than clamping/rejecting NaN. Parent code does not substitute a finite output for a NaN head or bearing.

**The third float& parameter is untouched throughout UpdateTracking.** It is not saved, loaded or written as an output in this body. Success returns true after assigning the two Radians values; all parent failure paths return false without assigning either angle. Object pose / published-ID writes that happened before marker failure remain, as described above. Calls that throw during assignment are ordinary exception paths, not a transactional rollback claim.
