## getMemberNames and CZString

getMemberNames checks Value type byte+8. Null (0) returns a vector with begin/end/capacity zero. Object (7) reserves using the tree size, starts at tree begin, copies each key, and follows the tree successor until end (0x008E6B9A..0x008E6C64). The key data pointer is node+0x10 and packed length/policy is node+0x14; copied length is word>>2 (0x008E6BD0..0x008E6BDE). Embedded zero bytes are retained in the result string. It does not call strlen, sort a vector after extraction or preserve JSON text insertion order. Successor descent is right child then its leftmost descendant, otherwise ascend parents until leaving a left child (0x008E6C16..0x008E6C34).

For any non-null, non-object type, build and throw Json::LogicError with the string `in Json::Value::getMemberNames(), value must be objectValue` (string starts 0x008E6DC4, call 0x008E6D08). This includes **empty arrays**, not only nonempty arrays; the guard reads type, not size. Construction/unwind cleanup releases local strings, stringbuf/locale/ios state; no substitute empty result and no direct log occurs. Malformed vision config reaching this throw is covered by M1-034's standing termination rule, with this owning record and crash/throw address retained; the report does not invent a defined native fallback.

CZString::operator< at 0x008E7E4C:

- If left data pointer is null (array index representation), unsigned-compare the raw +4 words (0x008E7E8C..0x008E7E96).
- Otherwise right data must be nonnull; null right throws LogicError `assert json failed` at 0x008E7EB6. No guessed mixed-representation ordering is permitted.
- For two strings, read lengths from +4>>2, call memcmp(left,right,min(lengths)) (0x008E7E5C..0x008E7E6C). Negative memcmp returns true. Zero memcmp returns whether left length<right length; positive returns false (0x008E7E70..0x008E7E98). Prefix-shorter keys precede longer keys. Comparison is unsigned-byte lexical order with explicit lengths, independent of phone locale and pointer addresses. Duplication-policy low bits are not part of string comparison.

The object lookup/insert path uses this comparator, e.g. string-key operator[] 0x008EAA88..0x008EAA98, then inserts at the tree position. This connects the comparator to getMemberNames' ascending traversal. Both directions of lookup and equality are named ordered-map interfaces; neither heap allocation nor JSON file key position chooses this iteration order.

## LoadRobotConfigs failure tail

The static filename is constructed as `config/engine/vision_config.json` (0x00522632..0x00522644; literal 0x00BE7FC0). At 0x0052266A..0x0052267C the loader supplies DataPlatform this+4, Scope1, that filename, and **the address of its existing +0x118 Value**. The value is initialized to Json null by the loader constructor at 0x0051EE7A..0x0051EE84.

On false return, sErrorF event `RobotDataLoader.VisionConfigJsonNotFound`, format `Vision Json config file %s not found or failed to parse`, with the relative filename as %s, occurs at 0x005226AA (event literal 0x00BE7FE1, format 0x00BE800A). Release logging field-vector storage, set global errG to1 and invoke sDebugBreakOnError only when enabled (0x005226AE..0x005226E8). Both failure and success converge at 0x005226EC, which calls LoadGameRequestAndTrickConfigs. **No return, config clear, default-resource read, retry, old-value restoration or success flag occurs in this branch.** A nearby Json::Value::clear at 0x0052260C belongs to the preceding config's failure path, not vision's.

DataPlatform's scoped overload resolves path then calls the path overload with the same destination (0x0084BFE4..0x0084BFEC). The path overload tries fopen(path,"r"), constructs Reader, and calls parse(stream,destination,true) at 0x0084C0C2. A failed open still reaches that parsing stage after setting stream failure state. On parser false, it emits error `DataPlatform.readAsJson`, `Failed to read [%s]` with **resolved path**, sets errG/optional break (0x0084C0E0..0x0084C120), obtains formatted reader errors, and, only when nonempty, emits channel `Unnamed`, debug event `DataPlatform.readAsJson`, `Json reader errors [%s]` (0x0084C124..0x0084C15C). It then closes stream/releases locals and returns saved parser result; no destination reset occurs. These lower-level logs precede the loader's VisionConfigJsonNotFound error. Exact formatted parser-error bytes depend on input/reader rules and are not guessed here.

Reader's stream overload reads bytes into a string and invokes pointer-range parse with the same destination (0x008E0938..0x008E098C). Pointer-range parse pushes that destination on its value stack and calls readValue, then returns the saved result without a transactional temporary/rollback (0x008E082C..0x008E0919). readObject replaces the destination with an object **before** completing its member loop (0x008E0F20..0x008E0F6A); parsed members can survive a later syntax error. Therefore “read failed, so vision config is always empty/null” is unsupported. The exact value passed to Init is the Reader-mutated loader+0x118, which can be a partial object. A preexisting loader value is likewise not explicitly preserved by the wrapper; what survives depends on how far parsing got.

Robot::Robot checks the DataPlatform pointer at 0x005103BC..0x005103BE. When nonnull it loads context+0x1C loader, adds0x118 and passes it directly to VisionComponent::Init (0x005103C0..0x005103CA). The Init result is ignored; ReadAllBackupDataFromRobot follows at 0x005103D4. Thus a failed config read does not itself prevent the Init call or the subsequent backup read.

VisionComponent::Init clears its initialized byte+0x10 before reading config (0x00650D20 onward). If the value has no usable ImageQuality.TimeBeforeErrorMessage_ms, its first missing-parameter path emits `VisionSystem.Init.MissingJsonParameter`, format `%s`, parameter `TimeBeforeErrorMessage_ms` (0x00650EA6..0x00650EAE), errG/optional break and returns1 through 0x00650FAC..0x00650FB2, leaving initialized byte zero. Preserve that **VisionSystem** event spelling even though this path is in VisionComponent. Other partial/wrong-kind inputs can fail later or throw; no universal “all parse failures take the first missing-field path” is claimed. Full VisionComponent/VisionSystem initialization remains M11-059.
