# OV04 — PreActionPose height-tolerance reader

Answers `requests/overnight/20261014-ov04-m12-038.md`. Research only; no implementation or manifest changes. Binary: shipped ARMv7 `libcozmoEngine.so` 3.4.0-1204, SHA-256 `02263c07f6bb60f4d7f351a3667dca84fd3e6c0fc6f838e18b5de7cf4e2989e1`. Native instructions are the evidence; decompilation and symbol names were navigation aids. Ranges below are half-open unless a single instruction is cited.

The current manifest says:

> M12-038, “The PreActionPose+0x14 height tolerance reader”, RECOVERABLE_GAP. Authority: “PreActionPose+0x14 is written by SetHeightTolerance 0x0050DAA4 (max|translation|/sqrt(3), 0x0050DB06) but no reader was found in GetCurrentPreActionPoses, the base IsPreActionPoseValid or IDockAction::GetPreActionPoses' compaction”. The important distinction is **copying the stored bits versus using them to make a decision**. There are confirmed readers of the first kind. The evidence here does not justify calling the field globally dead or substituting it for Ramp's literal.

## Search method and limits

Capstone Thumb mode with `skipdata=True` traversed every byte through `.text`'s exclusive end, producing 64,845 `.byte` directives rather than stopping at the first undecodable halfword. Candidate filtering was `mnemonic.startswith('vldr')` with a memory operand `[register,#0x14]`. Narrowing to an `s` destination and a base other than PC/SP leaves 260 candidates. The supplemental search checked every even byte offset for the Thumb VFP encoding prefix (`byte[1]==0xED`, immediate byte `byte[2]==5`), decoded four bytes there and applied the same scalar filter. Its one extra match crosses an established instruction boundary, as noted in the coverage table.

Separately, every indexed function whose name contains `PreActionPose` was decoded from its own entry with skipdata, searching all `#0x14` operands, not just VFP loads. This found copy operations and virtual-table accesses which the requested VFP-only search cannot find. The two compaction reads at +0x30 demonstrate why merely finding no `vldr +0x14` cannot establish non-use.

The scan is reproducible directly from the identified ELF; it does not depend on a shipped-file upload, runtime execution or an external disassembler service. Nearest-symbol attribution alone was **not** treated as a proof of operand type. The text section also contains embedded literals and code in other instruction modes; a raw Thumb match in those bytes can be a false positive.

## Reachability, build disposition and unread work

Pre-action construction, copying and docking are normal engine paths. Charger creation is on the normal BlockWorld construction path (`0x0061BE6E -> 0x0061BE80`, as traced in OV03). None of these observations relies on SDK mode. Ramp's validity function is present and its virtual dispatch was recovered, but a normal initial Ramp factory route has **not** been established: the identified clone call at `0x0050F89A` requires an existing Ramp. It would be unjustified to label Ramp either normally reachable or SDK-only from this evidence.

**Build rows:** preserve the exact f32 writer and bit-copy semantics; keep Ramp's literal comparison independent of the stored field; keep Charger forwarding to base. Do not add a height-tolerance decision based on its name. These are bounded, buildable findings. They do **not** by themselves move the whole M12-038 to IMPLEMENTATION_GAP: the global existence/non-existence of a decision reader remains RECOVERABLE_GAP.

**Contradictions:** the quoted manifest's “no reader ... in ... compaction” needs the decision/copy distinction: compaction demonstrably copies the field at `0x00550B52/0x00550B96`. This does not contradict a claim that compaction makes no decision from it. Its `max|translation|/sqrt(3)` wording also needs the literal-multiply detail if used as an arithmetic specification. No existing settled record is claimed contradicted without a current record quotation.

**New records:** none proven necessary merely by this search. If the manager separates this item, the confirmed writer/copy contract and the unresolved decision-reader search must remain visibly distinct; do not settle a whole-path claim while hiding the latter in prose. Ramp's normal factory reachability is also still open, already reported in OV03.

**Exact unread scope:** this report has not completed interprocedural base-register/alias proofs for every remaining scalar candidate, nor searches for all integer, multiple-register, SIMD, pre-adjusted-base or indirect getter forms across the entire binary.
