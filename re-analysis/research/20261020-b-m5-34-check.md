## What changed and why

The prior BeginWindow printed dense instructions and immediately started the
observation. Reading them consumed the brief interval. Its questions used internal
phase names and host millisecond ranges without explaining the answer choices.

The revised flow is: plain-language preview -> Enter when ready -> timestamped
START -> existing robot stimulus and existing observation duration -> END ->
numbered questions and optional notes. Every observation says where to look and
which questions follow. Blink, eye dart, whole-head motion and body/wheel movement
are distinguished. The loaded neutral-reference.svg comparison remains mandatory
where it previously was; the operator compares eye outlines without treating color
or scan-line appearance as an established firmware reference.

Automatic checks explicitly say NO ANSWER NEEDED. The optional notes prompt
invites the operator's own description. Not-seen, unclear and not-observed have
distinct definitions and are not presented as answers to avoid.

## Path, gates and cancellation review

Reviewed all five BeginWindow call sites and all AskWindow calls. The readiness
wait is before fromMs, activeObservationWindow and START. It is skipped under
--yes; interactive cancellation is checked before creating a new active window.
Actual start/end timestamps remain in the JSON, although they are removed from
the console instructions. EndWindow still precedes questions.

Canonical answer arrays, normalization, raw-answer retention, observation fields
and grader calls are unchanged. Numbered choices agree with the existing one-based
M3M4Hw.NormaliseAnswer behavior. No grade is relaxed; resting-eye, clip-stop,
body-wiggle and locked-head gates remain as before. Uncertain answers stay uncertain.

Two new cancellation points needed cleanup: LOCKED_HEAD has already acquired its
track lock, and PARAMETERS has already changed blink settings when the readiness
prompt is reached. Narrow catch-and-restore paths now unlock/restore if BeginWindow
throws. Their normal finally cleanup remains. LAYERS already encloses its prompt
in restoration cleanup; CANCEL and LIVE have not yet started their stimulus.
No scheduler lock is held while reading console input.

The only added user wait is outside the marked observation. There is no added
delay inside a sample window, RNG draw, altered robot command, production engine
edit or analysis change. The engine may naturally continue idle activity while
the operator reads; the prompts explicitly limit physical answers to START..END.
PARAMETERS' earlier diagnostic readback boundary remains unchanged.
