## Narrow checks

- **SetObjectPoseChanged:** does touch state/API. It drives configuration-cube rebuild, tallest-stack signal and the vtable+18 subscriber (`UNKNOWN` subscriber). Even a charger with a stationary pose can force rebuild (missing-entry branch in `DidAnyObjectsMovePastThreshold`). NOT "no effect." M13-040's open item about shared configuration/map/cache owners must be reconciled to this concrete boundary, not papered over as no-op.
- **M11-074 map continuations:** do touch state/API — the charger quads feed the platform-overlap test at 0x00513CD8 (steps 1-5 above) and the map cache decides whether the quad is re-derived. Effect on live traffic: yes (overlap decision). Keep as an M11 item; do not downgrade.
- **M12-001/M12-045 cached-pose destructor:** no demonstrated live effect. Candidate "no effect during items 1-4" (teardown-time owner), but **not proven** — there is no traced destructor range here; mark UNKNOWN and keep the record (reversible) rather than exclude.
- **Catch-all 0x004E65C6:** catches std::exception only, returns a zeroed/in-flight fallback (empty corners); not reachable with shipped objects on the platform path (no degenerate hull / fewer-than-3-point quarantined by M1-034 on malformed input). Probably no effect on robot traffic/API for shipped objects. Re-confirm with a hull/corner census if B-M13-14 wants full coverage.
- **Markerless footprint:** does reach the charger-platform test (located charger is Markerless on the operator's robots); its `GetBoundingQuadXY` (0x00502C32..70, re-root then pad) dictates whether the platform flag clears. Build obligation remains.

## Unknowns

- Ramp/HumanHead base class ancestry (Block vs ObservableObject) not from `known.py`/decomp (only `Block` and `MarkerlessObject` override GetBoundingQuadXY; Ramp and HumanHead don't show up). Own `known.py` search was performed; no overriding symbol present. Which base they inherit determines their footprint's re-rooting. Outside the located-charger path so classified "not reachable with shipped objects on the platform test; only on native objects placed physically on the charger."
- Catch-all exit value (empty quad vs logged MISSING) — the throw source (likely `std::bad_alloc` from a rejected cv::minAreaRect or heap overrun) was not isolated to a single preceding `throw` instruction at 0x004E65C6..C6 range; the answer's prior B-M13-11 check said convexHull total 0 returns empty, minAreaRect zeroes its result then proceeds; degeneracies caught by exception handling. Effect on robot traffic: an empty returned quad propagates to the platform-overlap helper as a zero-area region; that could keep `platform` true until real contact-loss? Mark UNKNOWN for exact worst-case; no shipped object tripped it in B-11's excluded-field test.
