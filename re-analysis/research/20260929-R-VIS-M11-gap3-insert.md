# R-VIS M11: PotentialObjectsForLocalizingTo::Insert / UseDiscardedObservation / LocalizeRobot and the confirmed-object pose refresh

Author: a `cozmo-verifier` subagent asked to verify and, where the extractor's rows were too coarse, extract the exact rules (M11-044). Text saved by the manager from its reply, 2026-09-29. Read from `resources/lib/armeabi-v7a/libcozmoEngine.so` (Thumb, capstone). Class legend: SRC = read here at the cited address; OTHER = body belongs to another layer, only its contract read; UNK = not read or name unknown. This is a single-pass reading by one agent: the addresses are checkable, but it has not had a second independent pass.

## 0. Verdict on the extractor rows (`20260929-R-VIS-M11-gap1-extraction.md`, 1A.1 to 1A.12)

All of 1A.1 to 1A.7 and 1A.9 to 1A.12 are PASS-equivalent at the cited addresses; the rows are too coarse to build from. Corrections and additions:
- **1A.2, this+0x10:** resolved in P0 (the name was UNKNOWN).
- **1A.4, byte names:** MovementComponent+0xA = !HEAD_IN_POS (status 0x200) and +0xC = ARE_WHEELS_MOVING (0x8000); the lift byte +0xB is not part of the gate (0x63E320..0x63E340; the M2 table in `re-analysis/inventory/M2-protocol.md` around line 505).
- **1A.3, gate evaluation:** IsPoseInWorldOrigin and CouldUse are called unconditionally at 0x50CE54 and 0x50CE5E, before any branch. The distance threshold is 250.0f (GetMaxLocalizationDistance_mm 0x4EF460: `movs r0,#0; movt r0,#0x437a`) plus 1e-5f (0x3727C5AC), compared in float32.
- **1A.5, tolerances:** both IsSameAs calls use Point3f(1,1,1) mm and Radians(0x3C8EFA35 = 0.0174533 = 1 deg). The first call takes HistRobotState* directly as a Pose3d, because HistRobotState+0 is its pose (ctor 0x5304B0 copies PoseBase to +0 and 0x5B bytes of RobotState to +0xC).
- **1A.7 alone does not answer "where is a confirmed object refreshed".** The only two callers of AddVisualObservation in the whole .so are AddAndUpdateObjects 0x620C94 and UseDiscardedObservation 0x50CDF6 (section 3).
- **The stationary test in 1A.5** is a refresh trigger for "the observed pose moved while the robot did not"; it is not a localization prerequisite.
- **Not in the extractor:** the CouldUse body, the WasCameraMoving body, the IsObjectConfirmedAtObservedPose body, and the AddAndUpdateObjects preamble (rows below).
- **1A.11 comparator:** confirmed `std::greater<float>` (demangled symbol at 0x50D5DC).

## 2. The flag bit is the pivot

- Insert's 5th argument is stored in pair+0x18, and it is the only thing UseDiscardedObservation tests.
- flag = 1 means AddAndUpdateObjects already called AddVisualObservation for this observation and it returned true. For other-origin objects the flag is forced to 1.
- flag = 0 means the confirmed-at-observed-pose shortcut skipped it; UseDiscarded is then the only place the AddVisualObservation happens.

## 3. End to end: a later sighting of an already-confirmed object C in the current origin

There are two disjoint cases at A2/A3.

**Case X.** IsObjectConfirmedAtObservedPose is true (0x50634C..0x5063C2): FindObjectMatchForObservation found C (its body 0x5063CC is OTHER, not read); confirmations[C][+0x24] count >= 2; the observed pose IsSameAs the reference pose (entry+0x18), using the observed object's tolerances: vfn(+0x30) = 0.8 * extent, so (35.2,35.2,35.2) mm for a cube, and vfn(+0x34) = pi/4. In Case X, AddVisualObservation is not called in AddAndUpdateObjects (flag = 0). Any refresh happens inside Insert:
- **X1.** Refresh via UseDiscarded when any of: dist > 250.00001; this+0x10 == 0 (robot localized and has not moved since); CouldUse == 0 (not resting flat or usable, is the dock object, is the MC+0x20 ID, or was tapped recently). Action: UseDiscarded(pair, WasCameraMoving(ts)) -> AddVisualObservation(observed, C, wcm, dist). Insert returns 0. [P2/P3]
- **X2.** Else, if head not in position, or wheels moving, or WasCameraMoving(ts): nothing. No refresh; Insert returns 0. [P4]
- **X3.** Else, if the robot poses at lastPoseUpdated and ts are the same (1 mm / 1 deg) and observed vs C differ (> 1 mm / 1 deg): UseDiscarded(pair, false) -> AddVisualObservation(observed, C, false, dist). Returns 0. [P5]
- **X4.** Else the pair is stored per root, nearest wins. The stored pair goes to LocalizeRobot -> LocalizeToObject: the robot is re-localized to C; C's pose and count are not touched. Losers of the per-root race are refreshed by UseDiscarded(pair, false) -> AddVisualObservation (a new loser only if in the world origin; a replaced old entry only if its key == the current origin). Insert returns 1. [P6]
- After Insert(M) returns 1, A6 runs other-origin objects with flag = 1: they can be stored or dropped, but UseDiscarded is a no-op for them.

**Case Y.** Not confirmed at the observed pose: A3 calls AddVisualObservation directly (bool = WasCameraMoving(ts), dist). If it returns false (count <= 1), the observed object is abandoned: no marker-time copy, no Insert, no occluders, no broadcast. If it returns true, flag = 1 and Insert runs with flag = 1, so UseDiscarded never calls AddVisualObservation again (P7).

**AddVisualObservation contract (0x50684C, OTHER = M11-007, read here).** For a found entry E whose pending pointer E[+0x34] is null (object already in the world): IsSameAs(observed pose, E reference pose, observed's tolerances) (0x5069C4..0x5069FC). Same: E count[+0x24]++; if the old count >= 1: UpdatePoseInInstance(this, C, observed, C, observedPose, bool, dist), then MapComponent::ClearRobotToMarkers(C) (0x506A72..0x506A98); if the old count < 1: nothing is applied. Not same: E count := 1 and E reference pose := observed pose; there is no UpdatePoseInInstance while the pending pointer is null. Tail: E[+0x28] := 0, E[+0x30] := observed[+0x1C]; it returns E count > 1 (0x506AA6..0x506ACA).

**UpdatePoseInInstance 0x505DE0 (OTHER, M11-007).** It writes the object's pose and PoseState (SetPose helper 0x50609C; ClampPoseToFlat for the docking object). On its applied path it also writes confirmations[C][+0x2C] := observed[+0x1C] (0x505FDC..0x505FE2), which is what Insert's GetLastPoseUpdatedTime reads. Internal conditions were not re-verified; seen: localize flag = !bool & connected/unique check & dist <= 250.00001 & Robot+0x355 == 0.

**State that changes.** On the Insert paths: the local pair map, the confirmations (via AddVisualObservation), C's pose and PoseState (via UpdatePoseInInstance), ClearRobotToMarkers, and on X4 the robot state via LocalizeToObject. Regardless of Insert's result: C[+0x1C], marker times, occluders, the observation broadcast, BlockWorld+0x54 and +0x58 (A5, A7).

## 4. Why the stack's BlockWorld stopped refreshing

- The stack reproduces the Case X shortcut (skip AddVisualObservation, matching A3) but has no Insert.
- So X1, X3 and the loser branches of X4 never call AddVisualObservation.
- In the engine the common steady state is X1: robot localized and stationary means this+0x10 == 0, so every sighting refreshes C through UseDiscarded.
- Stack comment for the tolerance: `cozmo-stack/src/Cozmo.Robot/Vision/BlockWorld.cs` line 500 (35.2 mm = 0.8 * 44, thunk 0x4E025C). Unbuilt markers are at BlockWorld.cs lines 1041 and 1050 (line 1041 also cites the Insert callers at 0x0062115E and 0x00621182).
