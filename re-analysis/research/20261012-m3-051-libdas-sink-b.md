## Entry and stored bytes

B01–B06: sink b admits level >= remoteMinLogLevel. Shipped `re-analysis/obb/assets/DASConfig.json` sets remote and local to `event` and supplies no local overrides, so both admit events, warnings and errors and reject debug/info. With overrides, only sink a uses the event-name override tree. Sink b also requires a configured singleton and zero disable mask. Sink a runs first, right-trims its own copy of text, and renders to Android logging. Sink b retains the original text and structured pairs; it does not serialize the rendered logcat line.

B02–B12: metadata is prepared on the caller before sink filtering. `$level` overwrites an entry-provided value, with strings `debug`, `info`, `event`, `warn`, `error`. `$ts` is generated only if absent from both globals and entry; generated value is signed decimal milliseconds from system_clock microseconds divided by 1000. The global snapshot uses TLS and a generation comparison; a stale snapshot is recopied under mutex 0x37054. It is captured at logging time, not reread when the queued entry executes.

B07–B10: the atomic sequence at 0x37110 is fetch-old/increment, unsigned 32-bit, with zero-initialized BSS storage; sequence allocation occurs only after the initial networking gate. Oversize drops later can leave sequence holes. Existing `$seq` is retained, although allocation still occurred. Event fields win over equal global keys because entry insertion precedes global insertion and existing nodes are not overwritten. The event name itself is the JSON key for original text; if that key already has a kv/global value, the original text is **appended** to it. `$data` is an ordinary string-valued member, not special framing or a nested JSON object. `$messv` defaults to `"1"`; a supplied value survives. Platform initialization can supply global `$messv="2"` (`0x12722..0x12726`), which therefore suppresses that fallback.

The caller thread ordinal is allocated and passed to B47C, but B09's capture contains no ordinal. There is **no automatically stored thread field**, file, source line or function field on this path. Any such key supplied by kv/globals survives by the general merge rule; it is not generated by sink b.

The exact stored framing is:

```text
{Q(k0):Q(v0),Q(k1):Q(v1),...,Q(kn):Q(vn)},
```

Here keys are in ascending native string-map order, not timestamp/level/event insertion order. All values, including time and sequence, are JSON **strings**. There are no spaces, newline, NUL terminator, enclosing array brackets, length prefix or binary header in the record bytes. For an illustrative entry with no other globals/kv, event `sample`, text `hello`, level event, time 123 and allocated sequence 0:

```text
{"$level":"event","$messv":"1","$seq":"0","$ts":"123","sample":"hello"},
```

This example illustrates framing; it is not an official capture or a complete app-global set.

`Q` uses shipped writer 0x1EFAC: surround with double quotes; escape quote/backslash and backspace/formfeed/newline/carriage-return/tab with their short JSON escapes; other bytes 0x00..0x1F become zero-padded four-digit hexadecimal `\u` escapes. Other bytes, including bytes >=0x80, pass through; slash is not escaped. It does not decode/re-encode Unicode code points. The no-escape fast path uses strlen; the escaping path uses the supplied length. Engine C-string entry values have already terminated at the first NUL. Compact flags are set by 0x1EC80, leaving spacing/comment flags clear. The JSON object writer enumerates member names in tree order (B11).

## Limits, files and flushes

B15: 150000 is `maxLogLength`, 5000 is `maxLogFiles`, 15 is `flushInterval`. They are **not an in-memory byte limit, an entry-count limit, and a batch size**. Configuration fallbacks are interval 5, max length 0x19000 (102400), max files 0x190 (400); shipped JSON overrides them. The byte cap is also copied to appender+0x10, used for B13's individual-message check; file owner+0xC is capped at 0x2E400 (189440). The task vectors dynamically allocate/grow; no configured 150000-byte or 5000-entry RAM-queue drop rule appears in B27/B28.

B13/B16: a serialized message **including its comma** >150000 is dropped with the native Android diagnostic; it never reaches the file queue or schedules the timer. Equality is accepted. Before writing, if current-count + next-message-bytes >150000, close/rename/reset/select-next-slot occurs. Equality stays in the existing file. The message is never split between files. The write task stream-flushes after each append and increments its signed-64 byte accounting by message length. This is a C++ stream flush, not an observed fsync or durability guarantee. Bad stream state/missing handle invokes the reopen path; file-open failures log errors rather than establishing successful persistence. The counter increment is not a durable-byte acknowledgement.

B17/B18: the engine supplies Scope 2 `DASLogs` as logDir; it is not a hardcoded absolute Android directory. Native appender mkdir mode is 0700, treating EEXIST as acceptable; another error leaves no file owner. Naming is `<logDir>/<slot padded to at least four decimal digits>.das_inprogress`, e.g. `0001.das_inprogress`, then `0001.das` on completion. Slots are modulo maxLogFiles, not timestamps or sequence numbers. Constructor starts its slot search at 1. Search skips occupied completed `.das`, configured archive-suffix variants, and `.das_inprogress` names; if every slot is occupied it returns the original candidate after the full cycle. Completion uses native rename; replacing an existing target is consequently a potential loss mechanism at saturation, not a chronological oldest-file purge. The active creation path uses open flags 0x241 (write/create/truncate), mode 0700, and regards fd >=1 as success (`0xE8A0..0xE8EA`). The current stream is opened for append through B18's helpers.

B19: startup posts recovery of existing regular files ending `das_inprogress`. Each noncurrent slot prefix is parsed with stoul base 10 and passed through the normal completion rename; current-slot file is skipped. This runs before the constructor's flush on the appender execution thread, using the file-owner queue. It is not safe to replace it with deleting all unfinished files. Malformed numeric names can enter native exception handling; no fabricated skip policy is proposed.

B20/B21: `DASForceFlushNow` checks the singleton and tail-calls B754. That builds an empty callback and **posts** the flush onto appender+0x2C; it does not wait for disk or transfer completion. Worker B8C0 clears timed-pending byte+0x14. When last-transfer-failed byte+0x15 is zero and a file owner exists, it posts rotation first. File rotation callback returns for zero current-byte count; otherwise it flushes then closes/renames/resets/selects the next slot (`0xFB2A..0xFB48`, `0xF0DC..0xF108`, B18). Unless paused, it then synchronously enumerates the file-owner queue, which orders that enumeration after preceding write/rotation posts.

An accepted record, after posting file append, requests a deadline only if networking is still enabled, pending+0x14 is zero, and interval+0x28 is nonzero. It sets pending and schedules system-clock now + interval*1,000,000; subsequent messages do not extend that deadline. The deadline callback invokes B8C0 directly on the appender execution thread. This is a deadline anchored to the first record after the previous flush, not a perpetually recurring 15-second timer. Force flush clears pending but the inspected path does not cancel an already scheduled deadline; do not assume timer cancellation/deduplication beyond that byte gate.

## Deletion and external boundary

B23–B26: enumeration collects d_type==8 regular entries, sorts native strings, optionally applies configured archive transformation, then processes names with case-sensitive suffix `das`. The callback result controls unlink; unlink failure emits a diagnostic and iteration obeys the shared stop flag. It is not an age-based delete rule.

Disabled network mask or pause → callback sets stop and returns false **before reading the file**. With the normal empty archive callback it remains on disk. New entries logged while disabled are dropped at B07; entries already captured can still write, because the worker's second mask check only gates timer scheduling. Disable does not clear queued tasks, erase files or wait for an in-progress attempt; enable merely clears requested bits and does not immediately drain the backlog. An already-running attempt has no rollback in these gates. Constructor initializes pause=true; pause true→false explicitly requests flush (B22).

Empty file and file >189440 return consumed without transfer. Valid nonempty file is read, its last byte removed **unconditionally**, and contents wrapped in `[`/`]`. The call at BA6C passes endpoint string, payload and response-output string to platform transfer 0x27C3C. This is the stopping boundary; HTTP/SQS/JNI request internals were not traced or invoked.

The return path matters locally: result==1 clears failure+0x15; any other result sets failure and stop. **Both converge to return true**, so the enumerator attempts to unlink the file even after failure, then stops before the next file. Later flushes suppress the preliminary rotation while failure remains set but still enumerate when unpaused. This report makes no assumption of server delivery or retry retention. Response text and optional recovery/failure DAS diagnostics are handled by BA70..BB88; those diagnostics can themselves enter the ordinary DAS path.

## Thread and input boundaries

B27–B29: appender dispatch owner+0x2C and file dispatch owner+0xE8 each construct two native threads: immediate execution and deadline management. Deadline thread moves due tasks into the immediate queue; it does not itself execute serialization/file callbacks. Execution swaps a batch under its queue mutex, unlocks, then invokes functions in batch order. Enumeration runs on the file execution worker; the appender worker waits for its synchronous dispatch result. Consequently the platform transfer boundary is reached on the file worker in this chain.

The engine logging caller performs pair construction, metadata/TLS/global snapshot work, sink-a logging, remote-singleton locking, map merge/copy, sequence allocation and async task posting. It can block on globals mutex 0x37054, sink-b singleton mutex 0x3703C, and the appender's immediate-queue mutex during posting. Allocation and the earlier Android log call also occur synchronously. It does not synchronously wait for the sink-b file write or transfer. `DASForceFlushNow` itself does not acquire the singleton mutex in the inspected exported wrapper. Disable/enable use plain mask read-modify-write, not the queue locks.

B30: startup reads the profile's DataCollectionEnabled Boolean and selects `DASEnableNetwork(2)` or `DASDisableNetwork(2)` at 0x00665C18..0x00665C26. The engine then calls DASConfigure at 0x00665CD6. This corrects §13.5's prose ordering, which says Configure then network selection. Enable clears supplied bits; disable ORs supplied bits; **any remaining bit blocks sink b**. A compatibility input must therefore name DataCollectionEnabled, and retain the native bit semantics, rather than claim “upload enabled” merely because bit 2 was cleared.
