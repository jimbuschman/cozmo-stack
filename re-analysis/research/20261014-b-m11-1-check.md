## Blocking

1. **CozmoRobot.cs:327, the FaceWorld hook.**
   - **The port:** it calls `Faces.OnRobotDelocalized()` = ClearAllFaces, which deletes every face and raises FaceDeleted
     events.
   - **The native body** (`FaceWorld::OnRobotDelocalized` 0x004F55E4..0x004F563A) only erases each face's viz object, if
     face+0x120 isn't the sentinel (EraseVizObject 0x004F5614), then stores the sentinel. Viz produces no output (V1–V6).
   - **Fix:** bind no observable body. Do nothing.
2. **VisionSystem.cs:665, the frame-mismatch Delocalize.**
   - **The port** passes `(s.Status&2)!=0`.
   - **The native** passes the actual carrying state (0x00512F82..0x00512F96: carrying+8 ≠ −1). Only the tread-boundary
     site uses status&2 (0x00512B98).
   - **Fix:** pass the carrying state on this path.
3. **Docking.cs:372/280/271, the put-down.**
   - **The port:** the attach parents the object's native pose to the lift and sets `NativeCarryingTree = true`, which
     nothing clears. On release, UpdateCarriedObjectPose returns early and MarkReleased writes only the PoseState, so **the
     placed cube keeps following the lift**.
   - **The native:** `CarryingComponent::SetCarriedObjectAsUnattached` (0x006333D4) re-expresses the object in the origin
     (GetWithRespectTo 0x00633442), then `AddRobotRelativeObservation(obj, newPose, state)` (0x00633458).
     `UnSetCarryingObjects` (0x00633C6A) warns if the object is still `IsChildOf(robot+0x2F0)`.
   - **Fix:** port the unattach: re-parent to the origin through GetWithRespectTo, call AddRobotRelativeObservation, and
     clear the flag. **Test:** a put-down cube no longer moves with the lift.
4. **A race** (Docking.cs:283-287, NativeDelocalization.cs:36-37, CozmoEngine.cs:1050).
   - **The worker side:** UpdateCarriedObjectPose runs on the vision worker (FrameProcessed). It writes MainPose and
     re-parents it to the current origin, reading `_nativeOrigins`.
   - **The message thread:** Delocalize and ComputeLiftPose write the same nodes and origins.
   - **No shared lock.** An interleaving loses the carried cube's move.
   - **The native** runs all of this on one thread (Robot::Update).
   - **Fix:** run it on the robot/message thread, or under one gate shared with Delocalize and ComputeLiftPose.
5. **VisionSystem.cs:106, NativeDelocalization.cs:15: the history binding.**
   - **The port** binds `History = robot.Engine.Robot?.PoseHistory ?? new RobotStateHistory()` once.
   - **After RemoveRobot then AddRobot,** vision-only states go to the new history while raw states and the cull go to
     the old one.
   - **The native** has one history (Robot+0x390): SetNewPose 0x00512708..0x0051271C, AddVisionOnlyState 0x005310D8.
   - **Fix:** read the robot's current history dynamically, or rebind on robot construction. No silent fallback.
