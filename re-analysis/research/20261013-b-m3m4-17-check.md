## Blocking

1. **The shared slot can leave a buried blended entry pointing at a freed node** (Lights.cs:1181, 829-833).
   - `list::assign` (0x006385B6) reuses nodes in order and erases the extra ones.
   - If a later, shorter blended play C replaces the slot while the buried entry A's iterator (info+0x10,
     0x00638698..0x006386A8) is past C's length, A points at a freed node.
   - The P3 resend (0x00637ACC..0x00637AE4) then reads `[r7+0x18]+0x14` from it, which is **undefined behaviour on the
     phone's heap**.
   - **It is reachable with shipped data:** A = SpeedTapWin (2 patterns) at index 1, then a non-blended B, then C = Flash
     (1 pattern), then C and B end.
   - **The stack** indexes past the end, throws inside `lock(_gate)`, and drops every queued send that tick, with no
     MISSING. This needs an operator ruling (M1-034-style), or a visible MISSING.
2. **An unsupported fallback for where cube lights load from** (CozmoAnimations.cs:383). `Options.ResourcesPath ??
   assetsRoot` is new: before, a null ResourcesPath meant no cube animations. The input is M3-062. Use it; don't fall
   back to the animation-assets argument.
