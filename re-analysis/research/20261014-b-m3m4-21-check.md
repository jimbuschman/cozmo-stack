## Blocking

1. **The advance through a dangling entry isn't covered** (Lights.cs:1172-1180).
   - **The setup:** after the P3 skip, the dangling entry stays on the stack.
   - **The native, next Update:** it reads `node->next` from the freed node (0x006379A6 `ldrd r0,r1,[r7,#0x18]`, then
     0x006379AA `ldr r0,[r0,#4]`). The Stop path (+0x41) also goes through 0x006379A6.
   - **The stack** advances silently: Index 2 isn't < Length, so the entry is popped, then NoAnimsLeftOnLayer, then the
     default. There's no M1-034 log.
   - **Fix:**
     - apply the same keyed skip and visible log at the advance/pop (and the Stop) of a dangling entry;
     - append 0x006379A6..0x006379AA to M4-045's `unresolved`;
     - test: one more tick after the skip asserts the log.
2. **The dangling test uses the slot's current length** (Lights.cs:1202).
   - **The problem:** `lower.Blended && (uint)lower.Index >= (uint)lower.Anim.Length` can't tell an entry whose node was
     freed by an earlier shrink. **This is reachable with shipped data:**
     1. A = SpeedTapWin, blended, at index 1;
     2. then B, non-blended;
     3. then Flash, blended. The slot shrinks to 1, which frees A's node 1 (0x006385B6);
     4. Flash ends, and B is resent;
     5. SpeedTapWin is played blended over B, which is allowed because B isn't blended. The slot grows back to 2;
     6. D ends, then B ends, and A surfaces with Index 1 < 2.

     The stack resends `slot[1]`. The native reads A's original freed node (0x00637ACC..0x00637AE4).
   - **Fix:** when an assign shortens the slot (0x006385B6), mark every buried blended entry whose index is at or past the
     new length as dangling (a per-entry flag or a slot generation). Use that mark at P3 and at the advance in finding 1,
     not the current length.
   - **Test:** the sequence above.
