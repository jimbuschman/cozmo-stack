## Summary for the manager (read this first)

1. The decode path is now read end to end for the shipped classes: the Vorbis block decode and frame loop `0xAB7E40` (V01..V04), the output hand-off `0xA73490` (V05), the packet-collection tails of the streamed class `0xAB1550` (V09) and the in-memory class `0xAB0448` (V10), the setup cache `0xAB2D74` (V11), the DSP allocation and teardown `0xAB3264`/`0xAB3428` (V12), the header walker `0x9CD340` (V15), the in-memory StartStream `0xAB0B20`/`0xAB0A30` (V17), the seek lookups `0xAB1020`/`0xAB04F0` and the start position `0xA736D4` (V19, V20), the loop/end slot `vt+0x74` (V07), and the ADPCM stream class `0xA73ABC`/`0xA73D34`/`0xA739E8` (A01..A05). PCM (`0xA75BC4`, `0xA75E34`, `0xA75B1C`) is read but no shipped bank has a PCM source.
2. What happens to the decoded floats: `0xAB7E40` allocates `channels*frames*4` bytes (16-aligned) from the pool and returns planar floats; `0xA73490` publishes that pointer in the io state (no copy), together with the frame count, the AkChannelConfig (+0x04), the position, the total and the media sample rate (+0x24), advances `[S+0x18]`, and decides the result: 0x2D, or the return of `vt+0x74` (0x11 at the end of a single play, 0x2D after a loop restart); the pitch node later releases the block through `vt+0xC`. Frames per call are the packet value (128/576 at 256/2048), not the 1024 the voice asks for.
3. The end of a single play is signalled with the LAST frames (0x11 from `vt+0x74` inside `0xA73490`), not by a following empty call. A stream that has run dry reports 0x2E.
4. The existing offline C# (WwiseVorbisNative / WwiseVorbisDecode / WwiseVorbisImdct) is a transliteration of `0xAB6380/0xAB63E0/0xAB3780/0xAB6B14/0xAB3520/0xAB5A94/0xAB3978` and an offline form of `0xAB7E40`; it does not cover the stream integration (V02, V05, V07..V12, V19, V20). Three more shipped files (one stereo, one 512/1024) were checked under the engine: whole-buffer and one-packet-per-call feeds give identical bytes and total frames equal the header SampleCount (section 8).
5. Contradictions with existing text: M6-002 evidence C13/C14.3 about the emit (it can store 0x11; +0x24 is the sample rate; +0x04 is the channel config), and inventory 6.12 (skip is the post-lookup leftover) (section 7).
6. Shipped reach (section 1): streamed Vorbis 1826+18 Cozmo, 96 SFX, 9 UI, 213 Music; in-memory Vorbis 27+1+4; ADPCM stream 333; PCM none; plug-in sources 27 Cozmo and others (not read); loop-restart paths 57 Sounds; start-offset paths only with a non-zero PBI start offset.
7. UNKNOWN or open: the callers of the source lifecycle slots, the `vt+0x88` call sites, the plug-in source bodies, readers of `[state+0x24]` (sections 6 and 9).

## 2. Vorbis: the engine's data path

Layouts (from the call sites and the stores). Streamed class: F = S+0x60 (the block `0xAB7E40` works on), D = S+0x70 (decoder state: argument of `0xAB3264/0xAB3244/0xAB3428`).
