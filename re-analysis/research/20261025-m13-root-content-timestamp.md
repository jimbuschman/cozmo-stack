## What this timestamp means

MemoryMap embeds its tree at +8 and root at map+58; root content data pointer is at map+DC. The getter returns that data's Last at +0C. It does not walk leaves. Last can therefore be older than some descendant data and is not a monotonic revision counter.

The constructor is a further clock owner: 00681384 loads Robot+2C, 00681386 stores Unknown type zero, 00681390 duplicates that timestamp into First/Last, and the stack data is passed to QuadTree ctor 00684C08. Root NodeContent construction copies the supplied data. Native initial Last is consequently not intrinsically zero.

For insertion, the assignment at 00686D3A happens after overlap/pointer guards but before the content override decision. “No geometry replaced”, false return, and unchanged dirty state do not establish unchanged Last. Conversely, pointer identity and no overlap can bypass the write. Auto-merge and subdivision introduce additional sharing/replacement effects. Merge preserves the source's clocks, not the destination's newest value. Transform does not contain a blanket assignment from Robot+2C: inspect the specific callable and its returned or mutated data.

These details explain the PARTIAL label. Root-pointer replacement, direct Last mutation and mutation of aliased content are three ways to change what +38 returns. The checked operation inventory establishes those mechanisms, but a universal negative about every other shared-data holder would need additional alias/callback closure. UNKNOWN is retained rather than equating root timestamp with a latest-observation aggregate.

## Readers and observable consequence

**Planner, ImportBlockworldObstaclesIfNeeded 004FD4B8/3410.** After its mutex gate it samples the current map's Last. Reimport occurs for `cached < sampled || !tightPadding`; this is an unsigned comparison, not inequality. Thus an older Last does not invalidate the tight import, while false tightPadding forces import even when the timestamp is unchanged. At 004FD5CE it caches the sampled value and proceeds to construct/import the obstacle environment. Tight padding selects 2/1; false selects 7/6. No-update returns without rebuilding. A failed mutex acquisition also skips import independently of Last.

The timestamp does not itself send a path message or launch an autonomous replan. This gate is encountered when the planner is asked to import/check/plan. It controls the obstacle snapshot subsequently used for safety and route decisions; robot path traffic is the downstream observable boundary owned by the planner records. A timestamp change alone is not evidence that a particular route or robot command must change. End-to-end proof of all replanning/message consequences is outside this bounded reader check and remains with M13-003 and related path records.

**BlockWorld's three sites.** All calculate a maximum and store +58. They do not test whether the sampled map timestamp differs, compare with old +58, or conditionally invoke replan/re-check from this numeric assignment. The first uses AddAndUpdateObjects' own frame argument; the latter two use Robot+2C. None computes max(old BlockWorld+58, new inputs), so these assignments should not be described as a monotonic world revision either.

Their directly established result is world last-change state.
