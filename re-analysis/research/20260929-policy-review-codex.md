## C records, highest impact first

1. **M8-004** — the simplified score-all manager changes which behavior runs; exactness requires the native activity/chooser and reaction-dispatch structure.
2. **M4-004 and M4-006** — live public motion calls add a calibration refusal and post-send wheel confirmation that the engine does not have.
3. **M8-008** — a failed/missing calibration report advances behavior after five seconds where the native action remains running.
4. **M8-009** — multi-resource behavior teardown order differs and can alter visible unlock/removal order.
5. **M9-016** — live singing uses a 66.67 ms render policy instead of the native 30,000-byte/+14-frame admission budget.
6. **M3-004** — the frame event is faithful, but the default live convenience call suppresses the first 15 accepted frames.

## Record text that contradicts or overstates the current code

- **M3-004:** the title says warm-up frames are “delivered like any other,” but `CozmoRobot.NextFrameAsync` defaults `includeWarmUp` to false and therefore suppresses them for the ordinary live convenience path (`CozmoRobot.cs:516-525`). The lower-level `FrameReceived` event does deliver them, so the record needs to name both seams.
- **M6-021:** the title says “WwiseSelection's constructor takes a seed.” The seed seam is now `WwiseRng(ulong)` (`WwiseSelection.cs:49-66`); `WwiseSelection` takes a `WwiseRng` object (`WwiseSelection.cs:511-517`). The behavior is as intended, but the record names the wrong constructor.
- **M1-022:** `EQUIVALENT_IMPLEMENTATION` currently covers both unshipped host socket realization **and shipped engine wrapper decisions**. The latter are cited instruction-for-instruction and appear reproduced; under “Exact, always,” they should be an exact record (or exact portion), with only the OS/socket implementation left equivalent.
- **M5-003:** likewise, the record labels all of shipped GetFaceHelper/Interpolate/Clip/Combine equivalent even though current code transcribes their native branches and tables. Only the unshipped `libm` realization justifies equivalence. Split/narrow the record or reclassify the shipped core after verification.
- **M11-013:** the title sounds like a general switch, while current code and inventory constrain it to offline tools and keep it false on the live path. The authority also admits the unconnected observation's native ObjectID origin is still UNKNOWN; the record should not imply that the type-derived ID is source-established.

No other reviewed record's descriptive text contradicted the current implementation at its named seam. This review does not approve or reclassify any manifest record.
