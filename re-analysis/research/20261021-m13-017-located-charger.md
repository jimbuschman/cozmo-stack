## Result and scope

Starting HEAD **d81d0213** (`R-M13-017` open in `jobs/QUEUE.md`, research row 24). The coverage table was opened before extraction. SetOnCharger, SetPoseOnCharger and the specified platform-step range were read fully from the `.so`; decompilation was used only to locate helpers. This report is authority-6 independent extraction until checked and adopted; no EXACT_SOURCE promotion is made.

The missing behavior is a **contact-on observation join**, not a one-time synthetic charger spawn and not localization to the charger. An existing located charger is updated on every true state; a newly created one gets a normal object ID and a Known root-relative pose through the world/confirmer machinery. The old rising-edge wording in the request and stack accurately points to the first opportunity to create it, but is insufficient as the implementation rule.

The transform must use the engine's existing pose helpers and the actual parent node. A3's charger-relative-to-robot transform and D3's robot-relative-to-charger transform both use the source pi and 30 mm constants; that does not authorize replacing either with a hand-written inverse or idealized yaw arithmetic. Shared quaternion/tree arithmetic remains M11-065/066/067. The geometry constructor 0x00846A84..AC6 reads the translation words, constructs Rotation3d, and passes transform/parent/name to PoseBase; it does not make a new world origin.

Failure boundary: SetOnCharger does not check AddRobotRelativeObservation's return at 0x00511B4C (that helper returns 0 at 0x00506C44). The supported type13 factory branch constructs Charger; the caller does not have a graceful allocation-failure alternative (a null object later reaches the vtable load at 0x00511B36). Do not invent an original success/failure fallback there; original faults follow M1-034. By contrast, D2's missing/wrong-kind charger warning and result1, and D4's failed history result, are defined behavior. Robot::GetPose's root checks log but return the owned pose; they do not silently choose an identity origin.

On a normal true rising state, source order is:

1. Locate/create/update charger and execute the world/map/light notification chain.
2. Update confirmer reference/count/timestamp, destroy the temporary filter/pose.
3. Platform=true store → external platform event(true) → threshold-send(50) → tracker hook.
4. DAS on-charger → external ChargerEvent(true).
5. Contacts=true store.

The source calls external delivery before the reliable threshold-send request. The stack's approved deferred app delivery can run a public callback later; a regression must distinguish the source enqueue points from the wall-clock order of public callback execution and network transmission. Do not implement a user callback under an engine/world lock merely to reproduce the native call order.

After contact-off, order is DAS off-charger → ChargerEvent(false) → contact-byte clear; the platform stays set. On a subsequent normal OnTreads engine tick, the geometry test controls its clear. With intersections still true there is no platform-change output. Once false, platform=false store → platform event(false) → threshold-send(400) → tracker hook. A contact-on tick can request false geometrically but the setter's contacts-OR holds the flag true. No new timer, center-distance cutoff or extra 50 mm wait belongs to this platform rule; the separate sourced distance accumulator and other threshold writers remain M4-019's.

## Regression design requested by item 6

No production code or test was changed/run by this extraction. Proposed tests are source-backed scenarios for a separate approved builder, using the real engine/world owner and received full RobotState messages:

1. **No located or connected charger; origin/pose already live.** Start synced, OnTreads, platform=false, with a valid current robot origin and a deliberately nontrivial **prior** robot pose. Receive contact-on. Assert exactly one type13/family4 charger in the current origin, Known, ID from the real unique-ID owner, flattened native pose matching A3/A6 and parent=current origin. Assert its confirmer count/reference and timestamp rule. Observe that world pose notifications occur before platform/event outputs. This must not call a test seam that inserts the charger directly.
2. **Continued contact.** Receive another contact-on. Assert same ID/object, pose observation repeated, no second edge platform event or ChargerEvent. Deliberately change the owned robot pose between states to expose an implementation that gates A3–A9 on rising only. Verify world notification semantics rather than expecting a second first-location event.
3. **Contact-off while overlapping.** Receive contact-off through the same route. Assert ChargerEvent(false) and contacts clear, located charger retained. Run the normal engine tick with footprints still intersecting: platform stays true, no platform-owned threshold400. Assert charger pose is fixed in the origin when the robot moves; it must not follow a still-parented robot node. Keep the separate distance/stats threshold writers from being the trigger for the assertion.
4. **Footprint exit.** Feed/commit a robot pose whose **real** robot quad no longer intersects the charger quad, then run the actual tick hook. Assert platform false, platform-change enqueue before reliable threshold400 send-request, tracker hook after; repeat tick adds no transition. Use native/intersection-backed geometry with clear overlap/separation, not an invented center cutoff or camera sighting. Public callback delivery is assessed under the approved app queue semantics, not as synchronous native callbacks.
5. **Reuse branches.** Existing located charger in current origin gets observed again without a new object. Connected-only charger supplies ObjectID to a new located instance. Charger located only in an old origin does not satisfy A4. These guard identity/origin ownership and prevent a hardcoded ID from passing case1.
6. **Separate mount test.** Receive contacts during BackupOntoChargerAction with the mount's saved ID. D2 success changes robot pose/frame/history; wrong/missing ID warns/returns1 internally while the backup caller still returns0. No synthetic SetLocalizedTo(true), new origin or contact-event replay is expected. Keep this separately scoped from fixing the contact-on world join.
