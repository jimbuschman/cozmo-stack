## Existing records contradicted by the source
- **M13-014, unresolved (3)** ("'ends without a verified face' is mapped to 'no fresh observation of the face after the turn'"): verified = `SmartFaceID(this+0x18C)` valid, set only by the RobotObservedFace handler while state <= 1, so observations received during the turn count (`0x0054C050..0x0054C19E`).
- **M13-014, the NO_FACE / NoFace question** (unresolved 2), and the effect text "nonzero returns NO_FACE 0x0300000E when no face pose is found": correct for `+0x193` set. For `+0x193` clear the original returns **SUCCESS**, not any NO_FACE (`0x0054BEB6..0x0054BEBC`). The repo's `FaceActionResult.NoFace = 0x0300000B` is MISMATCHED_UP_AXIS in `ActionResult.cs`.
- **M13-014, unresolved (1)** (id 0 "keeps the -1 last observed face"): id 0 is the invalid SmartFaceID and selects `FaceWorld::GetLastObservedFace(pose, false)`.
- **M13-007, unresolved** (stand-in "centre-within-half-a-cube"): the real test is `Quadrilateral::Intersects` on min-area-rectangle footprints.
- **M13-020 authority** (mostly right): its unresolved (4) ("TurnTowardsPoseAction::Init not part of this record") is now read (Q4). Its unresolved (1) ("children are M13-021") is answered in Q5.
