## AddRobotRelativeObservation(obj, pose, state)

The B rows (0x00506B78..0x00506C48):

- **B1:**
  1. copy the pose;
  2. SetParent(copy, Robot::GetPose());
  3. GetWithRespectToRoot (R37);
  4. operator= into the copy.

  The copy is now parented to the **world origin**.
- **B2:** if the object is in BlockWorld: SetPoseHelper(this, &obj, pose, −1.0f, state, "AddRobotRelativeObservation")
  (0x0050609C).
- **B3, SetPoseHelper with state 2:**
  1. if robot+0x2B8 == obj+0x18, Robot::SetLocalizedTo(nullptr);
  2. copy the old pose and the old state;
  3. vtable+0x28 SetPose(pose, −1.0f, 2);
  4. BroadcastObjectPoseChanged(obj, &oldPose, oldState) (0x005060FA).
- **B4, SetPose for cubes** (ActiveCube thunk 0x004E022A → ActionableObject::SetPose 0x004E01E4):
  1. clear the six cached pre-action-pose vectors (+0x28..+0x70);
  2. ObservableObject::SetPose 0x004EF580, which runs Vision SetPose 0x004EF590:
     - `_pose` = the new pose (operator=, so its name gets "_COPY");
     - the state at +0x24;
     - SetName("Object_" + id). The string-helper bodies are unread;
     - fromDistance is stored only when ≥ 0, so −1 isn't stored;
  3. then strb 1 at +0x50 (field identity unread).
- **B5:** the not-in-BlockWorld branch is **unreachable** from this path.
- **B6, the confirmer:** `_poseConfirmations[obj+0x14]` with node+0x24 = 1, node+0x18 = the root-relative pose,
  node+0x2C = obj+0x1C. Return 0.
- **B7, compared with AddLiftRelativeObservation** (OV01): that one does no lookup and no re-parent, sets Known (1), and
  stores the lift-relative pose.
