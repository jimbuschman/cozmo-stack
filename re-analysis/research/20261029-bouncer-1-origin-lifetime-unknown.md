## Answer

**A native parent edge strongly retains the selected origin node/control block, but does NOT increment that node's logical PoseBase-wrapper owner count.** It is neither weak nor a raw borrowed pointer. It therefore keeps the origin allocation and its parent chain alive after an origin PoseBase wrapper is released, while still allowing logical Owners to reach zero and the defined owner diagnostics to occur.

A FindRoot/WrapExistingNode wrapper is a DIFFERENT ownership relation: it adds a shared strong reference **and** increments logical Owners. Allocation retention alone does not make that relation interchangeable with the parent edge. An extra wrapper can change when Owners reaches zero, whether NotLastOwner/UnownedParent runs, and whether the zero-owner transition happens inside or outside the origin-list teardown's AllowUnownedParents interval. This report establishes that native distinction; it does not prescribe a C# representation.

There is **no demonstrated dangling-parent/UB case here**. Native child references keep the allocation valid; a logical-unowned parent is a defined VERIFY-and-continue situation. M1-034 is not grounds to skip it. Existing null-node GetParent/WrapExisting crashes are different paths and are not reached merely because a valid origin wrapper's Owners becomes zero.

## Lifetime implication for this selected-origin interface

The earlier checked face contract installs parent(selected historical origin) into the stored HeadPose node. L1-L3 show that relation alone retains origin allocation. It does not need an artificial PoseBase logical-owner increment merely to keep the node from becoming dangling. As long as any child/control strong reference remains, releasing another wrapper cannot hit shared on_zero_shared. The eventual final strong-reference release, not the logical Owners transition, is what reaches the allocation's on_zero_shared callback.

The exact final PoseTreeNode destruction/control callback and all production owner-release edges remain the current M11-077/M11-084 gaps; this report does not certify them. The decisive bounded result does not need those final leaves: L3 proves the callback is deferred while the installed child strong reference exists. The selected origin still has its own origin-list PoseBase owner during normal list lifetime; the checked list destructor is an explicit release edge that temporarily permits unowned parents. There is no per-face “origin retired because face no longer visible” step in any inspected caller or parent primitive. No broader origin-retirement census is inferred.

An additional live FindRoot wrapper would retain a particular root node's identity/ancestry as already established in the origin supplement, but it also adds Owners through L6. Native parent retention is not a wrapper. Whether a proposed auxiliary wrapper changes an observable diagnostic depends on its actual creation/release edge relative to native origin owners; that is a concrete production-lifetime comparison for the manager's C# audit, not settled by allocation survival. No whole pose-tree ownership rewrite or new compatibility policy is established by this read.
