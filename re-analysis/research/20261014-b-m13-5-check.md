## Blocking

1. **A fresh plan leaves `_total = null`** (NativeLatticePlannerRuntime.cs:81, 91-96, 161).
   - **What the native does on the force path:**
     - it clears the actions, then jumps to 0x004FECDA (0x004FEBD2);
     - at 0x004FECDA..0x004FECF6 it still assigns the total from the local prefix: start from sp+0x1F0 (zeroed at
       0x004FEB6C..0x004FEB7C) into +0xAC, and the empty action vector into +0xB4;
     - so the total becomes an **empty plan with start (0,0,0)**. It is never absent.
     - Only PlanIsSafe and OldPlanUnsafe are skipped.
   - **The port** returns false silently on `_total is null`, a path the native doesn't have.
   - **What the native GetCompletePath does instead:** it checks only status 0 and 1 (0x004FFB74..0x004FFB88), then
     FindClosest on the empty plan gives index 0 and FLT_MAX (0x008569A4..0x008569BA). Then:
     - Info "Robot is %f from the plan, at index %d" (0x004FFBF2);
     - the RobotPositionError sEvent (0x004FFDE4);
     - clear, then status 0 (0x004FFE2A);
     - return 0.
   - **Reachable:** a drive whose goal is the start. DoPlanning stores status 3 for an empty plan (0x00500212 →
     0x00500590), and Read calls GetCompletePath for status 2 or 3.
   - **Fix:** on the force path, set `_total` to an empty plan with the default (zeroed) start, and skip only PlanIsSafe
     and OldPlanUnsafe.
   - **Test:** a fresh ComputePath reaching status 3, then GetCompletePath:
     - the Offset Info with FLT_MAX at index 0;
     - the RobotPositionError MISSING;
     - Publish(0);
     - false.
