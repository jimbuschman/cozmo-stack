## 0. Findings first

1. **Nothing on main builds the path.** No non-test code constructs `WwiseEventRuntime`, `WwisePlaybackBridge`, `WwisePlaybackLimiter`, `WwiseVoiceLinker`, `WwiseVoiceBusPass` or `WwiseVoiceEngine` (grep over `src`: only tests and the WIP composition). `RuntimeNodeOf` has 10 references and no assignment anywhere in `src`; `WwiseRoutingNode` is constructed only inside `WwiseBusWalk.cs`. The WIP composition (806 lines) predates batches 5a..5h: it installs throwing seams for bodies main now builds (`NodeVt84A9F1F80`, `InitSource9BEB30`, `BeforePlayA00618`, `TailA01918`, `TailCtxVt24/28`, `Call9BDA28`, `Call9E808C`, `SetupFadeInTransition`, `TransitionA366AC`, `SourceInfoA1EC54`) and never sets `PlayPath`, `MediaTable`, `RtpcListeners`, `RuntimeNodeOf`, `StreamingFor`, `CtxNodeChainFlag9BC90C`; building it today would throw earlier than its `UnreadBodies` list says.
2. **A concrete shipped Sound** (section 1): event `Play__Robot_VO__QA_React_Pickup_Angry_2` (188399711) -> Sound 957475640 (Vorbis `0x40001`, stream type 1, media 456005573, prefetch 2786 B) -> ActorMixer 13023553 -> root ActorMixer 62050212. The root carries the Compressor in FX slot 0, an LPF property of 15.0, volume -2.0, the `event_volume` RTPC on parameter 0, positioning byte 0xC3 and a **max-instances limit of 1 (global)**. It exercises the Compressor, an active filter A, the event_volume RTPC and the limiter creation with a subscription.
3. **The first seam every play under 62050212 reaches once the PBI exists is the limiter's own `0xA19ECC` subscription** (`WwisePlaybackLimiter.cs:440`, thrown in `CreateLimiter`). `Cozmo.bnk` root 62050212 has advanced-settings bytes `04 01 01 00 00 00` (max instances 1, global flag); the engine calls `0xA19ECC(limiter+0x10, node, &{0x10000,0}, 1)` at 0x9F2CCC..0x9F2CE8 and the node argument is the node itself (`r1 = r6`, the argument of `0x9F29E8`), which the inventory called unread (T-L1). 1872 Cozmo Sounds are under it (1862 directly, 10 under RanSeq 461334142); the only other Cozmo node with a limit is ActorMixer 66225135 (max 5, under 682998829).
4. **`CtxNodeChainFlag9BC90C` is false for every shipped chain.** The C# doc names `0x9F68D8/0x9F6B44/0x9F627C/0x9F6DB4` as writers of `[node+0x40]` bits 17..19: those four write `[node+0x45]` / `[node+0x47]` bits (advanced-settings setters). The only writer of `0xE0000` is the Bus loader (`0x9C6540 orrne r2,r2,#0xe0000`, byte C bit 0); a scan of every ARM `orr/bic/bfi` on a `[x+0x40]` word finds no other. All 15 shipped buses (Init.bnk is the only bank with HIRC type 8) have byte C = 2 (bit 0 clear) (T-N1).
5. **The writers of the playing-id entry fields are found.** `0xA03108` (called from `0x9A0EF8`, from AK `PostEvent 0x9A6704`) writes `[item+0x20]` event id, `[+0x24]` game object id, `[+0x28]` external-source holder, `[+0x3C]` playing id, `[+0x40]` callback, `[+0x44]` cookie, `[+0x48]` flags (masked when the callback is null), `[+0x18] = 0`, `[+0x1C] = 1` (T-E1). The Anki wrapper `0x8D8CE4` passes flags only from {0,1,4,5,8,9,12,13}, so `[pbi+4]` never has `0x100000`: **`[state+0x1C]`, `0xA05574` and the play-position repository are unreachable on the Cozmo path**, and `0xA0428C` never calls anything (T-E4).
6. **Robot audio reaches Robot_Bus_N only through the aux-send route, and that route has no C#.** Anki posts `SetGameObjectAuxSendValues(go, [{Robot_Bus_N, 1.0}])` and `SetGameObjectOutputBusVolume(go, 0.0)` (the dry path is muted) as queued messages 0x12 / 0x13 that the C# runtime never pumps. Engine: handler `0x9AEDE0` -> `0xA0CAFC` -> `0xA0BA3C` stores `[GO+0x24..0x40]`; per voice `0xA4B93C` -> `0x9BDA88` -> `0x9BD368` (builds `{busId, linear gain, kind}` from `[GO+0x24..]` and the node's user aux fields) -> `0x9D4228` (merge into `voice+0x2C`) -> `0x9D4108` -> `0xA43434` (find or create the Robot_Bus line, make an aux connection with `[conn+0x68] != 0`) -> aux walk `0xA447D8..0xA44898` (sums the entries whose id equals `0xA68A2C(line+0x4C)`) -> `0xA4FBEC`. I read all of these and verified `0x9BD368` (600 cases) and `0x9D4228` (800 cases) under EMU (T-A1..T-A8). Shipped data: the root aux byte is 2 (use game-defined aux sends), so `[ctx+0x88] = 1` for 2196 of 2231 Cozmo Sounds (T-A3). The C# models `0x9D4228` as a gather over the 0x4C-byte table `[voice+0x10]` (`GatherAndDispatch`); the engine's arguments are `voice+0x2C` (0x14-byte entries, count `[voice+0xCC]`), a different array.
7. **The V7 state machine is modelled on the wrong object.** `0xA54F1C` loads `r6 = [[voice+0xD4]+0xC]` (the owner PBI, 0xA54F20..0xA54F2C) and reads `[r6+0x1F8]`, `[r6+0x54]`, `[r6+0x11C]`, `[r6+0x164]`, `[r6+0x1D8]` and calls `[r6]->vt+0x3C`. `WwiseVoiceBusPass.RunVoiceStateMachine` (`WwiseVoiceBusEngine.cs:1580`) takes `voice.PrimaryBus`, a `WwiseMixBus` (the first connection's line), and reads `NextSourceParam`, `Gain54`, `Gain11C`, `SampleScale164`, `FrameBudget` (`WwiseBusLifetime.cs:205..291`) from it. The same engine words are `pbi.Field1F8` and `pbi.StartOffset` ([pbi+0x1D8]) elsewhere in the C#. The origin is the earlier extraction's label "bus" for `[source+0xC]`.
8. **No path from a bus's FX list to a line's FX slots.** `WwiseVoiceLinker.InitLine` builds the line with `Array.Empty<WwiseBusFxSlot>()` (`WwiseVoiceLinker.cs:821`) and `WwiseMixBus._slots` is readonly; the engine creates the Robot_Bus EQ/EQ/Limiter/Hijack chain lazily through `0xA4F754 -> 0xA4E974` from `[bus+0x28]` at the first bus pass (report 8 B-04). `WwiseBusChain` is used only by the offline singing renderer; `WwiseHijackPlugin.Create` has no production caller. The Hijack's plug-in id is `[[HijackFx+0xA0]+4]` = the first u32 of the FxCustom parameter block (T-H1).
9. **`0xA56A7C` is not about positioned sounds.** `[pbi+0x34]` is the pointer to the PBI's modulator-record list: `0xA56A7C` walks it with `0x9E8114/0x9E8248/0x9E83FC` (0xA56AC4..0xA56B90), `0x9E62AC(..., pbi+0x34)` fills it, and the C# own `ConsumeModulatorsA01918` uses `Field34` that way. It is reached only for PBIs with modulator records (the 57 shipped Cozmo Sounds under modulator-bound RTPCs, live-bodies-4 R9). The earlier text "[pbi+0x34] is null for non-positioned sounds" (live-bodies-8 V2-09; C# message at `WwiseVoiceBusEngine.cs:902`) is wrong.
10. **Filters A and B process `u16 [S+0xE]` frames, not `u16 [S+0xC]`.** `0xA766F0` loads `ldrh r3,[fp,#0xe]` (0xA76A24, 0xA76D54), the planar stride `[S+0xC]*4` (0xA76A5C..0xA76A68) and the channel count byte `[S+4]` (0xA76A18). The C# (`WwiseVoiceBusEngine.cs:865`) passes `Math.Min(MaxFrames, ...)`, the `[S+0xC]` extent.
11. **The Compressor (1872 Cozmo Sounds) is read except its stereo-linked worker.** Init `0xA9FB28`, the Execute wrapper `0xA9FC70` and the per-channel worker `0xAA0298` (the one mono and unlinked stereo use) are transcribed and verified bit-exact under EMU (400 + 600 cases, 31,501 samples). The linked worker `0xA9FEEC` is read at control-flow level only (T-F1..T-F8).
12. Other answers: PBI Term callers (T-N4); creation of subscription registries `0xA1A338` (T-L3); the bus-volume-callback tables are always empty (no caller of the registration); `0xA549A0`'s only caller is the pending-source arm `0xA52C9C` (T-V3).
