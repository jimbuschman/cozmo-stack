# Audit of the settled M7 and M8 records (2026-09-29)

The manager ran three independent `cozmo-verifier` passes (Claude) over the 22 records that DeepSeek build jobs
settled as EXACT_SOURCE in M7-behaviour and M8-framework (B-M7, R-BEH). Each pass:
- opened the cited addresses in `libcozmoEngine.so`;
- compared the C# with them;
- checked that the whole claimed production path is recorded;
- checked the tests for circularity.

The manager then re-checked the central claims in the binary and the code (below).

## What the manager checked in the binary

- `IdleBehavior` is constructed only in `Cozmo.Conformance/Behavior.cs:54`.
- `UpdateLiveAnimationLocked` returns at once when `StreamLive`'s lock is on top, and `StreamLive` pushes ProceduralLive
  itself (`AnimationScheduler.cs`).
- `AddOrUpdateEyeShift` 0x0064F3C8 calls `AddToPersistentLayer` (0x0064F41A) and `AddPersistentLayer` (0x0064F472).
- The ReactToImpact vtable slot 0x0102BEE0 is 0x00606487: `movs r0,#1; bx lr`.
- The BehaviorPlayAnimSequence vtable relocation at 0x01026968 (vptr+0x48) is `InitInternal`; the IBehavior base slot
  is `__cxa_pure_virtual`.
- StopActing: `movs r1,#0; ldr.w r2,[r0,#0x80]; blx r2` (0x005BD358..0x005BD360). `ScoredActingStateChanged` does
  `movs r1,#0; str.w r1,[r0,#0x104]` (0x005BF044..0x005BF046).
- IActionRunner::Update, tracks locked: `movs r6,#0x19; movt r6,#0x300; str r6,[r4,#0x18]` (0x00540572..0x0054057C).

All hold.

## The pattern

The DeepSeek verifier passed these builds, and the tests are green: 47, 63 and 52 tests in the three areas. But
several tests assert the contradicted behaviour, and the rest don't reach the defects. The settlements rested on
source-backed constants, with wrong structure between them: slot identities, the gates around a path, and which code
path is the production one. That is the `Current warning` failure mode in AGENTS.md. The remaining DeepSeek-settled
layers (M5, M9, M10, M11..M15) should get the same audit, one layer at a time, when each layer is free.
