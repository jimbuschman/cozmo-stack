## 3. M3-041 L30: the libc++ numeric formatter (libc++_shared.so)

### Record quoted

M3-041, RECOVERABLE_GAP, "IMU diagnostic chunk reception, file logging and stream close on robot removal". unresolved: "Rows L1-L36 adopted (manager, 2026-10-10, jobs/B-M3M4.md), except L30: every float and filename number goes through the packaged libc++ formatter (0x49B64 -> 0x82528 -> bl 0x813B0), which is unread. M3-041 stays RECOVERABLE_GAP until L30 has rows ..."

### Answer

libc++_shared.so ships its own complete printf. 0x00082528 is a vsnprintf (EOVERFLOW guard, one-byte dummy buffer, bounded-copy sink, NUL at min(result, n-1)) and 0x000813B0 is a full printf core with its own double-to-decimal conversion (base-1e9 big-array arithmetic, round-half-even, e/f/g/a), integer conversion (d u o x X, flags, width, precision), no locale lookup (the decimal point is the literal "." at 0x000824E0, no grouping) and inf/nan text. It reaches the phone only for leaf predicates and helpers: __signbit, __isfinite, strlen, memchr, strerror (only for the %m conversion), __errno, memcpy/memset, __stack_chk_fail and pthread TLS for the thread-locale switch, plus compiler-rt integer division that is local code (0x8675C, 0x86804, 0x86964). It does not call the phone vsnprintf or snprintf. The instruction pattern and strings resemble the musl vsnprintf/printf_core/fmt_fp; that is an identification note only, every rule below cites the shipped instructions.
