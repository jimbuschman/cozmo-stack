## Method and caveats

- Everything is ARM-mode code in `resources/lib/armeabi-v7a/libcozmoEngine.so`, disassembled with capstone from the `.so` bytes. I used none of the tracked disassembly.
- Callers come from a scan of every `b`/`bl` in `0x95E000..0xAE3000` plus a scan of data words for function addresses (vtable entries).
- Vtable words are `R_ARM_RELATIVE` in-place values. I checked the relocation entries for each slot cited.
- Literals are read as raw words. Float constants are given as bit patterns.
- PLT names were resolved from the relocations:
  - `0x4D3064` is `pthread_mutex_lock` and `0x4D3070` is `pthread_mutex_unlock`.
  - `0x4D3658` is `clock`, `0x4D6778` is `powf`, `0x4D6754` is `pthread_cond_broadcast`.
  - `0x4A6694` is `__aeabi_uidivmod`, `0x4BE310` is `__aeabi_uidiv`.
  - `0x4D37F0` is `memcpy`, `0x4D667C` is `memmove`, `0x4D36DC` is `memset`.
- Four things were run under Unicorn, with only the allocator, mutex and uidivmod stubbed:
  - `0xA1EC54` on a fast, a hit, an items and a miss case.
  - The static plugin constructors.
  - The registry builder `0x9CBECC`.
  - `0x9CC2AC` and `0x9CC4D8` for plugin key `0x006C0003`.
- The Thumb-mode `.init_array` entries (odd addresses) were not executed.
- "PBI" is the 0x1FC-byte object from `0xA02EC8`. "ctx" is `pbi+0xC`. "voice" is the 0x540-byte object.
- Where a row says NEW, no existing record or correction row covers it.

## Headline findings

1. **`0xA1EC54` is the writer of `pbi+0x1DC` and `pbi+0x1E0`.**
   - It writes through its output pointers: `*r1 = media data pointer` and `*r2 = media size`.
   - Its only PBI call site is the tail of `0xA0285C` (`0xA02934`). The constructor values are 0.
   - It has no return value use. It never fails: a lookup miss gives `(0, 0)`.
2. **C24.2's FX claim is contradicted.** The registry `0x108D9DC` holds 23 plugin records, not two.
   - They include key `0x006C0003` (the Compressor).
   - `0x9CC2AC` and `0x9CC4D8` accept it, so the voice init builds an in-place FX wrapper for it.
   - The return-value claim ("only 1 or 2") is confirmed.
3. **The writer of `u16[0x1052440]` was found: `0xA1C7D4`.** It was missed before because it addresses by PC-relative `0x105243C+4`, not through GOT `0x1040058`.
4. **`pbi+0x1F8` is the stop-at-frame offset** (-1 means none). The read-and-clear getter is `0x9CBACC`. This settles the "meaning UNKNOWN" in C21 B6.
