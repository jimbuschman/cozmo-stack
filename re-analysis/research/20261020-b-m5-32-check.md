## Blocking findings

### F1 — LAYERS can pass despite an explicitly unjoined frame

`cozmo-stack/src/Cozmo.Conformance/M5HwAnalysis.cs:236` (`LayerActivity`) correctly
omits an unjoined frame from Activity and returns a non-null Problem. However,
`FiniteLayers` at line 496 establishes completeness solely by comparing the surviving
Activity rows with the captured audio messages. It does not require `activityProblem`
to be null. At lines 503–511 it can return `OBSERVED_CONDITIONAL_LAYER_FRAMES` and
clear `missing`, despite that explicit problem.

Reproduced by executing the changed assembly with a small independent console probe:

- One captured stream has audio silence, Start(1), backpack, face, End in that order,
  at 10/11/12/13/14 ms, with distinct frame lines and ordinal zero. Successful gate
  observations at each capture minus 0.1 ms match their actual tags and lengths.
- A layer-frame observation at 9 ms names audio sequence 1, face sequence 4 and a
  true face flag. A second layer-frame observation at 15 ms names audio sequence 99,
  which has no successful gate or captured message. The check window is 0–20 ms.
- `JoinSends` succeeds for the captured sends. `LayerActivity` returns one Activity
  row and **"1 StreamLayers frame(s) could not be joined to the wire."**
- `FiniteLayers(..., drained: true, activity, problem)` nevertheless returns
  **OBSERVED_CONDITIONAL_LAYER_FRAMES**, `faceActivityEstablished=true`, `missing=null`.

The fixture tests analysis of incomplete capture evidence, not a claim about a real
robot trace or a source-supported second frame after End. The grader must reject
this evidence under the job's unconditional unjoined-frame rule.

**Required correction:** propagate a non-null activity problem into the conclusive
verdict gate and retain its explanation. Complete coverage must include the observed
frames, not merely the subset that reached the captured wire. Add a regression with
an otherwise passing stream plus an unjoined frame; it must be INCONCLUSIVE.
Also retain the existing missing/ambiguous-send-join regressions.

### F2 — AUDIO mistakes a partial epoch for incorrect engine accounting

`M5Hw.cs:392` passes `Admissions(hooks, playStart, playEnd)` and all refreshes.
`M5HwAnalysis.cs:270` removes earlier gate rows, but `BudgetSamples` at lines 310–329
starts spending at zero for each refresh epoch. If an epoch begins before the window,
earlier successful sends have already reduced its allowances. The first in-window
gate therefore falsely contradicts the original refresh. `Audio` then promotes this
to `OBSERVED_ADMISSION_ACCOUNTING_MISMATCH`, ahead of the missing-evidence fallback.

Executed reproduction, with source-derived constants:

| Time | Observation |
| --- | --- |
| 0 ms | Epoch 1 refresh: played/streamed byte and frame counters all zero; allowances 8192 bytes / 14 frames |
| 1 ms | Successful buffered silence, size 1, gate allowances 8192 / 14 |
| 3 ms | Successful buffered silence, size 1, gate allowances 8191 / 13 |

Passing both sends to `BudgetSamples` yields
**OBSERVED_COHERENT_SAMPLES_WITHIN_GATE**. Passing `Admissions(hooks, 2, 4)` with
the same refresh yields **OBSERVED_ADMISSION_ACCOUNTING_MISMATCH**, with one
accounting mismatch. These observations satisfy native C9/C14 exactly. The harness's
play-start timestamp is taken outside the scheduler lock; it does not guarantee an
epoch boundary. Nor does a complete wire join repair the missing spending history.

**Required correction:** reconstruct spending from the refresh through the window
using the available earlier gate rows, while limiting the claim to the requested
window. If that prefix is unavailable, mark the epoch unverified and return
INCONCLUSIVE; do not infer zero earlier spending or label it an engine mismatch.
Regressions should cover a mid-epoch window, an unavailable prefix, and an actual
incorrect remainder. The one-second send-join margin is not an accounting reset.

Both findings are test/harness bugs. Neither establishes a source-recovery gap or
an animation-engine defect.

## Locks, callback safety and test oracles

On the reviewed scheduler path, registration and emission are serialized by the
existing scheduler lock. Buffer observations are raised after releasing the buffer
lock. The direct-End snapshot acquires only that existing leaf lock, releases it
before send/notification, and adds no reverse acquisition. The real subscriber is
`ConcurrentQueue.Enqueue`; it does not call back into robot/scheduler or perform
analysis. Offline snapshots do not hold a queue lock while acquiring the scheduler
lock. No introduced lock cycle or data race found on this path.

The event documents synchronous notification and the no-callback/enqueue-only
contract. `RaiseDiagnostic` catches handler exceptions and also isolates a throwing
logger. A throwing multicast handler skips later subscribers for that observation;
that is documented diagnostic loss, not an engine-state mutation. This review does
not certify arbitrary subscribers violating the documented contract or concurrent
external manipulation of the public StreamSendBuffer.

The changed tests use independent native constants/rules for timer decrement,
fallback bounds, allowance arithmetic and conditional face emission. Comparing
observed gate/flag data with actual sink messages is a consistency check, not an
independent proof of the entire generator. The subscribed/unsubscribed byte
comparison is a legitimate differential test required by the job; it does not
upgrade either run to a source-fidelity oracle. The fixtures' simulated played
counters and synthetic transport timestamps are explicitly disclosed substitutes.
DRIVING expectations are fixed phase/result fixtures and immutable first-run replay.
No circular source-fidelity assertion found; F1/F2 are missing adversarial coverage.
