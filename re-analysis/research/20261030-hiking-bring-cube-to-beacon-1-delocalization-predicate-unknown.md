## Current C# data and exact missing interface

`AIWhiteboard.PossibleObjectStorage` already holds the same shared list used by handlers and ProcessClearQuad; `PossibleObject` contains a Pose3d and ObjectType. `PossibleObjectStorage.Add` copies the Pose3d wrapper and retains its pose-tree ownership (AIWhiteboardClear.cs:54–59), and Erase(first,end) disposes the owned value in source list order. This is sufficient **when entries carry their real native pose graph**: the required input is the graph's actual root ID, not a separate cached OriginId or a flattened root guessed from coordinates. A flat root with its real native ID is legitimate; a flat pose given a host default root is not enough evidence.

`BlockWorld.CurrentOriginId` and the production native origin owner are available after FinishDelocalization. `BlockWorld.AnyRemainingLocalizableObjects(uint)` exists at BlockWorld.cs:1082 and already uses the checked filter/predicate. `NativeDelocalizationWorld.FinishDelocalization` uses the same semantic keep condition `id==currentOrigin || AnyRemainingLocalizableObjects(id)` for world buckets. That is an implementation navigation lead, not primary evidence replacing D5.

**MISSING is the bound deletion interface/caller, not an unknown predicate.** Needed inputs are actual possible-pose root ID, actual current-world-origin ID, actual BlockWorld localizability query *at the AIComponent phase*. If a stored possible pose lacks an owned native graph, report that entry unavailable; do not claim it zombie and erase it. No additional pose/world-wide recovery is needed to state this boundary.

The current private `UpdatePossibleObjectRender()` in AIWhiteboardClear.cs can serve the source render body, but its `ClearQuadWorldOrigin` provider must be the actual current Robot.GetWorldOrigin. Its source-matching renderer is called once unconditionally after zombie iteration in D3. **ProcessClearQuad's size-changed-only rendering condition must not be copied here**: it is a different caller. Existing public PossibleObjectsRedrawn event is not a native external state event; source Viz sends are no-ops. No new synthetic API event is implied.

The current `AIWhiteboard.OnRobotDelocalized` also clears failure tables. This is contradicted by the concrete D3 body. Manager has explicitly approved replacing prior tests that used delocalization as an artificial failure-reset fixture with fresh state or an explicit test reset; those test setup changes do not justify preserving the unsupported production clear. Native failures survive this recipient.
