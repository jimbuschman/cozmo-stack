## 0. Answers in one place

1. **Insert order (0x9F3274):** binary search, **priority descending** (`vcmpe`, "new > mid" goes to the lower index). Equal priority is broken by `pbi+0x1C8` then `pbi+0x1C4`, both unsigned. The direction is chosen by the byte `[list+0xE]` (= limiter `+0x46`, the KillNewest bit): **0 = descending on (1C8, 1C4), non-zero = ascending**. Both keys are written only in the PBI constructor: `+0x1C4` = post-increment of the global u32 `0x108DC18` (initial 0); `+0x1C8` = post-increment of the global u32 `0x1052434` (initial 1) when `params+0x7C == 0`, else `params+0x7C` itself (which also sets `pbi+0x1BE` bit3). On the Play path both are creation sequence numbers. So a `KillNewest == 0` list holds the newest PBI first among equal priorities, and the victim (the LAST eligible PBI whose priority is <= the new one) is the oldest of the lowest priority. "Kill oldest" is now source, not a label.
2. **0xA01CA4(victim, reason):** no notification, no wire. It marks `pbi+0x1BD` (bit1 + reason in bits 2..4), then takes one of three routes. (a) Paused, or a stop/pause item already at `pbi+0x148`: `vt+0`(pbi,0,0) at once. (b) `pbi+0x1BA & 0x78 == 0`: `vt+0`(pbi,0,1). (c) Fade route: re-aim the running transition `pbi+0x144` to id `0x02000000`, end 0.0f, duration 0, curve 4; if there is no such transition (a Play with fade-in time 0, the normal case) write `pbi+0x168 = 0.0f`, `pbi+0x40 = 0.0f` and call `vt+0`(pbi,0,0). `vt+0` (0x9FF7B8) only marks the PBI stopped (1BC bit5 set, bit1 cleared, bit3 set, cancels the two transitions). The live voice is stopped and destroyed by the next voice pass (`0xA44A6C..0xA44B30`), not by 0xA01CA4.
3. **Per-object variant (0x9FA6F8, 0x9FA410, 0x9FA9FC..):** read in full (section 5).
4. **0xA376C0 / 0xA37880:** read in full. On shipped data 0xA376C0 returns 1 with no effect (both thresholds are 1.0f) and 0xA37880 returns 1 with no effect unless `PBI count + 1 - virtual count > 256`.
5. **Removal:** PBI Term `vt+0x10` = 0xA029DC calls 0xA01684 first: virtual-count decrements, `0x9F3528` per list (decrements `[list+0x20]`), then node `vt+0x94` (0x9ED428, bus 0x9C5240), which decrements `+0x60`/`+0x62` and destroys an idle limiter (section 11).
6. **0x9F29E8 +0x50/+0x54, vt+0x11C, 0xA19ECC, RTPC 0x10:** section 3. No shipped node carries RTPC param 0x10, so none of the RTPC-0x10 paths run on shipped data.
