## Result

Two direct source differences are established, plus an ordering difference at the unlock recipient. The main finite arithmetic, traversal, mutation and body-codec operations match the cited instructions. The file cannot receive an unconditional source-fidelity pass: retained-owner, unknown-history, calendar and shared-recipient behavior still have the expressly bounded proof limits listed below. Static symbol/type inspection found no definite compile error; this is not a compile pass.

1. **DIFFERS — forced daily check with prior Play bracket zero refreshes current brackets unnecessarily (lines 139–142).** Native `696AD6: cbz r0,696AEA`, `696AEA: cmp r6,#1`, `696AEC: bne 696AE6` sends `previous==0 && force==true` directly to calendar `696AEE`. It does not call `GetNeedBracketByIndex` at `696ADE`. Managed code always calls `State.GetNeedBracket` after its early `!force && previous==0` check. This is not a pure read: native helper `69CB20` calls `UpdateCurNeedsBrackets`; native `69C12C..132` tests dirty and `69C1F4/1FE` writes bracket values and clears dirty. Managed `Needs.cs:435..442` likewise calls its updater; `408..424` updates cached brackets and clears `_bracketsDirty`. The extra refresh therefore changes downstream state in the dirty-cache case. Native *does* refresh for previous-nonzero even when forced.
2. **DIFFERS — the star Sparks scalar selection uses live current level instead of ProcessLevelRewards' passed level (lines 84–88).** Native saves the input index (`699416: mov r4,r1`, `69943E: str r4,[sp,#14]`), reloads it into `r7` at `699480`, and passes that same `r7` into all five getters (`699482/48E/49C/4AA/4B6`). Managed code uses `State.NativeUnlockLevel` instead of its `index` parameter. Ordinary current-level calls initially have equal values; the source distinction remains real for different supplied index/state values or a changed live level. No ordinary production call supplying unequal values, or reachable callback changing the level in this interval, was established here; this is a conditional helper-contract difference, not a proved normal-run failure. The earlier daily build ledger's description of these lookups as “current selected level” is insufficient: the actual instructions establish the captured argument.
3. **DIFFERS in order — Progression owner validation precedes the unlock-string parse (lines 80, 95).** Native `6994F2..4FA` parses the name and skips id zero BEFORE reading connected Robot/Progression at `6994FC..506`. Managed code checks Progression first. On a missing managed owner plus an id-zero descriptor, managed returns false and aborts traversal; native never needs that owner for that descriptor and can continue to subsequent rewards. An unknown owner is not a justified zero/default input. Whether this host-unavailable combination is supported must remain explicit; this is not evidence for changing native id-zero behavior. No broader “recipient caching bug” is asserted without a reachable mutation between the relevant reads.
