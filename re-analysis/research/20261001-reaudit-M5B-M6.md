## M5-animation, part B

### `M5-019` — HOLDS

> **Current text:** “The layer base face is written back only by a streaming animation, not idle ones.”

`ApplyFaceLayersToAnim` `0x0064F154..0x0064F244` writes the animation face to the layer base at `0x0064F1EE`, before layer combination, only with `storeFace=1` and a successful face pull; the idle path uses false. `AnimationScheduler` and `TrackLayers` are the live streamer/layer manager, with no second production writer. Both tests use fixed face inputs and assert native before-combine/order behavior rather than reading a C# flag.

### `M5-023` — HOLDS

> **Current text:** “Abort: AnimationAborted broadcast -> AbortAnimation 0x8D reliable; state cleared; buffer kept and flushed by the next no-animation Update unless InitStream drops it; no EndOfAnimation.”

The broadcast route `0x005276E8..0x0052C22E`, streamer abort `0x0057B3F2..0x0057B58A`, and following Update `0x0057D122..0x0057D1DE` confirm that exact order: choose/reset streaming keyframe or idles, clear state, send reliable tag `0x8D`, retain pending buffer, and never synthesize EndOfAnimation. HEAD's live robot event → scheduler path reproduces it. The four tests enter through the scheduler/robot route and use literal tag/order/no-End expectations from the rows; they do not inspect a helper result alone.

### `M5-024` — HOLDS

## M6-wwise-bank

### `M6-003` — HOLDS

> **Current text:** “IMA ADPCM exactly: header predictor is sample 0, 63 nibbles, diff ((2n+1)*step)>>3, interleaved int16, 64 frames per block.”

Decoder `0x00A7A194..0x00A7A3C4`, the 89-entry i16 step table at `0x00FFD650`, 16-entry i16 index table at `0x00FFD708`, and three call sites confirm predictor-first, nibble/sign/index update order, 16-bit saturation, channel half mapping and interleave stride. HEAD performs integer operations at the same widths and routes shipped format-tag-2 mono/stereo media through it. Tests use native table bytes, a shipped block and exact decoded samples; none generates expected PCM by calling `WwiseAdpcm`.

### `M6-019` — HOLDS

> **Current text:** “The STMG state-manager reader (0x9B0B14): the threshold, max voices, the two group tables and the 37-parameter table.”

Reader `0x009B0B14` consumes threshold f32, u16 max voices, state groups, switch groups with u8 flags/12-byte items, then 37 packed 21-byte parameter entries with f32 values/ramps and u8 built-in. `WwiseStmg.cs` preserves byte widths/order and rejects truncation rather than guessing. The shipped `Init.bnk` offsets/counts/defaults (including 1.0f=`0x3F800000`) reparse identically. Tests use hand-built fixed bytes plus the shipped chunk, not values returned from the reader as their oracle.
