> **Status (manager, 2026-10-04): UNVERIFIED.** Saved verbatim from the cozmo-extractor's scratch file. A verifier checks the rows before any inventory correction adopts them.


> Status: UNVERIFIED extractor report (cozmo-extractor, 2026-10-04). Read-only. All addresses are VAs in resources/lib/armeabi-v7a/libcozmoEngine.so, ARM mode (checked by disassembly with capstone). Floats are given as raw bits first, value second. "vmla/vmls/vnmls" = VFP non-fused: vmla Fd = Fd + rnd(Fn*Fm), vmls Fd = Fd - rnd(Fn*Fm), vnmls Fd = rnd(Fn*Fm) - Fd; every operation rounds to binary32.

Scratch tools (scratchpad only, x5\ subfolder): d5.py (disassembler), e5.py (Unicorn harness that runs the engine's own 0xA14E28 on a curve built in emulated memory), m5.py (my float32 port of the disassembly), fuzz_a.py / fuzz_b.py, vec.py -> vectors.txt (golden vectors from the engine), ship.py / census.py (shipped-curve comparison). **Verification of my reading.** m5.evaluate (a transcription of the disassembly, not of the C#) was compared with the engine code run under Unicorn on 50,928 cases (20,000 random curves: 1..5 points, interp codes {0..9,10,15,100}, scalings {0,1,2,3,4,5,7}, x random / on a point / NaN, hint 0/1, duplicate abscissae; 30,928 y edge cases: 0, -0, +-inf, NaN, +-1e30, denormals, +-37, +-740, +-1, +-0.99999994, and 30,000 random binary32 bit patterns in scalings 2/3/4). Result: 0 mismatches in value bits and in the idx output (NaN payloads not distinguished). The manager's example reproduces: scaling 3, (0,-60)->(100,0) linear, x=50 -> 0x0DA22560 = 9.993018535662365e-31.

## 0. Headline results

1. **0xA14E28 is a leaf with no calls at all** (no bl/blx in 0xA14E28..0xA15244; mnemonic census: vldr, vmul, vmla, vsub, vdiv, vcmpe, vcvt.u32.f32, vcvt.f32.s32, ubfx, branches). There is no powf/expf/logf/sinf PLT call: sine, cosine, log10 and 10^y are all inline polynomial/bit-trick approximations in binary32. Literal pool 0xA15248..0xA152C0 (the next function starts 0xA152C4).
2. **Signature:** float 0xA14E28(curve* r0, float x (bits in r1), u32 hint r2, u32* idxOut r3), softfp (result bits in r0). curve = {pts*, count, scaling} (12 bytes: [r0] points, [r0+4] count, [r0+8] scaling). A point is 12 bytes {f32 x, f32 y, u32 interp}; the interp of the LEFT point of a segment selects the shape.
3. **All 12 call sites of 0xA14E28 (the two accumulator sites and ten others) pass hint 0** (L5-21), so the hint start index never matters on any shipped path; it is described for completeness.
4. **The C# double model differs from the engine in more than width** (section 4): boundary rule at an interior abscissa (C# evaluates the previous segment at t=1; the engine returns that point's y exactly), interp codes >= 10 (C# linear + reduced; engine y = 0 / constants, L5-25), NaN x, scaling-2/3/4 numerics (the engine's log is a 2-term atanh series: up to 0.0155 dB bias for small |y| and up to 1.7 dB near |y| -> 1 on shipped curves; pow10 has up to 0.23 % error and gives 0.99904 for y = 0), the SCurve value at t -> 0+ (0.000697, not 0), the clamp constant (764.6162109375 vs 764.616).
5. **A curve with count 0 never reaches 0xA14E28 from a bank**: it makes the subscribe function 0xA117C8 return 0x1F and the RTPC reader aborts the HIRC object (L5-06). A one-point curve returns y0 for every x.
6. There are **ten other call sites** of 0xA14E28 besides the two accumulators (L5-20); they are in the RTPC set/apply path (0xA10C98..0xA11620), the helper 0xA0E81C and 0xA12244. Their bodies are NOT read (RECOVERABLE_GAP).
