## Blocking

1. **A deadlock** (BlockWorld.cs:1353-1355, B3: `lock (_gate)` around the whole of UpdateObservedMarkers).
   - **The vision thread** takes `_gate`, then `BlockConfigurationManager._updateGate`: Processor → ProcessFrame →
     UpdateObservedMarkers (VisionSystem.cs:982) → AddAndUpdateObjects → ObjectObserved (BlockWorld.cs:1573) →
     ManipulationSystem.cs:38 Configurations.Update() → `lock (_updateGate)` (BlockConfigurations.cs:129). The same
     happens through BlockConfigurationManagerUpdate (BlockWorld.cs:1406 → ManipulationSystem.cs:35) and PoseStateChanged
     (ManipulationSystem.cs:39).
   - **Behaviour and robot-message threads** take them in the opposite order: CubeGameBehaviors.cs:195/:660
     Configurations.Update(), or PoseStateChanged → `lock (_updateGate)` → BuildLocked → `_world.LocatedObjects` →
     `lock (_gate)` (BlockConfigurations.cs:135, BlockWorld.cs:1188).
   - **Before:** UpdateObservedMarkers held `_gate` only in short blocks, and the callbacks ran with no lock
     (BlockConfigurations.cs:74-78 assumes that).
   - **Lights.cs:1033-1035** takes `Lights._gate`, then `_gate`: a hazard if any callback reaches Lights.
   - **The fix:**
     - go back to the short `_gate` blocks, so the callbacks run with no BlockWorld lock held;
     - serialise the cliff path against the frame with a **separate** frame lock, taken only by the frame window and by
       AddMarkerless/the cliff add, ordered before `_gate`, and never taken inside a callback;
     - keep the snapshot iteration and the flag-window behaviour;
     - add a test that would deadlock under the old design (with a timeout), and update the comment.
2. **A test pins a departure** (M3M4X16BuilderTests.cs:272, `TiltedCubeCandidateIsMissingAndCliffDetectionContinues`).
   - It asserts that a cliff object is located. Natively, AddMarkerlessObject's intersection test (0x0062255E; `bne.w
     0x00622568` → 0x00622722) **skips AddLocatedObject** when a candidate intersects. With the cube centred on the cliff,
     the original adds no cliff.
   - Keep asserting the M13-025 MISSING, the Detected log and the CliffReport. Remove the "a cliff object is located"
     assertion, or keep it only with a comment that it is the visible M13-025 departure, not source behaviour.
