## Required concrete profile and existing C# interface

The new DriveToPlaceOnObject composition begins with native leaf B9true. If drive succeeds, Wait1 reaches actual dock weak pointer and sets B9false. If the inner drive fails, outer ignores its failure and skips Wait1, so B9 stays true. Therefore NativePlaceRelRunner must accept that actual leaf state and choose PR2/PR4 or PR5/PR6; it cannot permanently assume either profile.

Current `PreActionPoseInput` in `PreActionPose.cs:803` exposes the third positional argument as `FlagA` (native input+8). Current `NativePlaceRelRunner.Init` unconditionally calls `DockPreActionPoses.GetNative(...FlagA:true...)` and then reads `pre.Poses[pre.ClosestIndex].Marker`. That is the B9true profile only. Native B9false needs no GetNative call at all and still needs actual observed-marker selection. The existing `NativeObservedMarkers.Get(target,target.LastObservedTimestamp)` is the data interface already consumed by native Pickup. Its markers/graph transforms must be real: absent producer input is MISSING, not an invented marker, first static cube face or preaction fallback.

Do not blindly transplant all existing NativePickup marker-selection code: its MAIN frame agrees with native PR6, but its simplified best-squared-distance loop omits the source sqrt/re-square behavior in PR7. This report does not broaden into a Pickup rewrite; it identifies the exact shared selector contract needed by the newly enabled PlaceRel profile.

Other IDock setup/result/turn/handler/cleanup recipients are retained checked contracts. Source floor-carried drive bypass/own Check remains the prior native-action-interface table; this clarification concerns only PlaceRel B9/marker branch. Known preflight also run for Marker::GetCodeName before checking the concrete no-winner null fault. No native UNKNOWN remains for the requested profile distinction. No official record can settle from this thin interface answer alone.
