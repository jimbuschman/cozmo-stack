## SourceQuadTree.cs is not a second tree

It is the stack's first M11-045 tree. Before this commit, the stack's MemoryMap was a polygon list (`_regions`). The
problem is that each map now holds **two stores that disagree**:
- `_regions` still receives all production content (objects, edges, ClearOfCliff/Cliff), and answers every query
  (`HasCollisionRayWithTypes`, `HasContentType`, FaceBehaviors);
- `Tree` gets only cliffs. In production even those stop at an M11-048 MISSING (`OverlapForTest` is null).

## Blocking

- **B1. The play-area value is wrong** (MemoryMap.cs:96, BlockWorld.cs:1336). `robot.play_area_size` reads
  `Tree.Processor.ExploredArea`, which in production is always 0.00, and helper+0x38 is always 0. The native value
  covers every map insert (0x006816E8, 0x00681934), and nothing visible marks the stack's value as incomplete.
  - **The real fix:** all map content goes into the tree, and the queries come from it (M11-045, M11-046, M11-017).
    That is job B-M3M4-20.
  - **Until then:** a visible MISSING naming M11-045 instead of the invented value.
- **B2. A runtime delocalization keeps the old map** (FreeplayStack.cs:303, BlockWorld.cs:2844, SourceQuadTree.cs:253).
  AddNewOrigin isn't modelled (BlockWorld.cs:895), so `CreateLocalizedMemoryMap(CurrentOriginId)` keeps the old map,
  and the commit removed the old `Clear()`. Natively, Delocalize always gets a new origin ID: AddNewOrigin 0x00510A66;
  `next` starts at 1 and becomes max(next, id+1) (0x00847934, 0x00847A86, 0x00847B58..0x00847B6C). So a fresh map is
  made (`research/20261013-blockworld-flag-and-map-helper.md` Q2 rows 3, 7).
- **B3. A race, and the flag window** (BlockWorld.cs:2296, 2157..2161):
  - `_poseChanges` is enumerated outside `_gate`, while cliffs append from the robot-message thread (Sensors.cs:849)
    and vision runs on `Task.Run` (VisionSystem.cs:757);
  - a cliff can also land while +0x74 = 1, and log FirstPoseForObject. Natively, HandleCliffEvent runs on the same
    thread before UpdateAllRobots (0x004ED62E before 0x004ED648), so the flag is 0.
- **B4. The InTriangle arithmetic** (BlockConfigurations.cs:344-345). Native computes inv = 1/denom (vdiv 0x004E0406),
  then inv*num (vmul 0x004E0412, 0x004E0444). The stack divides directly.
- **B5. Rotations use matrix row sums** (BlockConfigurations.cs:658, BlockWorld.cs:1066-1067, 1110-1112). Native uses
  Rotation3d::operator* (0x0084ACA6): a double quaternion narrowed to float, then UnitQuaternion_<float>::operator*
  (0x00849C1C). The results aren't bit-identical. **This is being read as its own record**, and the stack-wide pose
  arithmetic follows from it.
- **B6. An exception escapes AddMarkerless** (BlockWorld.cs:1055-1056). When the robot isn't localized, the filter
  covers all families, and `Footprint.GetBoundingQuadXY` throws NotSupportedException for a cube that isn't yaw-only
  (BlockConfigurations.cs:400-402). This skips the Detected log and the CliffReport. Native always computes the quad
  (0x0062255E..0x00622568; M13-025).
