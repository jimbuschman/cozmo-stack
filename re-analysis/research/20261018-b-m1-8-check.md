## B1 — BLOCKING (M1-054 / M15-014 / M15-030): needs persistence on every production connection, wrong clock, zeroed write

- Before this commit the connection-time needs read (key 0x194000, queued by the mfgId handler, M3-033) had no consumer
  unless a host built a FreeplayStack. Now `EngineNeedsOwner.cs`:15 (AttachConnectionRead) and :17 (serial hook) consume
  it on every Create/ConnectAsync: FinishReadFromRobot → InitAfterReadFromRobotAttempt (`Needs.cs`:1460-1581) →
  StartWriteToRobot (`Needs.cs`:1598-1639), an NV erase+write of 0x194000.
- **Clock:** the engine passes one clock, `()=>Timer.SecondsF` (`EngineNeedsOwner.cs`:6), seconds since engine start.
  Native uses the BaseStationTimer f32 for Init/Update (0x004EC9DE, 0x004ED636) but `system_clock::now()` epoch time for
  persistence (resolver 0x00694D9C; StartWriteToRobot's +0x1C0 stamp, strd 0x006954F8, ldivmod 0x0069555C).
- **Consequence 1 (C# API / downstream state):** ApplyRobotCopyLocked (`Needs.cs`:1750-1755) stores the robot blob's
  TimeLastWritten (epoch seconds, written by the official app); ApplyDecayForTimeSinceLastDeviceWrite (:1776) computes
  elapsed ≈ −1.7e9 s, where native gets the real positive interval (0x00695304..0x00695330). Most likely case on the
  operator's robot (version-5 blob from the official app, no device file: case 5). The levels feed NeedsState reports.
- **Consequence 2 (robot flash):** StartWriteToRobot writes zeros for curNeedsUnlockLevel, stars, timeCreated, onboarding
  and forceNextSong (`Needs.cs`:1619-1622, no MISSING at the write site); native packs them from manager state
  (0x006955F2..0x0069560C: +0x10/+0x14, +0x54/+0x58, +0x60, +0x64/+0x68, +0x1D0). TimeLastWritten is engine seconds
  (`Needs.cs`:1552, :1613). Reached when the robot has no blob (case 1), has a version 1–4 blob (rewrite), or with
  `--state-dir` when the device copy is newer (case 8). The record would corrupt what the official app reads back.
- **Holds:** InitInternal's forced WriteToDevice (0x0069347E) is a phone-file write (writeAsJson 0x00693EE6), not robot
  NV; nothing reaches the robot at Init. The robot write is gated on `_robotConnected` (native robot+4,
  0x006954A6/0x006954AA); the read goes out after the NV traffic gate.
- **Closes by:** building the system_clock producer and the economy-field packing (M15-030, M15-014/017), or keeping
  connection-time persistence (read consumer, resolver, robot write) off the production path behind a visible MISSING
  until then. Init-time ownership and the tick can stay. No regression asserts the blob written after a failed read or
  the decay after a successful one.
