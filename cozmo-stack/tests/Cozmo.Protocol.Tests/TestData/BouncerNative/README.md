# Native Bouncer pixel reference

Run from the manager worktree root:

`C:\Users\JimBu\AppData\Local\Programs\Python\Python313\python.exe .scratch/bouncer-native-reference/reference.py`

Unicorn 2.1.4 wheel was downloaded to this directory with `python -m pip download --only-binary=:all: --no-deps --dest .scratch/bouncer-native-reference unicorn` and extracted locally into `deps` with Python zipfile. No global package changed. Wheel and all loaded library SHA256 values appear in manifest.json. `emu_elf.Machine` maps each shipped ELF PT_LOAD segment at the loader's fixed bases, applies native relocations, and aborts unknown imports; its documented libc stand-ins and allocator remain part of this test harness. Raster operations use native imgproc Mat rectangle, circle, and putText entry points with gray 128x64 image, white scalar, filled/LINE8 parameters, font 0x32 and scale 0.5. The engine's actual VCVTR instruction at 0x0086E610 is run separately with default FPSCR for half ties. No host OpenCV or C# output is used.

Each `.gray` is 8192 raw row-major bytes, black 0 and white 255. Manifest records each integer input, exact SHA256, white-pixel count, and nonbinary count; outputs include 10 individual digits, multidigit clipping, three circles, three rectangles and three composed frames in engine draw order. These are actual native raster executions given adapter-output integer coordinates; the cases do not execute Bouncer's own float geometry or its complete face-action/stream lifecycle. Rectangle and circle border cases outside normal clamped Bouncer coordinates intentionally exercise the bounded native primitive. The VCVTR half-tie checks are native instructions, not composed float-to-image tests.
